第八季学习记录：专题支线 · 动态 / 语义 / 多机 / 事件（0152–0178）

对应课程：第 0152 – 0178 节（语料库阶段 H，42 篇论文；本季 27 节课，97 张具象自绘图、95 张原文图） 记录日期：2026-09-21

一、这一季和前七季的性质不同

前七季是一条纵向的线：先建立坐标系，再打地基，然后视觉主干、激光主干、多传感器融合、 神经隐式、学习式方法——每一季都接在上一季后面。

这一季是横向的。它不接在第七季后面，而是横切所有前七季，去拆三个从没人明说、 但一直默认成立的假设：

前七季的隐含假设 本季哪一块拆它 拆完之后冒出来的新问题
环境是静止的 动态环境（0153–0158） 怎么判断哪些点在动？判错怎么办？代价是多少？
地图只是几何，不知道那是什么 语义建图（0159–0167） 标签从哪来？同一物体跨帧怎么认成同一个？
只有一台机器人、一个主体 多机协同（0168–0174） 谁是中心？怎么防止一个假回环把两台地图一起毁掉？
相机是快门式的，总有完整图像 事件相机（0175–0178） 没有绝对亮度、没有完整图像，传统光度误差和描述子全不能用了，那用什么？

拆完之后冒出来的全是新问题，不是旧问题的重复——这是本季最值得记的一句话。

二、四条支线各自的收获

2.1 动态环境：代价账是本块的主线

八篇论文可以按「拿动态怎么办」分成四种哲学：

哲学 代表 关键数字 / 判据
删（几何 + 语义双通道） DynaSLAM 0153 深度一致性阈值 τ_z = 0.4 m；语义 Mask R-CNN 195 ms/帧
删（纯几何，无语义） 点相关性、CRF 0154 不需要 GPU；代价是要等一段时间才能下结论
留 + 追踪（当路标） DynaSLAM II、Dynam-SLAM 0155 停驶车场景反而更准，但要把物体位姿一起优化
软降权（不删点） WF-SLAM、室外动态 0156 用场景流确认「此刻动没动」，避免误删停驶车

本块最重要的一笔账：高精度的「几何＋语义＋修补」三件套加起来约 737 ms/帧， 离 33 ms 的实时线差了二十多倍；想实时只能退到只用几何的 1.69 ms 档。 更要紧的是——即使画面里没有人，语义那 195 ms 也照样要付， 所以作者实测发现 DynaSLAM 在静态序列上反而略逊于原版 ORB-SLAM2。 动态处理不是白拿的鲁棒性，它在安静场景里是净亏。

还有一个判据层面的收获：「可动类」不等于「此刻真在动」。 语义只能告诉你「这是车」，只有几何（场景流）才能告诉你「它现在动没动」。 一刀切把可动类全剔除，代价就是把路边停驶车辆那些本来能用来定位的特征点全丢了。

2.2 语义建图：地图表示决定能力上限

这一块的主线可以做成一档表示能力的阶梯：

表示 代表（课号） 多出来的能力 拿不到的东西
surfel 面元 SemanticFusion 0159、Co-Fusion/MaskFusion 0160 稠密几何 + 语义 没有自由空间，做不了导航级可达性
体素 / TSDF MID-Fusion、EM-Fusion 0161、PanopticFusion 0162 空的地方也是信息 → 自由空间、可抽网格 内存与算力更贵，普遍 2–5 Hz
场景图 DSG Kimera 0163 分层抽象（楼→层→房间→物体→网格），可行动 实现最重，依赖完整系统

另外三条贯穿线索： - 语义粒度的三档：逐像素语义 → 实例分割 → 全景（stuff + things 都要）； - 数据关联判据决定实例稳定性：IoU 类在遮挡/消失时会丢实例，统计检验类更稳； - 「建物体模型」比「只滤动态点」贵得多：0165 YOLO-SLAM 只删人点就能无 GPU 跑， 而 0161 做对象级重建必须 GPU + 降频。

2.3 多机协同：这块最抽象，也最需要图

这一块是前七季那条「回环假阳性铁律」最残酷的战场： 单机一次假回环毁一张地图；多机一次假回环会把两台机器人的地图一起缝歪。

两代解法（0171 做了并排对照）：

家族 做法 优点 代价 使用者
一致集最大化 / PCM 找互相不矛盾的最大一堆，只把那一堆放进优化 绝不会被假回环拉歪；实现简单 大图要枚举、算得慢；漏真回环（recall 低） DOOR / DiSCo / DCL / D²SLAM 远场
渐进非凸 / GNC 不丢任何一条，逐步「降温」，残差大的边权重趋零 保 recall；在线可跑 要自己调降温节奏，参数不直观 LAMP 2.0 / Swarm-SLAM / Kimera-Multi

架构主线是三级递进：中心化（简单可靠但有单点与带宽瓶颈）→ 分布式（各机本地优化再汇合） → 完全去中心化（对等、无主、容断）。

通信上有一条很实用的规律：传什么决定了能省多少——原始图 > 点云 > 描述子 > 关键帧 > 拓扑/里程计。 第七季 0135 讲的那个免训练几何描述子 Scan Context，在这一块被直接当成机器人之间的通用语言 （0170 DiSCo-SLAM）；后续还演进到 LiDAR-Iris 与 DELIGHT。

2.4 事件相机：先补物理机理，再谈算法

这一块的物理机理本身就反直觉，所以 0175 专门做了一节概念铺垫：

  • 它输出的不是图像，而是一串稀疏的 (x, y, t, 极性) 四元组；
  • 每个像素独立、异步工作，只在亮度变化超过阈值时才发一个事件；
  • 没有绝对亮度——它只知道「变了」，不知道「多亮」；
  • 静止时什么都不输出——这既是优点（省数据）也是致命弱点（没有信息可用于初始化）。

也正因为没有绝对亮度，传统的光度误差完全不能用了（回链第三季 0048 DSO 用的就是绝对亮度）， 于是这一块演化出两条优化目标：重投影/边缘对齐派（EVO、ESVO、DEVO、PL-EVIO） 与对比度最大化派（CMax-SLAM）。

融合范式的主线是：单事件 → 事件+帧 → 事件+IMU → 事件双目， 其中双目/深度主要解决尺度，IMU/标准帧主要解决静止退化与初始化。

四、本季的诚实标注（原文与清单的可疑处）

  1. 2019_Kimera-Semantics.md 文件名与内容不符：正文其实是 Kimera 主论文 （IJRR 2021，约 27k 词，含 DSG 五层结构与全家族模块），不是独立发表的 Kimera-Semantics 模块论文；「2019」这个年份也与正文的 2021 不符。0163 开课即声明。
  2. Kimera 主论文并未提及 Kimera-Multi：因此不作「前者是后者前身」的断言， 只作「同属 MIT-SPARK 团队与同一表示体系」这一较弱表述，并标注为推断。
  3. 一处误报经核实后推翻：预精读环节曾报告两篇论文撞名（DiSCo-SLAM 与 D²SLAM）， 逐字核对原文后确认是误报——两篇是不同论文（一个激光分布式、一个空中集群视觉惯性）。 课上反而把它当教学点：同名论文要靠作者与传感器区分。agent 的自我汇报不能直接采信。
  4. 2018_EventTracking.md 偏跟踪而非完整 SLAM，且依赖已有深度图； 2024_CMax-SLAM 只做旋转运动（rotation-only BA），不是完整 6-DOF SLAM。 两处都在课里显式说明限定。
  5. 2022_MR-TopoMap 是探索与拓扑框架，不是完整的协同 SLAM 后端，课上如实说明边界。
