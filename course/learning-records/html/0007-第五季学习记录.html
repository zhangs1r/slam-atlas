第五季学习记录：多传感器融合（0095–0103）

对应课程：第 0095 – 0103 节（语料库阶段 E，多传感器融合，共 9 篇） 一句话概括这一季：前四季把三个传感器各自拆开看过一遍，这一季把它们装回同一台机器里。

一、这一季读完了什么

课次 系统 它的一句话
0095 导览 三个传感器的盲区几乎不重叠——这才叫互补
0096 R³LIVE（2022） 两条流水线并行：激光管几何、相机管颜色，末端合流成着色点云
0097 R³LIVE++（2024） 从"贴颜色"到"估辐射"：同一面墙在不同曝光下该是同一个颜色
0098 LIV-GaussMap（2024） 地图不再是一堆点，而是一组能直接被光穿过的椭球——建图与渲染合流
0099 FAST-LIVO（2022） 视觉不提特征、不三角化，直接把激光地图当成自己的地图用
0100 FAST-LIVO2（2025） 同一份体素地图 + 同一个滤波器 + 序贯更新（本季顶点）
0101 TVL-SLAM（2022） 因子图后端、没有 IMU——用来证明"紧耦合 ≠ 必须用因子图"
0102 AdaFusion + FusionPortable 怎么用多模态"认地方"，怎么用带真值的数据集"量准不准"
0103 M-LOAM（2022） 多激光雷达的在线外参标定：一边跑一边把传感器关系估出来

二、几个"啊哈时刻"

1. 融合的价值不在"日常"，而在"退化"

以前我以为多传感器是"多加一层保险"。读完这一季才明白：在正常场景下，三种传感器是互相冗余的；只有在各自的退化场景里，互补才真正变成价值。

反过来看第四季 0076 课那个数字就很清楚了：一条 200 米的隧道里，纯激光的位移误差高达 56%。融合不是让好场景更好，而是让坏场景能用。

2. 「深度白送」这四个字，改变了直接法的性质

第三季 0046–0050 学直接法时，最让我头疼的是：每个像素的深度都得自己估（逆深度那一套）。DTAM 要估一张稠密的逆深度图，DSO 要维护活动点，SVO 用概率深度滤波一个像素一个像素地收敛。

而 FAST-LIVO 系做的事情是：激光已经把地图建好了，地图里每一格存的是一块平面——视觉上来直接问"我这个像素投过去落在哪块平面上"，深度就出来了。

这就等于把直接法最贵的那一步直接删掉了。也难怪 LIVO 能做得比纯视觉直接法快那么多。

3. 「序贯更新」——一帧里的测量可以一个一个来

这是我这一季最反直觉的一个收获。我一直以为"一帧数据"就该"一起处理"（攒够了再解一个最小二乘）。

FAST-LIVO2 的做法是：一帧里有若干个平面测量、若干个图像块测量，它们一个一个地去更新同一个状态，而且每更新一次就重新线性化一次。

好处是想得通的：状态每被一个测量修正一点，下一个测量的线性化点就更准一点——像一个人一边听一边修正自己的判断，而不是把所有人的话听完再一次性表态。

4. 「地图里存什么」这条暗线，走完了两个极端

从第二季一路追到现在，这条线的每一站我都在学习记录里记过：

  • 第二季 0033：存一个标量（TSDF 的截断距离）
  • 第二季 0034：存体素块（只给表面附近分配内存）
  • 第四季 0084：存点，但用能增量插入删除的树管起来
  • 本季 0100：存一块平面（中心 + 法向 + 统计量）
  • 本季 0098：存一组椭球高斯

规律很清晰：存储单元一路变厚，因为下游要用它的人变多了。 一开始只有"找最近点"要用，存点就够；后来视觉要用它当几何约束，就得存平面；再后来渲染器也要用，干脆存成能直接画出来的东西。

三、三条主线的收束

主线一：融合的两种哲学

两条流水线并行 统一状态、统一地图
代表 R³LIVE / R³LIVE++ FAST-LIVO / FAST-LIVO2
几何谁管 激光惯性那一路 同一份体素地图
纹理谁管 视觉惯性那一路 同一个滤波器、同一份地图
视觉深度从哪来 自己那一套 VIO 估 直接复用激光地图
产物 着色点云 / 辐射场 统一地图 + 位姿

两种都是紧耦合——判断标准不是"用了什么算法"，而是"两种数据有没有进同一个待优化的问题"。

主线二：建图与渲染的合流

第一季 0015（3D 高斯）→ 第二季 0036–0039（NeRF / Instant NGP / Plenoxels）→ 第三季 0071（神经隐式 SLAM）→ 本季 0097 / 0098。

以前是"先建好地图，再想办法把它画出来"；这一季变成地图本身就是画得出来的东西。而且多了激光这一路，几何是白送的——不用像 3DGS 那样从稀疏点云和光度梯度里慢慢猜。

主线三：看不见的地基

最后两课（0102 / 0103）提醒了我一件很实在的事：融合系统在真实场景里跑不起来，往往不是算法不够聪明，而是地基没打好。

  • 时间：硬件触发同步 → 在线估计残余时偏（第三季 0057 的 td）→ 外参标定
  • 外参：出厂标定会被震动与温度带偏，所以干脆把它当待估变量（0103）
  • 退化：融合真正发光的地方

四、精读 agent 纠正了我的四处错误假设

这一季的四个精读 agent 又一次证明了"不许凭印象"的价值。我在简报里写的假设，有四处与正文不符，全部被指了出来：

我的假设 正文实际是
R³LIVE++ 引入了视角相关的反射 不是——它的辐射量是每通道单值常量（朗伯、与视角无关）；视角相关是 LIV-GaussMap 用球谐才做的
FAST-LIVO（v1）用序贯更新 不是——v1 是异步更新，"序贯"是 FAST-LIVO2 的贡献
v1 就已经是"同一份地图、一个滤波器" 不是——v1 是"两份地图、一个滤波器"；统一成一份是 v2 的事
第三篇（TVL-SLAM）属于 LIVO 家族 不是——它不含 IMU、视觉走特征法、也不是实时；它的角色是"因子图紧耦合路线"的对照样本

这四处如果没被纠正，就会原样写进课程里。 所以我在写作简报里都会附一句"如果我的描述与正文不符，请以正文为准并明确指出来"——这句几乎每次都有收获。

另外还有两处路线图显示名不精确： - AdaFusion 的用途是地点识别（not 里程计融合）——路线图只写了"注意力式融合网络"，没说清用途 - 所谓"多传感器鲁棒里程计"其实是多台同一种传感器（多激光雷达）+ 在线外参标定，不是异源融合

五、留给阶段 F（前沿：神经隐式与 3D 高斯）的疑问

  1. 3DGS 的"自适应密度控制"到底怎么做？ 这个问题从第一季 0015 课就挂着（当时那篇综述只引用未展开），第三季 0072 提到过，本季 0098 的 LIV-GaussMap 也没展开——它用的是另一套初始化与优化方式。
  2. 地图里存高斯，到底能不能用于定位？ 本季 0098 的高斯地图只服务于渲染，位姿还是独立 LIO 给的（比较松的耦合）。那"高斯本身参与定位"是什么样子？
  3. 神经隐式 SLAM 的实时性天花板在哪？ 第三季 0071 的 NICER-SLAM / DN-SLAM 还受限于速度与场景规模；本季 FAST-LIVO2 已经把"存平面"做到实时了，那"存隐式场"能不能也做到？
  4. "提取 vs 不提取特征"的第三回合。 视觉侧（第三季 0046–0050）与激光侧（第四季 0074/0084）都走完了；本季 FAST-LIVO 系列给出了一个有意思的答案——一个系统里两种策略可以共存（视觉走直接法、激光走地图配准）。那学习式前端会把这条线引向哪里（阶段 G）？
  5. 多传感器 + 高斯的组合：本季已经有了"融合结果可渲染"（0098），那"可渲染 + 可回环 + 大尺度"什么时候能凑齐？
