第十一季学习记录：应用与相邻领域 · 看位置（0199–0205）

对应课程：第 0199 – 0205 节（语料库阶段 K，5 篇论文；本季 7 节课，30 张具象自绘图、28 张原文图） 记录日期：2026-09-21 ★ 这是整个项目的最后一季。A–K 十一个阶段至此全部开课。

一、这一季跟前十季有什么根本不同

前六季（A–G）是一条纵向的路，把 SLAM 这条技术线越挖越深。 第八季起，项目连着开了四个横切面，但它们切的角度各不相同：

季型 代表 导览课要讲什么
续接季 A–G 预告「一个技术演进」的下一站
横切 · 支线季 H（专题支线） 讲清「横切在哪、拆掉了什么默认假设」
横切 · 工具季 I（数据集与评测） 先立一套分析框架
横切 · 补名词季 J（基础零件） 先承认「这些词你早就在论文里见过、但没人解释过」
横切 · 看位置季 K（本季） 先画出「一个完整机器人系统」的框图，再说明 SLAM 只占其中一环

这一季不读新方法。 它回答的是一个前十季从没正面答过的问题：

SLAM 站在系统的哪一环？它的上游从哪拿数据、下游把结果交给谁？

导览课立下的分析框架是一条七环系统链：

传感器 → 感知/前端 → SLAM/里程计 → 地图 → 规划 → 控制 → 执行器

前十季一直在讲链上的第 ②③④ 环（感知 / SLAM / 地图）， 而规划、控制、执行器、以及「算力放哪」这些环，前十季几乎没碰过。

二、全季最有价值的一张表：五篇覆盖的环极不均匀

这不是巧合，它本身就是这一季要讲的内容：

篇目（课号） 覆盖哪些环 关键事实
Falcon 4 0200 横跨六环（感知→执行器） 全季唯一自洽闭环的整机系统，也是唯一落到执行器的一篇（Pixhawk 4 → 电机转速）
运动规划综述 0201 一环都不实现 它是导航栈的「解剖图」，是元层面的选型指南
RecSLAM 0202 只覆盖 SLAM 与地图两环的算力部署与融合方式 算法零改动（用 GMapping 当黑盒），把「多机 + SLAM」当待调度的算力负载
Wildcat 0203 就是 SLAM/里程计这一环本身 与第九季 0184 闭环
撤稿的区域特征融合 0204 感知这一环 警示课，不写撤稿理由

★ 一条横向的新轴：0202 引入的是「机器人–边缘–云」这条 计算基础设施轴，它与 A–J 季的「算法纵向轴」正交—— 这是前十季从未出现过的一环。它不解决多机 SLAM 的算法问题（地图一致性、回环、通信受限）， 而是把「多机 + SLAM」整体当成待调度的算力负载。

★ 一个正面冲突（很适合做成对照）：面对「机器人算力不够」，两条路方向相反—— - 0200 把算力往机上堆（换 i7-10710U、坚持全部 onboard、无地面站）； - 0202 把算力往机外送（原始帧卸载到边缘）。 - 而 0201 从统计上支持 0200 这一侧：学习/复杂算法不宜端到端上机，应保留经典组件。

三、两处「技术核心」

3.1 Falcon 4 的双参考系解耦（0200）

戏剧冲突：VIO 局部准但越走越偏，SLAM 长期准但一跳一跳不平滑。 直接二选一都有毛病。

解法：只把两者的漂移量注入回路（原文写的是注入 (T_DRIFT)^-1）—— 于是同时保住 VIO 的平滑与 SLAM 的长期无漂。 这是「两个都不完美的东西怎么组合」的一个漂亮范例。

另有两个很好的数字教具： - 三层地图的存储量级：语义层（树干圆柱 + 地面平面）约 2 MB 对 全局粗体素图 1250 MB——约 600 倍； - 为什么树冠下必须用 LiDAR：密林树冠下阳光透叶打出斑驳光斑、 光斑随时间移动、局部亮暗剧变，破坏了视觉的恒亮假设。

3.2 Wildcat 的连续时间表示（0203）

问题：一帧点云不是一个瞬间——激光雷达一边转一边走， 同一帧里先扫到的点和后扫到的点是在不同位置采的，于是直墙被扫成斜线。

解法：连续时间表示——用 B 样条把轨迹表示成一条能求值的曲线， 于是任意时刻都能插值出位姿，每个点各归各位。

一个重要的反面（能同时打穿两个误解）： Wildcat 自己的纯里程计在 MulRan 上比 LIO-SAM 更差（2.9% vs 2.4%）， 它赢在鲁棒性（对手跑不完隧道）与全局一致性（回环 + 重力约束）， 不是赢在单帧精度。

四、三处清单与正文不符（第 20–22 处）

4.1 ★★ 第 20 处：「仿真」是文件名截断造成的误读

清单标「边缘计算加速多机器人仿真」——错。 真实标题是 Edge Robotics: Edge-Computing-Accelerated Multirobot **Simultaneous Localization and Mapping**。

错的源头很小但很典型：文件名 2022_Edge_Robotics__Edge-Computing-Accelerated_Multirobot_Sim.md 里的 _Sim 是 Simultaneous 被 66 字符长度限制切掉之后剩下的残骸—— 正好切在第三个字母上。于是 Simultaneous 变成 Sim， Sim 又被顺理成章读成了 simulation。

而且它不只是仿真：有真机原型（3 台 TurtleBot3 + 1 个边缘节点，端侧 Jetson TX2）。

→ 处理方式：开课即纠正，并把「文件名截断是一种系统性失真，不是个别事故」讲成教学点。 （本季三篇应用论文的文件名都在第 66 个字符处被截断。）

4.2 ★★ 第 21 处：清单替论文说了一句它没说过的话

清单在 Wildcat 备注里写「用 SE(2) 相对位姿做稠密重建」。逐词实测：

清单的说法 正文实测
用 SE(2) SE(2) 在正文里出现 0 次；出现的是 SE(3) / SO(3) / so(3)
做稠密重建 正文没有「稠密重建」这个说法；产物是 surfel + submap

→ 处理纪律：这是清单的说法，不是论文写的。我们不为它补话—— 不去替论文解释「它其实也想用 SE(2)」，也不去替它圆「稠密重建大概是这个意思」。 论文说的是 SE(3)，我们就写 SE(3)。

并顺手讲清 SE(2) 与 SE(3) 的区别（平面 3 自由度 vs 空间 6 自由度）， 以及为什么这篇不需要 SE(2)：① 场景是三维的（QCAT 含三层楼梯与隧道）； ② 它的位姿图专门加了重力方向约束；③ 它的面元匹配代价是三维 point-to-plane 型。

还附了一个很合理的猜测：误会可能来自「平面」这个词—— 它用协方差矩阵的最小特征值判断一个面元「平不平」， 但那是面元自己的局部几何，不是位姿被表示成平面运动。

4.3 ★ 两处标题不全（同一截断的连带后果）

  • 自主飞行漏了 Under Dense Forest Canopy——树冠下才是它的题眼；
  • 运动规划漏了 using machine learning: a survey——它是一篇综述； 而且清单把它归成「系统类偏工程」也错；它还是本批公式最少的一篇（仅 1 个编号式）。

五、一次跨季对账（本季最值得记的一件事）

第九季 0184 写：「Wild-Places 的真值由 Wildcat SLAM 自举生成， 原文写明平均误差 0.3 m」。

本季 0203 第一次读 Wildcat 本身，去原文对账：

  • Wildcat 正文给的是 QCAT 绝对误差 FlatPack 均值 0.42 m / SpinningPack 均值 0.34 m （Table II，63 个测绘靶标）。
  • 0.3 m 就是 0.34 m 的四舍五入（取的是 SpinningPack 那一个）。
  • 更要紧的是它不是轨迹误差，是「地图上这 63 个测绘点准不准」—— QCAT 这种 5 km 级室内外场景根本拿不到轨迹真值 （原文：providing an accurate pose ground truth is not feasible）。
  • 另外原文还有一个 DARPA 的 3 cm，那是另一种口径 （稀疏体素地图对稠密真值的最近邻统计），作者自认「不能精确反映地图精度」。 → 3 cm 与 0.42 m 是两个不能放在一起比的数。

★ 做这次对账不是挑第九季的错，而是示范「数字离开口径就会失真」这件事本身。 并接回第九季的核心洞见：Wildcat 的误差是亚米级（0.34–0.42 m）， 而它要判的阈值是米级（3 m），误差比判据小一个量级—— Wild-Places 拿它当亚米级真值去评「检索落在 3 m 内」，完全成立。够用比准更重要。

★ 而且这条链是双向的：第九季站在数据集的角度转引了 0.3 m； 本季站在 SLAM 系统的角度查到了 0.42 / 0.34 m，并说清了它是什么误差。

六、撤稿警示课（0204）：本季最特殊的一节

6.1 事实部分（逐词实测）

  • 正文从头到尾没有撤稿声明：retract 全文命中 27 处，27 处全部落在图片路径里 （图片目录名继承自带 RETRACTED_ARTICLE 前缀的文件名，是假命中）； 排除图片路径后，正文文字命中 0 处。
  • Declarations 段反而完全合规：Funding「无资金支持」、 Conflict of interest「作者声明无相关利益冲突」、 Data availability「可向通讯作者索取」、Ethical approval「不涉及」。
  • 外部核实（Springer 官网）：标题前缀 RETRACTED ARTICLE； 期刊 Soft Computing（Springer），Vol 27, Issue 23, pp 18195–18213, 2023； DOI 10.1007/s00500-023-09278-3； 变更历史「09 March 2026 — This article has been retracted」； 撤稿通知在另一份文件：DOI 10.1007/s00500-026-11323-w。
  • ★ 它仍有 98 条 Scopus 引用。

6.2 课上的四段骨架（写成操作课，不是论文摘要）

  1. 起——零件全对：把它用到的第十季零件逐条列出来打勾 （RPN、ROI pooling、ResNet50、Faster-RCNN、KITTI、AP/mAP/IoU、相机-LiDAR 标定与投影）， 读者会本能觉得这篇很正规；
  2. 承——声明全合规：Declarations 四条逐字抄出来，全部合规；
  3. 转——回到论文内部查自洽性：同一个 mAP 在正文与表格里分别是 97.13% 与 85.67%； 摘要同时给 70 ms 与 15.8 FPS 而 1÷0.070 ≈ 14.3 FPS； 训练集明细相加是 4500 而正文写 4400； 对比表的引用归属与自家参考文献表系统性对不上； 式(11) 的 4×4 矩阵底行全零、式(10) 里旋转矩阵没进目标函数；
  4. 合——判据是「可核查性」：不是「看起来像不像论文」， 而是「数据/代码是否可得、评测协议是否自洽、数字能否复现」。

6.3 ★★★ 不许说的话（照单执行）

  • 不许写「因为数据造假所以被撤」；
  • 不许写「因为无法复现所以被撤」；
  • 不许写「因为作者有问题」「因为审稿人发现了什么」；
  • 不许出现「撤稿原因是……」这一句式；
  • 不许把「读起来不对劲的地方」说成「撤稿的证据」，只能说成 「读时应当起疑、应去核查的地方」。

需要一句话时就用：「正文未给出撤稿理由；本课不写理由。」

6.4 全季最重要的一句话

零件都对、声明都合规、格式都像样，仍不保证整篇可信。

而判据要建立在「可核查性」上—— 这也顺手解释了为什么它仍有 98 条引用： 撤稿不会自动撤回别人已经引用的行为。

七、本季的诚实标注

  • 撤稿理由不写（通知是出版方另发的文件，本语料库没有）。
  • 0202 的多处原文疑点如实标出：上传时延单位 ms 应为 s； 1.51 s 与 49.74% 口径不自洽；通道名 3G / 5G 前后不一致； 角速度写成 m/s²；「平均 58.71% / 上限 12.16%」混了两个指标； Algorithm 3 下标应为 j。
  • 0200 弃用了一个量级不可能的数字（原文「1.1 km 回环覆盖 200 m²」）， 改讲轨迹导数（急动度）那一段。
  • 0203 如实区分：Wildcat 自报的 QCAT 误差是「对齐之后的形状误差」， 不是「绝对位置误差」；DARPA 的 3 cm 是另一种口径，两者不能比。

九、全项目结业小结

十一季 · 十一个阶段 · 205 节课 · 255 篇语料库。

  • 主干七季（A–G） 是一条纵向的技术演进： 从全景纲领出发 → 打地基 → 视觉主干 → 激光主干 → 多传感器融合 → 神经隐式与 3D 高斯 → 学习式方法；
  • 四个横切面（H–K） 是四种不同的切法： H 支线拆假设、I 尺子教衡量、J 零件补名词、K 位置看全局。

从第一季的全景纲领出发，最后又回到全景。

你现在能做什么： 拿到一篇论文，能读正文而不是猜标题；看到一个指标，会先问它是在什么尺子上量的； 看到一个陌生名词，能判断该不该停下来读懂它；看到一个方法，能说出它在系统链上站在哪一环。

还欠什么： 建图质量的评测只被点过名；多机数据集的真值难题没解； 有少数几个零件的重要性来自行业共识而非本语料库证据； 而且这始终是 255 篇语料库上的课程，不是 SLAM 全集。
