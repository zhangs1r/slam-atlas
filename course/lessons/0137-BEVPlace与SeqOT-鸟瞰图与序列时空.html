本节目标

读完你应该能回答① 说清 BEV 图为什么「对平移天生鲁棒、对旋转只是图像旋转」；② 讲清群卷积如何把「旋转等变」变成「旋转不变描述子」；③ 说清 BEVPlace 只给 2-DOF 位置（x, y）、不给 yaw；④ 讲清 SeqOT 用「序列 + 数学证明的 yaw 不变」扛长期大场景。

和前面课程怎么接

本篇是 0011「检索被吃掉」 的延续，且和 0136 OverlapTransformer 同属「投影图路线」：OT 用 range image（只对 yaw 不变、不对横向），BEVPlace 用 BEV 图（对平移天生鲁棒、靠群卷积对旋转不变）——两者正好互补。也呼应 0135 Scan Context 的「旋转 / 横向」二分：BEVPlace 用「投影 + 结构」一次性接近两者，但仍不估 6-DOF。

1. 它到底在做什么：先讲人话

上一节（LCDNet / OverlapTransformer）已经证明：把点云投成一张「图」再喂网络，比直接啃无序点云更友好。本节两篇把这条「投影图」路线推向两个新方向：

  • BEVPlace：把点云从正上方拍成鸟瞰密度图（BEV）。道路场景里传感器只在地面运动，所以平移在 BEV 上几乎不改变外观、旋转只是整张图转一下——这天然适合做「平移鲁棒 + 旋转不变」。
  • SeqOT：单帧不够稳？那就用连续多帧（序列）range image，让 Transformer 把时空信息融成一个描述子，专攻长期、大视角变化。

两者都「内建不变性」——不变性不是搜出来的，是投影方式 + 网络结构送的。

2. BEVPlace：对平移天生鲁棒，还能顺便定位

BEVPlace 的做法：点云投到地面网格（0.4 m），每个像素强度 = 归一化点密度（沿用 BV-Match 的 Depth density）。关键点洞察：road scene 中传感器只做地面运动，点云平移在 BEV 上几乎不改变外观，旋转仅对应 BEV 图像旋转。于是——

群卷积（Group Conv）

基于 GIFT，去掉尺度特征（BEV 无尺度差）。群卷积是 SO(2) 旋转等变的：图转 θ，特征也转 θ。

NetVLAD 聚合

旋转等变特征经 NetVLAD（K=64）聚合 → 旋转不变全局描述子（类比 OT，但作用在 BEV 上）。检索用 L2 距离。

位置估计（独有）

发现特征距离与几何距离相关：$\|f(m_i)-f(m_j)\|≈\alpha(1-e^{-\|t_i-t_j\|^\gamma/\beta})$。由特征距离反解几何距离，≥3 参考做三边定位。

数字

KITTI Top-1 99.3%（旋转 98.0%）；地点识别约 30 ms + 位置估计 <1 ms（RTX3090），满足 10 Hz。

⚠️ 本季硬要求，务必分清：BEVPlace 只回归 2-DOF 位置（x, y），不输出 yaw。论文原话未来工作才计划「把旋转信息编码进全局描述子并估 6-DOF 位姿」。旋转不变指「描述子对旋转不敏感」（检索更稳），和「输出相对位姿」是两件事——后者是 0136 LCDNet / 0140 LCR-Net 才做的。

3. SeqOT：用序列扛长期、大视角

SeqOT 是 OverlapTransformer（OT）的序列版：单帧 OT 已经 yaw 不变且很快，但单帧信息有限，长期、大场景仍吃力。SeqOT 用连续 m=20 帧 range image 端到端融成一个序列级描述子。

输入

序列 range image，每帧 1×32×900，序列长 m=20。仍只用深度一通道。

SST（单帧）

OverlapNetLeg 压高度到 1、保宽度（保 yaw 等变）→ Transformer 增强，出单帧特征。

MSM（多帧）

每连续 3 帧特征沿宽度拼接，经 MST Transformer → NetVLAD+MLP 出 256 维子描述子。

GeM 时间聚合

所有子描述子沿时间维 GeM pooling → 256 维全局描述子（对子描述子顺序置换不变）。

SeqOT 最硬的贡献是用数学证明了 yaw 旋转不变性（式 3–12）：SST 对 yaw 等变 → MST 输出仍等变 → NetVLAD 对置换不变 → 子描述子 yaw 不变；GeM 对子描述子顺序不变 → 全局描述子不变。因为不变性是证明出来的，它只需匹配一次，而基线序列方法（非 yaw/顺序不变）要「正向+反向」匹配两次。数字：Haomo Seq1-3 AR@1 0.824、NCLT 2012 0.917；零样本泛化到 KITTI/MulRan（Velodyne-32→64/Ouster-64）；在线 98.32 ms（<100 ms）。它是纯检索（单阶段全局描述子）。

4. 两篇怎么分工：投影图 vs 序列

把本节两篇和前面摆在一起看，激光回环的「内建不变」路线其实分成两股：

方法 投影 / 输入 不变性来源 输出 范式
OverlapTransformer(0136)range image结构（只压竖维）描述子（仅 yaw 不变）纯检索
BEVPlace(本节)BEV 密度图群卷积+NetVLAD描述子 + 2-DOF 位置纯检索
SeqOT(本节)序列 range imageSST+MSM+GeM（证明）序列描述子纯检索
LCDNet(0136)点云（PV-RCNN）数据增强+UOT描述子 + 6-DOF 位姿检索+位姿

一句话：OT 路线（range image）只对 yaw 不变、不对横向；BEVPlace 用 BEV 补上平移鲁棒、还能定位；SeqOT 用序列补长期大场景。三者都是「投影图 / 序列 + 内建不变」，都不像 Scan Context 那样暴力搜对齐。

4.1 和前面课程怎么接（收束）

本篇是 0011「检索被吃掉」 在激光侧的进一步兑现：从 Scan Context 的免训练几何，到 LCDNet/OT 的单帧学习，再到本节 BEVPlace/SeqOT 的「投影图 + 群卷积 / 序列 Transformer」——学习式点云描述子已经在反向回环、横向、长期变化上全面超过手工法。但代价是需要 GPU、且大多不出 6-DOF 位姿。真正的「回环 + 重定位一体」要等 0140 LCR-Net。同时 BEVPlace 的「只 2-DOF」也提醒我们：描述子不变 ≠ 能输出位姿，这是评测这类方法时最容易混的点。

  1. 为什么 BEV 图「对平移天生鲁棒、对旋转只是图像旋转」？这带来什么好处？
    展开查看答案

    road scene 中传感器只做地面运动，点云在俯视图（BEV）上几乎只是平移一点，外观变化很小；旋转只是整张 BEV 图转一个角，内容不变。好处：① 平移鲁棒性由投影方式白送，不必像 range image 那样靠数据增强去扛横向畸变；② 旋转只是图像旋转，群卷积（SO(2) 等变）+ NetVLAD 就能拿到旋转不变描述子，比「暴力列移搜索」更稳。

  2. BEVPlace 的「旋转不变」和它「输出 2-DOF 位置」是一回事吗？为什么本季强调要分清？
    展开查看答案

    不是一回事。「旋转不变」是描述子对旋转不敏感（检索更稳），是描述子层面的性质；「输出 2-DOF 位置（x, y）」是它额外用「特征距离↔几何距离」映射做三边定位得到的，且明确不输出 yaw、不估 6-DOF。本季强调分清，是因为初学者容易把「描述子对旋转不敏感」误读成「网络给出了旋转位姿」——后者是 LCDNet / LCR-Net 才做的，BEVPlace 不做。

  3. SeqOT 为什么敢说「yaw 旋转不变是证明出来的」？它比单帧 OT 强在哪？
    展开查看答案

    它用式 3–12 链式证明：SST 对 yaw 等变 → MST 输出仍等变 → NetVLAD 对置换不变 → 子描述子 yaw 不变；GeM 对子描述子顺序不变 → 全局描述子不变。因为不变性有数学保证，它只需匹配一次，而基线序列法（非 yaw/顺序不变）要正向+反向两次。比单帧 OT 强在：用 m=20 帧的时空信息扛长期、大视角变化（Haomo/NCLT 明显更好），且零样本跨传感器泛化。

  4. BEVPlace 与 OverlapTransformer 同样用「投影图 + 内建旋转不变」，为何说它们互补？
    展开查看答案

    OT 用 range image，只对 yaw 不变、对横向平移会因投影畸变而失效；BEVPlace 用 BEV 图，对平移天生鲁棒、还能顺带给 2-DOF 位置。一个补「横向」，一个补「旋转」，投影方式不同导致各自的不变性范围不同——所以互补而非替代。BEVPlace 还多了「定位」这个 OT 没有的用法。

  5. 把 0135–0137 三节的点云回环方法，用「是否训练 / 是否出位姿 / 对什么不变」做个小结。
    展开查看答案

    Scan Context / ++（0135）：免训练几何描述子，只出相似度（++ 还能给 1-DOF 半度量），PC 管旋转、CC 管横向。LCDNet / OT（0136）：学习式，OT 纯检索（仅 yaw 不变），LCDNet 检索+6-DOF 位姿（UOT 头）。BEVPlace / SeqOT（0137）：学习式投影图/序列，BEVPlace 对平移鲁棒+给 2-DOF 位置（不估 yaw），SeqOT 纯检索、yaw 不变（证明）、扛长期。趋势：从免训练 → 学习式，从只检索 → 顺带出位姿/位置，不变性从「搜」变「长进结构」。
