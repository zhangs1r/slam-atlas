2. 这一季要还的两笔债

第二季结束时，我在 0017 课里留了一张悬念清单。还剩下三条没还，其中两条正好落在这一季。

悬念④：「提取 vs 不提取特征」为什么来回摆动？

第一季 0006 课（LiDAR 里程计综述）第一次提出这个疑问：特征法说特征稳、直接法说特征丢信息，两边都有道理。
第二季 0022 课（点云 BA）给了一个中间态——提取面/边特征做关联，但残差用全部原始点。
这一季的 0046–0050 是这条线索的完整答案。你会看到这条路怎么从"全稠密但要 GPU"（DTAM）→"只挑梯度大的像素"（LSD-SLAM）→"干脆回到稀疏点但补上光度标定"（DSO）→"只在关键帧提特征"（SVO），一路摆动。

悬念⑤：IMU 初始化到底怎么做？

第二季 0029 课讲预积分时，原文明确说它没有初始化章节——它假设前端已经给了关键帧、外参已标定、时间已同步。
我在课上把这条标成了"该论文的空白"。
这一季的 0057 与 0064 就是来填这个空白的。VINS-Mono 用视觉 SfM 先跑一遍再解重力/尺度/速度；而 0064 那篇更狠——只用 IMU 测量做优化，在还没有可靠视觉信息的那几秒就把重力方向和尺度定出来。

剩下的悬念③（ikd-Tree 与 k-d 树差在哪）与（3DGS 的自适应密度控制）不在这一季，它们分别在阶段 D（激光主干）与阶段 F（神经隐式与 3D 高斯）里还。

4. 一条暗线：单目「尺度」是怎么被一步步解决的

如果你只能记住这一季的一条线索，请记这条。第二季 0024 课（VO 教程）说过一句很关键的话：

单目相机只能给出方向（bearing），位姿只能恢复到一个尺度因子之内。

这句话在第二季只是一个"已知限制"。但你看完整季会发现——这十多年的视觉 SLAM 史，有相当一部分就是在跟这个尺度因子搏斗。

5. 另一种读法：按"误差在哪个空间度量"看

如果你更偏工程思维，这条线索可能更好用。整个视觉 SLAM 的方法家族，可以按误差定义在哪里分成两半：

重投影误差（在图像坐标上比）

把 3D 点投到图像上，看它离观测到的像素位置差多少。
特点：只关心"点跑到哪了"，对亮度变化、曝光变化完全免疫（因为压根不看灰度）。
代表：PTAM / ORB-SLAM 全系 / VINS-Mono。/ 理论根在第二季 0024 课的"3D-2D 在图像平面最小化更准"。

光度误差（在灰度值上比）

把一块像素图案按深度和位姿"搬"到另一帧，看对应像素的灰度差多少。
特点：用上了图像里几乎全部信息，在弱纹理、模糊、运动快时更稳；代价是怕光照变化、怕标定不准、会非常非凸。
代表：DTAM / LSD-SLAM / DSO / SVO / ROVIO。

而这个选择还有一个"终极裁决"——第二季 0026 课讲 SGM 时提过"稠密不提取特征"这一路，到这一季 0048 课（DSO）给出了最漂亮的一段实验：作者人为加两类噪声，看谁先垮。结论是：

$$\text{几何噪声强(卷帘快门/标定不准)} \Rightarrow \text{间接法胜}\qquad \text{光度噪声强/标定良好} \Rightarrow \text{直接法胜}$$

所以"特征法好还是直接法好"这个问题本身问错了。正确问法是：我的相机好不好、场景光变不变、算力够不够。

互动判断 ②

一台手机（卷帘快门、镜头畸变大、自动曝光乱跳）上跑视觉里程计，按 DSO 那篇的实验结论，哪种路线更现实？

6. 怎么读这一季（三种读法）

如果你的时间只够读 8 节，按这个顺序：

  1. 0042 PTAM —— 架构革命：为什么跟踪与建图要分家（这一个想法之后所有系统都在用）
  2. 0043 ORB-SLAM —— 特征法标杆：三线程 + 一套 ORB 服务所有任务
  3. 0047 LSD-SLAM —— 尺度第一次被当变量估（sim(3)）
  4. 0048 DSO —— 直接法的巅峰 + 全季最重要的"四象限"坐标系
  5. 0057 VINS-Mono —— 优化派 VIO 的教科书，也是第二季悬念⑤的答案
  6. 0061 OpenVINS —— 一致性讲得最透的一篇
  7. 0063 DM-VIO —— 延迟边缘化：把"边缘化会给错信息"这件事彻底解决
  8. 0067 自动驾驶 SLAM 综述 —— 把整季放回大尺度场景里看

这 8 节串起来，就是一条完整的"视觉 SLAM 主干演进史"。

如果你想跟着课程顺序走完 37 节，建议这样安排节奏：

  • 模块 1、2（0041–0050）连着读——它们是"同一个问题、两套哲学"的正面交锋，分开读会丢掉对比的快感。
  • 模块 3、4（0051–0056）可以快一点：RGB-D 与学习式这两支是"换条件"而不是"换哲学"，重点是看它们各自补上了什么、又留下了什么坑。
  • 模块 5（0057–0064）要慢，尤其 VINS-Mono 与 OpenVINS 两节。这一模块是这一季技术密度最高的地方，也是第二季预积分那一套真正开始干活的地方。
  • 模块 6、7（0065–0075）可以当成"挑着读"——按你现在关心的问题选（室外？动态？光照？算力受限？）。

关于现实

课后练习

  1. 用一句话说清"重投影误差"与"光度误差"的区别。说出各自用到了图像里的什么信息、以及各自的致命弱点是什么。
    展开查看答案

    重投影误差：把 3D 点投影到图像上，比较投影位置与观测到的像素位置之间的差距。它只用到特征点的位置（坐标），完全不用灰度的具体数值。
    致命弱点：只依赖少量稀疏特征，丢掉了边缘、弱纹理等大量信息；在模糊、快速运动、弱纹理场景下容易匹配失败。

    光度误差：把一块像素图案按估计的深度与位姿"搬"到另一帧，比较对应像素的灰度值。它用到了图像里几乎全部信息。
    致命弱点：对光照/曝光变化极其敏感（所以 DSO 才必须做光度标定 + 仿射亮度模型）；误差函数高度非凸，对初值敏感；对相机标定精度和卷帘快门这类几何噪声尤其脆弱。

    一句话记法：重投影误差关心"点跑到哪了"，光度误差关心"这块图案变暗了多少"。

  2. 第二季 0029 课明确说预积分那篇论文没有初始化章节。请说出：视觉惯性初始化到底要解出哪几个量？为什么它必须是"联合"求解而不是一个个单独解？
    展开查看答案

    至少要解出四样：① 重力方向（决定 roll/pitch 参考）、② 尺度（单目看不到的世界尺度）、③ 速度（IMU 积分需要初速度）、④ IMU 偏置（陀螺与加速度计的零偏）。

    为什么必须联合：这几样互相纠缠。举例——重力方向估错，会被 IMU 积分的加速度项"吸收"成尺度误差；尺度估错，又会让速度看起来偏大。单独解任何一个都会把误差归到别人头上（这正是"错误可观性"的来源）。所以主流做法是搭一个线性最小二乘（VINS-Mono 用视觉 SfM 起步，把这四样打包成一个线性方程一起解），或者干脆用"只用惯性测量的优化"（0064 课那篇）。

  3. "四象限坐标系"里，dense/sparse 与 direct/indirect 是两个正交轴。请各举一个"直接但不稠密"和"稠密但不直接"的例子，并说明为什么这两个例子恰好证明了"正交"。
    展开查看答案

    直接但不稠密：DSO（0048 课）。它直接在灰度上最小化光度误差（direct），但只用约 2000 个活动点（sparse）——用的点甚至比 ORB-SLAM 还少。

    稠密但不直接：稠密光流 + 正则化那一类（原文在 DSO 的引言里点名过这一格）。它处理整幅图的每个像素（dense），但像素之间的对应关系是靠光流/描述子匹配 显式建立的（indirect），误差仍定义在几何位置上。

    之所以这两个例子能证明正交：如果"直接"必然意味着"稠密"，那么 DSO 这个反例就不该存在；同理，如果"稠密"必然意味着"直接"，光流法这个反例也不该存在。两个反例各堵住一个方向，所以这两根轴是独立的。

  4. 本季有六个"站"在回应"单目尺度不可观"。请按你自己的理解，把六个站分成两类，并说出每一类的代价分别是什么。
    展开查看答案

    第一类：把尺度纳入估计（LSD-SLAM 的 sim(3)、VI-DSO 把 scale 当变量、VINS-Mono 联合初始化）。
    代价：多出状态与耦合，数值上更难——VI-DSO 正是因此才需要发明"动态边缘化"，因为普通边缘化会把旧尺度钉死、把系统拉偏。

    第二类：从外部拿一个尺度（ORB-SLAM2 用双目基线、CNN-SLAM 用学习到的深度、GVINS/P³-VINS 用 GNSS）。
    代价：多一个"外部来源"，就要多处理它的可靠性问题——双目要标定与同步、学习深度受训练分布限制（CNN-SLAM 在跨域时精度会掉）、GNSS 在城市峡谷里会被多路径污染（所以 GVINS 才需要鲁棒核）。

    补充：还有第三条路是"我不管"——DSO 就明说自己是纯里程计、尺度随便，评测时用 Sim(3) 对齐。代价是它没法单独用来做导航控制。

  5. 为什么这一季把 PTAM（0042）排得这么靠前，甚至排在 ORB-SLAM 之前？请从"它贡献了什么想法"而不是"它性能多好"的角度回答。
    展开查看答案

    因为 PTAM 贡献的不是性能，而是一个架构想法：把"跟踪"与"建图"拆成两个独立的线程。

    在它之前（MonoSLAM），所有路标和相机状态塞在同一个 EKF 状态向量里，规模一大就崩。PTAM 的观察是：这两件事的时间尺度根本不同——跟踪每帧都要出结果（几十 Hz），建图则是"慢工出细活"（可以几百毫秒）。既然快慢不同，就没必要挤在一条时间线上。

    拆开之后还带来两个额外好处：① 建图线程可以做真正的批量 BA（而不是 EKF 的一步更新），精度更高；② 地图可以只保留关键帧，规模不再随时间线性增长。

    这个"分而治之"的想法，之后 ORB-SLAM 直接继承并扩展成三线程（加了回环），再往后几乎所有现代系统都是这个结构。性能会被超越，架构想法不会。
