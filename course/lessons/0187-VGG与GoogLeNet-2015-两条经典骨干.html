1. 开场：清单说这是 VGG，其实它是 GoogLeNet

先处理一件尴尬事。这一节课在课程清单上的主题写的是「VGG（2015）」，但打开论文，你会发现根本不是。原文的一级标题是 Going Deeper with Convolutions，作者是 Christian Szegedy、Wei Liu、Yangqing Jia 等，摘要第一句就是：

We propose a deep convolutional neural network architecture codenamed Inception …

这句话在说什么：这篇论文提出的东西代号叫 Inception。紧接着摘要里写明：提交 ILSVRC14 的那个具体版本叫做 GoogLeNet，一个 22 层的深网络。所以这篇论文是 GoogLeNet / Inception，不是 VGG。而更麻烦的是：我们整个 255 篇的语料库里，根本没有 VGG 的一手论文——全库只有 2017 年的 SemanticFusion 一篇真正引到它（具体是正文里一句「based on the VGG 16-layer network」）。

但这里还有一件更值得注意的事：VGG 在 SLAM 语料里被引用的密度，远高于 GoogLeNet。整个语料库有 96 篇论文提到 VGG，其中 25 篇明确提到 VGG-16；而 GoogLeNet / Inception 只有 22 篇。也就是说，读者翻 SLAM 论文时真正撞上的是 VGG-16 backbone，不是 GoogLeNet。所以我们这样处理这节课：

VGG 数字全部标「转引」

前置补丁：VGG 是谁

VGG 由 Simonyan 与 Zisserman 发表于 2015 年 ICLR（发表处转引自 ResNet 篇参考文献 [40]）。做法极简：只用 3×3 小卷积一层层往下堆，堆到 16 或 19 层。它的数字全是转引——ResNet 篇给出 VGG-16 为 15.3 billion FLOPs、VGG-19 为 19.6 billion；2022 年 YOLO-SLAM 的 Table 1 给出 VGG-16 的 Top-1 70.5 / Top-5 90.0 / 权重 528 MB / 106 FPS。一句话：VGG-16 精度最低、权重最重，但推理最快。

最后，把这处清单失误本身也当成一个教学点。连课程清单都会把两个经典网络记混——一个 2014 年的 ILSVRC 冠军、一个只差 0.65 个百分点的亚军，名字一换就分不清了。那么读者更不能凭名字猜内容。本季的主题是「补名词」，而补名词的第一步不是背，是打开论文看一眼它到底在讲什么。

2. 前人卡在哪：加大规模的两笔账

要讲清 Inception 的价值，必须先讲清它之前的人是怎么做的、以及卡在哪。从 LeNet-5 起，CNN 的标准结构就是：堆卷积（可选对比度归一化 + max-pooling）→ 一个或多个全连接层。想变强怎么办？最直接的办法是加大规模——同时加深度（层数）和加宽度（每层的单元数）。原文承认这条路「既简单又安全」，但紧接着点了两个致命伤。

第一笔账：参数爆炸 → 过拟合

原文第 41 行：「Bigger size typically means a larger number of parameters, which makes the enlarged network more prone to overfitting」。人话：网络越大参数越多，数据不够就只会背答案。而按原文说法，带强标注的数据集「laborious and expensive to obtain」——贵得要命。

第二笔账：计算量二次增长

原文第 48 行：「if two convolutional layers are chained, any uniform increase in the number of their filters results in a quadratic increase of computation」。人话：两层卷积串起来，滤波器数一起翻倍，计算量翻四倍。算力预算总是有限的，所以「efficient distribution of computing resources is preferred to an indiscriminate increase of size」。

那能不能靠稀疏来省算力？原文讨论过这条路（用稀疏矩阵替换全连接层），但给出了一个非常工程化的否决理由：即使算术运算量减少 100×，lookup 与 cache miss 的开销也会占主导，所以「switching to sparse matrices might not pay off」。这才是 Inception 真正的出发点：既然稀疏在今天（2014 年）的硬件上不划算，那就造一个用稠密算子堆出来、但结构上模仿稀疏的模块。原文自己就是这么说的——Inception 一开始只是「a case study for assessing the hypothetical output of a sophisticated network topology construction algorithm」。

顺便，原文给这个模块的名字记了一笔有趣的账：网络名取的是 Lin 等人的论文名 Network in network 加一句网络梗 「we need to go deeper」；而「deep」在这里有双重含义——既指新增了 Inception 模块这一层级的组织，也指字面意义上网络更深了。「Inception」本身则是为 ILSVRC14 提交起的代号，不是方法学名称。

3. 核心机制：一个模块里同时看三个尺度

Inception 模块的做法，一句话：不再「一条直线堆到底」，而是设计一个「分叉再合流」的模块。同一个模块内并排放 1×1、3×3、5×5 卷积和一条 3×3 max pooling 支路，四条支路的输出在通道维拼在一起，成为下一层的输入。

生活类比：想象一个病人挂号，不是只找一位医生，而是同时挂了三个专科——眼科用 1×1 看单个像素的颜色，皮肤科用 3×3 看一小块纹理，影像科用 5×5 看更大的形状——最后把三份诊断报告订成一本，再交给下一位医生。注意关键词是「订成一册」（拼接），不是「加起来」（求和）：它们是并列的信息，不是需要合并的意见。这个区别很要紧，因为下一课 0188 的 ResNet 用的恰好是「加起来」。

关键的第二招是降维。原文说得很直接：「1×1 convolutions are used to compute reductions before the expensive 3×3 and 5×5 convolutions」——在昂贵的 3×3 与 5×5 之前，先用 1×1 把通道压瘦。这一招正是 Figure 2(b) 相对 Figure 2(a) 的全部区别。下面两张原图就是这对对照：

4. 公式与形状账：1×1 到底省了什么

这里要提前说明一件事：GoogLeNet 这篇论文全文没有一个编号公式。它表达结构的方式是两张结构图（Figure 2、Figure 3）加一张逐层的算力表（Table 1）。原文对模块的描述是一句话：「output filter banks concatenated into a single output vector forming the input of the next stage」。所以本课的「公式」是从卷积的定义直接写出来的参数账，而不是原文里的式子——这一点必须写清楚，免得读者以为原文给了这些算式。

$$\text{一个卷积层的参数量} = k \times k \times C_{\text{in}} \times C_{\text{out}} + C_{\text{out}}$$

这句话在说什么：① 这个式子在算「一层卷积要学多少个权重」——每个输出通道对应一个小得多的卷积核（k×k），它要连上所有输入通道（C_in），所以乘法关系是 k×k×C_in×C_out，最后再加每个输出通道一个偏置；② 为什么这么算——因为卷积核是共享的，它在空间上滑过整张图，权重数量只跟核大小和通道数有关，跟图像多大无关，这正是卷积比全连接省的地方；③ 形状账（这是本课最有用的一段）：假设输入 64 通道、想输出 128 通道、核是 5×5，直接算需要 5×5×64×128 = 204800 个权重；如果先用 1×1 把 64 通道压到 32 通道，再 5×5 升到 128，则需要 1×1×64×32 = 2048，加上 5×5×32×128 = 102400，合计 104448——只有直接算的 51%，而输出形状完全一样（都是 128 通道）。代价是中间只剩 32 个通道，信息被压过一道，这就是这一招唯一的风险。

原文还给了这条账的总体结论（这句可以放心引用，因为它出在正文里）：所有旋钮都调好之后，「networks that are 3−10× faster than similarly performing networks with non-Inception architecture」——相比性能相当的非 Inception 网络，能快 3 到 10 倍。但要付出代价：「this requires careful manual design at this point」——需要小心翼翼地手工设计，这句话后面我们会回来算它的账。

另外，原文在 Table 1 里给了逐层的算力账（例如 7×7/2 那一层是约 2.7K 参数 / 34M 次运算），但这份表格在本语料库里的 OCR 是被严重压平的（11 列数据挤在混排的表格里），单格数字不可靠，所以本课只引用它最稳定的一处结论，不逐格抄数。这也是本季的一条引用纪律：表格式数字引用前必须回查正文句子，回查不到就不写。

6. 它在前八季的哪些课、哪些方法里出现过

这是本季每节课的硬要求：必须回答「这个零件在前八季的哪些课、哪些方法里出现过」。先说一个可能让你意外的结论：GoogLeNet 本体的直接引用很少，而 VGG 的引用密度高得多。下面分两条给出原句。

（A）GoogLeNet / Inception 这条线

  • 第八季 0165 YOLO-SLAM 的前身、本季 0191 的主角 YOLO（2016）——它明确把 Inception 模块拆掉了。原文原话：「Our network architecture is inspired by the GoogLeNet model for image classification [33] ... Instead of the inception modules used by GoogLeNet, we simply use 1×1 reduction layers followed by 3×3 convolutional layers」。这是本案最有价值的一条：后人对 Inception 的取舍，恰恰证明「1×1 降维」才是被继承最多的那个零件，而多路并行那部分被丢掉了。
  • 第七季与回环检测——2021 年的 DeepSLAM 里，回环检测网络（Loop-Net）用的是 Inception 变体：原文说「The Inception ResNet V2 architecture [43] is adopted here. The Loop-Net maps images into feature vectors for loop closure detection」。这是本季接回「学习式回环检测」的最强接口。
  • 2024 年的 DeepSLAM 综述也提到有人比较过 PCANet、AlexNet、CaffeNet 与 GoogLeNet 四种深度学习架构在回环检测上的表现。

（B）VGG 这条线（全部为转引）

  • 第八季 0159 SemanticFusion——语义建图的代表方法之一，它把 VGG-16 当分割主干：「Their architecture is itself based on the VGG 16-layer network [21], but with the addition of max unpooling and deconvolutional layers which are trained to output a dense pixel-wise semantic probability map.」注意这句里的后半段：VGG 只负责编码，要出逐像素结果还得加反池化与反卷积——这就是 0190 FCN 要讲的接力。
  • 学习式里程计——2018 年的 UnDeepVO 的位姿估计器是「a VGG-based [19] CNN architecture」，输入两张连续单目图、输出 6 自由度变换；2021 年 DeepSLAM 的 Tracking-Net 则是「constructed from a CNN part of the VGGNet [39] plus an RNN」。
  • 第八季 0165 YOLO-SLAM 的 Table 1——这是本课 VGG 数字的转引来源：VGG-16：Top-1 70.5 / Top-5 90.0 / 权重 528 MB / 106 FPS；同表 ResNet-101 是 77.1 / 93.7 / 160 MB / 53 FPS；Darknet-53 是 77.2 / 93.8 / 159 MB / 78 FPS。VGG-16 精度最低、权重最重，却是三者中最快的——因为它结构最简单。
  • 第七季 0134–0140 地点识别的混合主干——2023 年的一篇地点识别论文一边用「Conv1–Conv3 layers of VGG-16 to extract the CNN feature pyramid」，一边把 Swin-B 接在它后面组成「hybrid CNN-Transformer」。这是本课与 0194 同框的唯一一处真实论文。
  • 一个反向的证据——2023 年的关键点检测论文 SiLK 用 VGG 级别的窄骨干，结论是相比现代大骨干「no empirical performance gain despite far greater parameter counts」：参数多得多，却没有性能收益。这说明 VGG 级别的窄骨干在关键点这种任务上已经够用。

一句话总结这两条线：GoogLeNet 贡献给后世的不是「多路并行」，而是 1×1 降维这个零件；VGG 贡献给 SLAM 的则是「一个简单、好懂、拿来就能当 backbone 的编码器」。而读者在论文里真正会撞见的，是后者。

7. 它不完美在哪：所以 SLAM 要加几何约束

本季的第二个硬要求：每个零件都要讲它的毛病。GoogLeNet 的毛病很特别——它的作者自己就先说了，而且说得比后人更狠。

毛病一：整个架构靠手工调

原文承认滤波器尺寸限定在 {1×1, 3×3, 5×5} 是「based more on convenience rather than necessity」（出于便利而非必然）；承认只在高层用 Inception 模块、低层保留传统卷积，是「not strictly necessary, simply reflecting some infrastructural inefficiencies」；也承认这套设计「requires careful manual design at this point」。人话：这不是一个能自动长出来的架构，是一层层试出来的配方。

毛病二：作者自己不确定成功该归功于谁

原文第 56 行原话：「although the Inception architecture has become a success for computer vision, it is still questionable whether this can be attributed to the guiding principles that have lead to its construction.」人话：结果好，但未必是那套设计原则带来的好——可能只是碰巧调对了。这种诚实很少见，但读课时必须照实转述。

毛病三：更宽更深的版本增益「仅有一点」

论文做过一个更宽更深的 Inception 版本，结果「improve the results only marginally」，于是没写进正文；7 个 ensemble 模型里有 6 个用的是 Table 1 那个配置。也就是说，这套模块的可扩展性是有天花板的。

毛病四：检测任务里连框回归都没做

原文第 147 行：「contrary to R-CNN, we did not use bounding box regression due to lack of time」。人话：检测那一半的工作其实是半成品。这直接说明：它不是一个检测器，它只是一个分类器加一根检测的脚手架。

现在把这些毛病接回 SLAM。关键要看清楚：GoogLeNet 是一个分类网络——它的输出是「这张图属于 1000 类里的哪一类」。它输出的东西里有类别、有置信度，但没有任何几何量：没有像素级的边界、没有深度、没有尺度、没有几何一致性。

所以当 SLAM 论文把它（或它的同类）当骨干用时，必然要多做几件事：

  • 要拿几何，就得改结构。2017 年的 CNN-SLAM 就是把一个残差网络拆开——前半段当编码器，后半段整个换成上采样，才输出一张深度图。分类网络的天然输出里没有深度，这个深度是硬接上去的。
  • 要拿掩码，就得加分割头。第八季 0159 的 SemanticFusion 在 VGG-16 后面接的是 max unpooling 与反卷积层——这就是 0190 FCN 那一课的内容。
  • 要拿框，就得加检测头。而 Inception 本身在检测任务上连框回归都没做（毛病四），后世才补出 0191 YOLO 这类专门的检测头。

即使这些都补齐了，还差最后一层保险。因为一个学习式零件给出的语义或深度，本质上都是统计预测：可能认错、可能在边界上糊。SLAM 的做法是永远不让语义单独决定几何——语义告诉地图「这里大概是个人」，但「它在哪、有没有动」必须由多视图几何与位姿优化交叉验证。这就是第八季动态块与语义建图块反复出现的「语义 + 几何双保险」，也是本季每一节课最终都要落回的那句话。

LOAM 系列处理的是点云几何，与骨干网络这条线几乎不重叠。本季真正的激光一侧在 0195 与 0196–0197，本课不涉及。

接第八季 0159 SemanticFusion

它用 VGG-16 当分割主干，是把「学习式骨干」直接焊进语义建图流水线的第一站。它当时出的毛病是：VGG 只能出高层的粗特征，要得到逐像素概率图必须再补反池化与反卷积——这一缺口由 0190 FCN 补上。

接第八季 0165 YOLO-SLAM

它的 Table 1 是本课 VGG 数字的转引来源，也是「主干选型要权衡精度 / 体积 / 速度」这条工程思路的实例：VGG-16 精度最低却最快，Darknet-53 居中，ResNet-101 最准但最慢（53 FPS）。

接第七季 0134–0140

地点识别那一块用的混合主干是「VGG-16 金字塔 + Swin-B 并联」——CNN 段就是本课讲的 VGG，Transformer 段是 0194 要讲的 Swin。这是全季唯一一处两者同框的真实论文。

接本季 0191 YOLO

YOLO 明确拆掉 Inception 模块、只保留 1×1 降维加 3×3。读完本课再看 0191，你会明白它继承了什么、丢了什么。

课后练习

  1. 某论文说「我们的骨干是 VGG-16，权重 528 MB」。你如何在不读 VGG 原文的情况下核实这个数字，并说明它的可信度？
    展开查看答案
    去本语料库里找引用 VGG 的论文，核对来源。这个数字来自 2022 年 YOLO-SLAM 的 Table 1（同表还有 VGG-16 的 Top-1 70.5、Top-5 90.0、106 FPS，以及 ResNet-101 的 77.1 / 93.7 / 160 MB / 53 FPS）。可信度判断：它是另一篇论文整理出的对比表，属于二手数据；但因为同一张表里三个骨干预训练模型一起列出、量纲一致，内部自洽度高，作为「VGG-16 又重又简单又快」的定性证据是够用的——本课所有 VGG 数字都属于这一类：只能转引，且必须标出转引来源。
  2. 用本课的形状账算一算：输入 256 通道、输出 512 通道、用 3×3 卷积。直接卷积与「先降到 64 通道再卷积」的参数量分别是多少？省了百分之几？
    展开查看答案
    直接卷积：3×3×256×512 = 1179648。先降维：1×1×256×64 = 16384，再加 3×3×64×512 = 294912，合计 311296。省下 (1179648 − 311296) ÷ 1179648 ≈ 73.6%，只剩约 26.4%。注意输出形状完全一样（都是 512 通道），代价是中间被压到 64 通道——这就是 Inception 里 1×1 降维的全部逻辑。提醒：这是按卷积参数公式算的算例，不是原文表格数字。
  3. 原文承认「it is still questionable whether this can be attributed to the guiding principles」。这句话对读论文有什么方法论意义？
    展开查看答案
    它提醒我们：结果好 ≠ 理由对。作者自己承认，Inception 效果虽好，但未必是那套「稀疏结构近似」的指导原则带来的。读论文时的推论纪律应该是：把「作者报告的实验事实」与「作者给出的解释」分开；前者可以引用，后者只能当作一种解释。这与本季开头在导览课里提的「诚实分区」是同一条纪律——本课把这个纪律落在了具体的一句话上。
  4. 如果让你给 0188（ResNet）做铺垫，你会用本课的哪个数字来制造对比？
    展开查看答案
    用 VGG 的 FLOPs：ResNet 篇转引给出 VGG-19 为 19.6 billion FLOPs、VGG-16 为 15.3 billion，而 34 层的残差网络只有 3.6 billion——「深了 8 倍却便宜得多」。这条对比的妙处在于：GoogLeNet 与 VGG 都在用「堆」的办法变强（一个堆模块、一个堆层），而 ResNet 要解决的问题恰恰是「堆到一定程度就堆不动了」。所以本课最后留下的悬念是：如果继续加深不管用，怎么办？那就是下一课。
