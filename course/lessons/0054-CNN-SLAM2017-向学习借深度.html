1. 先说清这篇在干什么

先给不熟悉背景的读者一句话：单目相机拍一张照片，理论上无法知道物体离你多远。它只能告诉你方向（bearing）——「那边有一面墙」，但「墙在 3 米还是 30 米」它不知道。因为把一个场景整体放大两倍，投影到图像上是完全一样的。

过去解决这个问题的办法是动起来：相机移动一小段距离，看同一个物体在两张图里的位置偏移了多少（视差），就能反推深度。这也是 0046 DTAM、0047 LSD-SLAM、0048 DSO 这几节的共同思路。但这条路有两个死穴：

死穴一：尺度不可观

靠视差算出的深度，永远差一个全局倍数。你可以得到「形状完全正确、但不知道多大」的重建

死穴二：纯旋转就没戏

相机原地转头时，没有任何视差可用——没有基线，就没有深度。原文实测：在这类序列上，LSD-SLAM 结果「significantly noisy」，而 ORB-SLAM 「completely fails」（4.2 节）

CNN-SLAM 的想法直接：既然「看一张图猜深度」这件事已经被深度学习做出来了，那就把它接进来当先验。它不替代几何，而是补几何的短板——这就是「向学习借」的意思。

这篇文章发表于 2017 年 CVPR。它用的深度网络是当时同组的前作 Laina 等（3DV 2016），基于 ResNet-50 的全卷积残差网络；它的 SLAM 骨架则是 LSD-SLAM（也就是我们上一站 0047 学过的那套半稠密直接法）。所以你可以把这一节理解成：在 0047 的机器上，插了一块「深度预测」的模块。

2. 尺度这条暗线：从「绕开」到「借来」

我们在 0040 导览课里立过一条暗线：整个第三季都在回答「单目的尺度问题怎么办」。走到现在，已经出现过三种不同的态度：

① 显式建模（0047 LSD-SLAM）

承认尺度的存在，把它当成一个待估变量，升到 $\mathfrak{sim}(3)$ 上估计。代价是状态多一维、数值更娇气

② 换传感器（0049 VI-DSO / 0051–0053 RGB-D）

用 IMU 的加速度、或 RGB-D 相机的深度读数，从物理上给出「米」。代价是要花钱、要标定、要处理多传感器同步

③ 借外部先验（本节 CNN-SLAM）

让一个在大量「图像-深度」配对上训练过的网络直接吐出带绝对尺度的深度图。代价是把「模型好坏」变成了新的不确定源

这里有个技术细节很值得单独看一眼，因为它把「尺度从哪来」讲得极其直白。网络训练时用的是一个特定焦距的相机。如果现在手头这台相机的焦距不一样，同样大小的物体在图像上占的像素数就不同，网络原先学到的「占这么多像素 ≈ 那么远」的对应关系就偏了。原文的修正方式简单到有点粗暴（式 5）：

$$\mathcal{D}_{k_i}(\mathbf{u}) = \frac{f_{cur}}{f_{tr}}\,\tilde{\mathcal{D}}_{k_i}(\mathbf{u})$$

其中 $\tilde{\mathcal{D}}_{k_i}$ 是网络直接回归出来的深度，$f_{cur}$ 是当前相机的焦距，$f_{tr}$ 是训练时那台相机的焦距。说白了就是：焦距差几倍，深度就整体缩几倍。这正说明它拿到的尺度是「网络记住的绝对大小」——不是几何推出来的。

⚠️ 这里要纠正一个我差点写错的数字

在准备这节课时，我一度以为原文给出了「33.99% → 55.75% → 64.52%」这样一条精度阶梯（网络原始深度 → 焦距调整后 → 精化后）。回原文逐行核对后确认：这三个数字原文并没有给。原文 Fig. 3 确实做了 (a) 直接预测 / (b) 焦距调整后 / (c) 再加精化 的三格对比，但具体数值标在图上、md 转录未保留；能查证的真实数字在 Table 1（见第 6 节）。所以本课只讲「逐级提升」这个趋势，不给这三个百分比——宁可少给一个数字，也不给你一个查不到的。

3. CNN 深度到底被用在哪三处

这是本节最需要搞清的问题。很多二手介绍会说「CNN-SLAM 就是用 CNN 深度做 SLAM」，但原文其实把用途拆得很清楚，一共三处，而且三处的性质完全不同：

用途一：当初始值

每次新建一个关键帧，先让网络预测一张稠密深度图，作为后续优化的起点。相比 LSD-SLAM 那种「不确定度初始化为一个很大的常数」，这里起点好得多

用途二：提供绝对尺度

这是最关键的。有了它，整段轨迹和重建不再「差一个倍数」。原文 Fig. 1 专门画了对比：(a) 本文的结果 vs (b) 当时最好方法的结果

用途三：逐像素加权融合

把 CNN 深度和几何估计的深度按各自的不确定度融合起来。这一处是本节技术含量最高的部分，也是下一个小节的重点

这里先埋一个伏笔：用途三的「加权融合」到底在融合什么？答案是——融合两个都不完美的深度估计，让它们互相纠错。下一个案例把这个机制和数字讲透。

4. 逐像素融合：谁更可信，就听谁的

先讲一个直觉。你有一台老式机械体重秤（精度差、晃得厉害）和一台电子秤（精度好）。两台都称同一个东西，一个读数 3.0 kg、一个 3.3 kg，你信谁？——谁的误差小就多信谁。如果知道机械秤的误差标准差是 0.3、电子秤是 0.1，那么电子秤的话应该占更大的权重。

这就是逆方差加权（inverse-variance weighting），统计学里的标准做法。CNN-SLAM 用的正是它，只不过用在了「深度」上：每个像素有两个深度估计，各自带一个不确定度 $U$（方差），按式 8 融合：

$$\mathcal{D}_{k_i}(\mathbf{u}) = \frac{\tilde{\mathcal{U}}_{k_j}(\mathbf{v})\cdot \mathcal{D}_{k_i}(\mathbf{u}) + \mathcal{U}_{k_i}(\mathbf{u})\cdot \mathcal{D}_{k_j}(\mathbf{v})}{\mathcal{U}_{k_i}(\mathbf{u}) + \tilde{\mathcal{U}}_{k_j}(\mathbf{v})}$$

读这个式子有个小陷阱：分子里，$\mathcal{D}_{k_i}$（当前关键帧深度）乘的是对方的不确定度 $\tilde{\mathcal{U}}_{k_j}$。这不是写错了——乘对方的方差，就是「对方的方差越大、我越少听他的」。融合后方差按式 9 收缩：$\mathcal{U} = \mathcal{U}_{k_i}\tilde{\mathcal{U}}_{k_j}/(\mathcal{U}_{k_i}+\tilde{\mathcal{U}}_{k_j})$。

互动判断

假设某个像素上，CNN 给的深度是 3.00 m（标准差 0.30 m，即方差 0.09），几何估计给的深度是 3.30 m 但质量很差（标准差 0.40 m，即方差 0.16）。按式 8 融合，结果最接近哪个？

5. 意外红利：纯旋转也能跑

这一节要讲一个很漂亮的连锁反应，它和「尺度」无关，但对实际使用很重要。

回忆一下 0024 讲过的：几何法估深度的前提是有基线——相机得平移，才能产生视差。那么相机原地转圈（比如人站着不动环顾四周、或者云台扫视）会发生什么？基线接近零，视差接近零，深度估计彻底失效。

而 CNN 的深度是从单帧图像独立预测出来的——它压根不需要基线。所以当几何法趴下的时候，这条路径还站着。

原文在 4.2 节专门用一个几乎纯旋转的 TUM 序列（fr1/rpy）做了验证，并且说得很克制：LSD-SLAM 的结果「significantly noisy」，而 ORB-SLAM 在这个序列上「completely fails」——原因是它缺少初始化所必需的基线。这是这一路方法少见的、能拿来说「我在这里能跑，别人不能」的场合。

6. 实验、以及那些该讲清的代价

6.1 一个刻意设计的困难设定：跨域泛化

这一篇的实验设计里有一个我特别欣赏的地方，值得单独指出：训练域和测试域是分开的，而且是刻意分开的。

训练

NYU Depth v2 的室内部分（Kinect 采集的深度真值）。原文形容它「包含许多客厅、厨房、卧室」

测试

ICL-NUIM（合成）+ TUM RGB-D（Kinect）。原文指出 TUM 那批「聚焦于办公室，有桌子、物件和人」，与训练集场景不同；相机传感器、视角、场景布局都不一样

原文的原话是，这样做是为了「portray the capacity of our approach — particularly relevant for practical uses — to generalize to novel, unseen environments」。也就是：它想证明的不是「在我的数据上我多强」，而是「换到没见过的地方还能不能用」。这个姿态在整个第三季里都不多见，值得记住。

6.3 还有一件顺手做的事：语义融合

因为同一个网络架构也能训成做逐像素语义分类（原文用了 4 个超类：地面 / 垂直结构 / 大件家具 / 小件物体），作者顺手把语义标签也融进了三维模型——每个 3D 元素带一个类别。原文说这是「据我们所知，首次在单目相机上展示联合的三维与语义重建」。

但这里要替原文说句公道话：它在 3.2 节明确声明，语义分割用哪个算法其实不重要——「although in principle any semantic segmentation algorithm could be used, the primary objective of this work is to showcase how frame-wise segmentation maps can be successfully fused within our monocular SLAM framework」。也就是说：语义是配菜，主菜是深度融合。读到这类自我限定，要给它记一分诚实。

6.4 该讲清的代价

CNN 深度没进联合优化

这是最根本的一条。网络给出的深度只当初始值和融合的一方，它的权重是固定的，并没有和位姿一起被联合优化。原文在结论里也把这一点指明了方向：未来的路是「closing the loop with depth prediction」，即用几何精化出来的深度反过来改善深度预测。这个「闭环」正是后面 0055 CodeSLAM 与 0056 DeepFactors 要干的事。

依赖训练分布

深度网络的输出只在它见过的场景类型内可信。虽然本文刻意做了跨域测试，但 TUM 与 NYU 都还是「室内、RGB 相机」。原文也承认深度预测的局限在边缘处模糊，所以才需要几何来修。

原始 CNN 深度在低纹理区也只是「更可信一点」

注意上面的融合算例：情形二里融合结果的 σ 仍有 0.24 m，只是从 0.40 降下来。CNN 不是「白墙的正确答案」，只是「比几何观测多一点信息」。

需要 GPU

实验平台是 Quadro K5200（8 GB）。原文特意说明分工：CNN 预测与语义分割跑 GPU，其余全跑 CPU，而且分成两个 CPU 线程（一个管逐帧的位姿估计与深度精化，一个管关键帧相关的初始化、位姿图优化与地图融合），以此做到实时。这是一个很实在的工程说明。

把这条线串起来看

本节结尾，原文留了一句话作结：深度预测与 SLAM 的结合，是解决传统单目重建固有局限的「promising direction」——尤其是在估计绝对尺度、在无纹理区获得稠密深度、以及应对纯旋转运动这三件事上。

而它没解决的是：这份借来的深度，能不能被优化？——下一节 0055 CodeSLAM 正面回答这个问题。原文 0055 对本篇的批评就一句话：CNN-SLAM「it is not possible to optimise the predicted depth maps further for consistency when multiple keyframes overlap」。

7. 巩固练习

课后练习

  1. 用三句话向同学解释：为什么「用网络预测深度」能解决单目尺度问题？它和 0047 用 sim(3) 估尺度、0049 用 IMU 给尺度，本质差别在哪？
    展开查看答案

    ① 单目的困难在于「放大两倍的场景投影完全一样」，所以尺度无法从几何观测中确定；② 网络在大量「图像—真实深度」配对上训练过，因此它输出的是带物理单位的绝对深度，等于把先验知识带进来；③ 差别在于「信息从哪来」——0047 是从数据本身榨（把尺度当变量估，代价是状态多一维），0049 是从另一条物理传感通道拿（IMU 有真实加速度），本节是从训练数据里沉淀的先验拿。三者都是「给系统补充尺度信息」，但供给源不同：观测内、传感器间、模型里。

  2. 算一算：某像素上 CNN 深度 2.00 m（σ=0.20 m）、几何观测 2.60 m（σ=0.10 m）。按式 8 融合结果是多少？融合后方差是多少？
    展开查看答案

    方差：$U_{cnn}=0.04$，$U_{geo}=0.01$。

    $D = (U_{geo}\cdot D_{cnn} + U_{cnn}\cdot D_{geo})/(U_{cnn}+U_{geo}) = (0.01\times2.00 + 0.04\times2.60)/(0.04+0.01) = (0.02+0.104)/0.05 = 0.124/0.05 = 2.48$ m。

    融合后方差 $U = (0.04\times0.01)/0.05 = 0.008$，σ = 0.0894 m。

    核对合理性：几何观测更可信（σ 小一半），所以结果 2.48 明显偏向几何的 2.60 一侧；融合后方差 0.008 比两者任何单独一个都小，符合「两个独立估计融合能降低不确定度」。

  3. 为什么原文说「即使给 LSD-SLAM 引导了正确的初始尺度，本节方法平均仍更准」这件事很重要？它在反驳什么？
    展开查看答案

    因为它在反驳一个很自然的质疑：「你赢，是不是只因为你把尺度搞对了？」如果收益全部来自尺度修正，那么把 LSD-SLAM 的初始尺度用真值引导一下（LSD-BS），两者就该打平。但实验显示本文平均仍更高，原文的判断是这体现了「深度融合方法本身的内在有效性」——也就是逐像素按不确定度融合这个机制在起作用，不只是乘了个系数。

  4. 原文为什么特意区分 LSD-SLAM 和 LSD-BS 这两个基线？如果没有 LSD-BS，会得出什么可能被误读的结论？
    展开查看答案

    LSD-BS 是「用真值深度引导出正确初始尺度」的 LSD-SLAM，等于一个「尺度问题已被作弊解决」的对照。若没有这个基线，本文的优势可能被简单归因为「单目尺度不可观」这一个众所周知的原因，读者会以为只要解决了尺度大家的精度就一样。有了 LSD-BS，才能把「尺度修正的贡献」和「深度融合的贡献」拆开——这是做对照实验时很标准、也很容易被偷懒省掉的严谨做法。

  5. 本节最根本的局限是「CNN 深度没有进入联合优化」。请说明：为什么这会导致误差被固化？以及这个局限是怎么成为下一节 CodeSLAM 的切入口的？
    展开查看答案

    因为它只作为初始值与融合的一方参与，权重固定、不参与梯度回传，所以网络那份深度中系统性的错误（比如某类材质总是估偏）无法被多视角的观测纠正过来；几何精化只在自己可信的区域改它，改不动的部分就永久留在那里。

    CodeSLAM 的切入口正在这里：它不再把深度当成一张「外部送进来的图」，而是把深度表示成一个只有几十维的向量（code）」，于是这个向量可以像位姿一样被求导、被优化——深度因此第一次能被「优化」，而不只是「被融合」。原文对 CNN-SLAM 的批评原话就是它「it is not possible to optimise the predicted depth maps further for consistency」。
