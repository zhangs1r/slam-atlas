1. 它的几条贡献（逐条按原文抄）

FAST-LIVO2 是 HKU-MARS 组 2025 年发表在 IEEE T-RO 上的方法/系统论文，摘要明言它是「一个快速的直接法激光-惯性-视觉里程计框架」，用 ESIKF 紧耦合 IMU + LiDAR + 图像，统一体素地图，视觉最小化光度误差。它是本组（紧耦合 LIVO）的集大成与全季顶点。

原文（§I 贡献段与 §II-B）自陈的贡献，逐条如下：

贡献 1：序贯更新（sequential update）

把一帧内的激光与图像测量分先后、一个一个地更新同一个状态，每更新一次重新线性化。原文明确说这是为「改善用异步更新的 FAST-LIVO 的鲁棒性」。注意：序贯更新是本篇贡献，不是 v1 的。

贡献 2：统一体素地图存平面

把激光点云和视觉点存进同一个自适应体素地图，每个体素拟合出平面（中心 + 法向 + 协方差），并复用平面先验加速视觉对齐。直接解决了 v1「同深度假设」在斜平面不准的问题。

贡献 3：在线曝光估计 $\tau$

状态里多了一维逆曝光时间 $\tau$（随机游走），把当前帧亮度缩放到参考帧尺度，使光度误差在光照变化时可比。v1 没有。

贡献 4：按需体素光线投射

图像格在激光近距盲区/超出激光视场时，沿射线回溯采样体素来召回视觉地图点，提升鲁棒性。v1 没有。

论文还在 §II-B 给出了一个自己的「紧耦合两视角分类」：按状态估计层（某传感器估计是否作为另一传感器模型的优化目标）和原始测量层（原始数据是否结合）来分松/紧耦合；并把本系统与 R3LIVE 区分开——R3LIVE 的 VIO 用逐像素直接法（贵、依赖光流初值），本系统用图像块级稀疏直接法，一步 frame-to-map 对齐，且复用统一地图的平面先验。

2. 体素地图里到底存什么（本节灵魂）

这是全课最该讲清的一点。每个体素里存的不是一堆离散点，而是一块被拟合出来的平面。

具体说，一个体素（voxel）里保存：

  • 平面参数：平面中心 $\mathbf q_j$（一个点）和法向 $\mathbf n_j$，以及描述不确定性的协方差/统计量；
  • 原始激光点：拟合平面用到的那批离散点也留着（用于后续精化/回退）；
  • 贴在平面上的参考图像块（patch）：视觉复用时直接拿来比亮度。

激光那一路的点-面残差（Eq.18–19）直接用这个拟合平面：

$$\mathbf 0=(\mathbf n_j\boxplus\delta\mathbf n_j)^T\Big({}^G\mathbf T_I\,{}^I\mathbf T_L\big({}^L\mathbf p_j-\delta{}^L\mathbf p_j\big)-\big(\mathbf q_j-\delta\mathbf q_j\big)\Big)$$

其中 $(\mathbf n_j,\mathbf q_j)$ 就是体素内拟合平面的法向和中心——不用再去邻域里现找 5 个点拟合。

为什么「存平面」比「存点」更好

① 查询快：视觉来一个像素，直接读体素里的平面参数（中心 + 法向）就能算投影，不必在成千上万近邻点里挨个比距离；② 抗噪：平面是多点拟合出来的，单个点的噪声被平均掉了，比「记住每个原始点」稳；③ 直接给视觉法向：光度对齐时做仿射变形需要表面法向，平面先验直接提供，省掉 v1 的「同深度」野假设。

3. 回链「地图里存什么」的谱系

「地图里到底存什么」是本专案最长的一条线索。FAST-LIVO2 把体素地图升级成「存平面」，正好接上前面几季：

课 系统 地图里存什么
第二季 0033TSDF（KinectFusion 系）每个格存一个标量距离
第二季 0034Voxel Hashing体素块 + 哈希表
第四季 0084ikd-Tree（FAST-LIO2）存离散点，但可增量增删
本节 0100FAST-LIVO2 体素地图存拟合平面（中心 + 法向 + 协方差）+ 原始点 + patch

注意一条工程事实：FAST-LIVO2 的 LiDAR 模块不是沿用 FAST-LIO2 的 ikd-Tree，而是改自 VoxelMap（自适应体素地图：哈希表 + 每个入口一棵八叉树）。所以准确地说是——增益公式/ESIKF 框架从 FAST-LIO 继承，地图表示从 ikd-Tree 的「点云」升级成「自适应体素（存平面）」。这一点务必如实写，不要张冠李戴。

4. ESIKF 的序贯更新（本节灵魂）

「序贯（sequential）」到底指什么？一句话：在一帧之内，多个测量不是一次性打包进滤波器，而是一个一个地、按顺序去更新同一个状态；每更新完一个，就重新线性化一次。

原文用贝叶斯分解（Eq.5–7）表达这一点——先由激光测度得到 $p(\mathbf x|\mathbf y_l)$，再由它结合图像测度得到 $p(\mathbf x|\mathbf y_l,\mathbf y_c)$：

$$p(\mathbf x|\mathbf y_l,\mathbf y_c)\propto p(\mathbf y_c|\mathbf x)\,p(\mathbf y_l|\mathbf x)\,p(\mathbf x)$$

单步 ESIKF 更新（Eq.11）的形式，从 FAST-LIO 的误差态迭代卡尔曼继承（增益公式的 $(I-KH)P$ 形式、状态仅 19 维）：

$$\mathbf K=\big((\mathbf H^\kappa)^T\mathbf R^{-1}\mathbf H^\kappa+\hat{\mathbf P}^{-1}\big)^{-1}(\mathbf H^\kappa)^T\mathbf R^{-1}$$
$$\hat{\mathbf x}^{\kappa+1}=\hat{\mathbf x}^\kappa\boxplus\Big(-\mathbf K\mathbf z^\kappa-(\mathbf I-\mathbf K\mathbf H^\kappa)(\hat{\mathbf x}^\kappa\boxminus\hat{\mathbf x})\Big)$$

关键区别要讲清：

序贯更新（v2，本篇）

同一帧内：激光平面残差先更新状态 → 重新线性化 → 图像块光度残差再更新 → 可能还有平面测量再更新。每个测量单独进、单独重线性化。对应原文「improving the robustness of FAST-LIVO that uses asynchronous updates」。

批处理式更新（对照）

把这一帧所有测量攒在一起，拼成一个大雅可比、一次性解。优点是一次成型，缺点是某个坏测量会污染全体，且一次线性化后不再回头看当前估计。

★ 务必纠正的误传

「序贯更新」是 FAST-LIVO2 的贡献，不是 v1 的。FAST-LIVO（v1）是异步更新——激光帧、图像帧交错到达，各自触发一次更新（Eq.11 注明 $m_c=0$ 或 $m_l=0$）。v2 才做到「同一帧内、一个一个测量地序贯更新」。两者都叫 ESIKF，但更新节奏不同。

5. 视觉那一路的残差：光度误差怎么算

视觉侧同样是稀疏直接法（patch 级光度误差），而且深度直接由统一地图给（就是上一节那个体素平面中心 $\mathbf q_j$）。残差（Eq.21–22）把当前帧和参考帧的亮度拉到同一曝光尺度后做差：

$$\mathbf 0=\tau_k\mathbf I_k\!\Big(\pi\big({}^C\mathbf T_I({}^G\mathbf T_{I_k})^{-1}{}^G\mathbf p_i\big)+\Delta\mathbf u\Big)-\tau_r\mathbf I_r\!\Big(\pi\big({}^{C_r}\mathbf T_G\,{}^G\mathbf p_i\big)+\mathbf A_i^r\Delta\mathbf u\Big)$$

逐项说：

  • $\tau_k,\tau_r$：当前帧与参考帧的逆曝光时间（v2 新增，在线估计），把亮度缩放可比；
  • ${}^G\mathbf p_i$：地图里那个点（深度由地图给，不估）；
  • $\Delta\mathbf u$：patch 内像素的相对坐标（一个小窗口，如 8×8）；
  • $\mathbf A_i^r$：参考块到当前块的仿射变形矩阵，它用到平面法向 ${}^{I_r}\mathbf n$ 和平面点 ${}^{I_r}\mathbf p$——正是「存平面」给的红利，让斜平面上的块对齐更准；
  • $\mathbf I_k,\mathbf I_r$：当前帧 / 参考帧的亮度。

参考帧怎么选？原文用参考块评分（Eq.12）在若干候选块里挑 NCC（归一化互相关）最高、且含一定纹理的作参考帧。这样视觉对齐既有几何（地图深度）又有纹理（光度），分工清晰。

6. 怎么处理「某一传感器退化」：互补性

三传感器融合最大的卖点，就是互补。原文在实验里专门讨论了视觉与激光的互补性：当激光在几何退化处（比如只看到一面长墙，点云无颜色、约束不足）失效时，视觉的纹理仍能撑住；反之当视觉遇到极暗、极糊、弱纹理时，激光的精确深度仍能保底。

原文 Fig.10 直接展示了这种互补：在「亮屏墙 / 黑屏墙 / HIT 涂鸦墙」等激光退化场景，对比 FAST-LIVO2、FAST-LIVO、R3LIVE 三系统——激光几何退化时，靠视觉纹理仍能不漂、出清晰彩色图。

和 R3LIVE 的融合哲学对照

R3LIVE：LIO 与 VIO 是两条并行子系统，各自估计后再联合，VIO 用逐像素直接法。
FAST-LIVO2：同一份体素地图 + 同一个 ESIKF + 序贯更新，视觉用图像块级直接法，且复用统一地图的平面先验。两者都紧耦合，但「融合发生的位置」不同——R3LIVE 在子系统末端，FAST-LIVO2 在数据入口处就共享地图。

8. 局限（逐条，按原文 §XI）

① 长距离有漂移（无回环）

原文明言「作为里程计，FAST-LIVO2 长距离可能有漂移」——未含回环。未来工作要把回环 + 滑动窗口优化加回来。

② 法向精化仅限简单场景

法向精化只在结构简单、图像观测好时正收益；NTU-VIRAL 的 eee/nya 极暗模糊序列甚至负优化。

③ 图极暗时融图不增益

Outside Building、Large Room (dark) 等场景结构丰富但图极暗，纯激光 FAST-LIO2 反更好。

④ 需预标定外参与时间同步

§IV-A 假设外参、时间同步已知，没有在线标定这部分。

9. 本课落点

FAST-LIVO2 把 LIVO 做到这一季的技术顶点：同一份体素地图（存平面）+ 同一个 ESIKF + 序贯更新 + 在线曝光 + 按需光线投射。它相对 v1 的三级跳（两份地图→一份地图、异步→序贯、无曝光→有曝光）正是紧耦合 LIVO 这条线的集大成。

「ESIKF 序贯更新」是谁的贡献？

课后练习

  1. FAST-LIVO2 的体素里存的到底是什么？为什么说「存平面」比「存点」更快、更抗噪？
    展开查看答案

    每个体素存：拟合平面（中心 $\mathbf q_j$ + 法向 $\mathbf n_j$ + 协方差/统计量）+ 原始激光点 + 贴在表面上的参考图像块 patch。

    更快：视觉来一个像素，直接读体素里的平面参数就能算投影，不必在近邻点云里挨个比距离。更抗噪：平面是多点拟合出来的，单点噪声被平均掉，比「记住每个原始点」稳。另外平面直接给视觉法向，省掉「同深度」野假设。

  2. 用一句话 + 一个公式说明「序贯更新」与「批处理更新」的区别。
    展开查看答案

    序贯：同一帧内多个测量一个一个地更新同一个状态，每更新一次重新线性化（贝叶斯分解 $p(\mathbf x|\mathbf y_l,\mathbf y_c)\propto p(\mathbf y_c|\mathbf x)\,p(\mathbf y_l|\mathbf x)\,p(\mathbf x)$）。

    批处理：把这帧所有测量攒成一个大雅可比一次性解。区别在于「是否每来一个测量就回头重看当前估计」——序贯会，批处理不会。

  3. FAST-LIVO2 的视觉残差里，深度从哪里来？$\tau_k,\tau_r$ 是干什么的？
    展开查看答案

    深度来自统一体素地图里的点 ${}^G\mathbf p_i$（即平面中心），不是视觉自己估的——和 v1 一样复用激光地图。

    $\tau_k,\tau_r$ 是当前帧与参考帧的逆曝光时间（v2 新增、在线估计的状态维度）。它们把两帧亮度缩放到同一尺度，使光度误差在光照变化时仍可比。这是 v1 没有的模块。

  4. 为什么说「序贯更新是 FAST-LIVO2 的贡献，不是 v1 的」？请结合原文给出依据。
    展开查看答案

    原文贡献 1 表述为「improving the robustness of FAST-LIVO that uses asynchronous updates」——即序贯是为改善「用异步更新的 FAST-LIVO」而引入的，说明异步是 v1、序贯是 v2。

    v1 的 Eq.11 注明：收到激光只融 $r_l$（$m_c=0$）、收到图像只融 $r_c$（$m_l=0$），即激光/图像帧交错触发更新，是异步。两者都叫 ESIKF，但更新节奏不同。

  5. 把 FAST-LIVO2 与 R3LIVE 的融合哲学对照一下（回链第五季 R3LIVE）。
    展开查看答案

    R3LIVE：LIO 与 VIO 是两条并行子系统，各自估计后再联合，VIO 用逐像素直接法（贵、依赖光流初值）。

    FAST-LIVO2：同一份体素地图 + 同一个 ESIKF + 序贯更新，视觉用图像块级直接法，且复用统一地图的平面先验。融合发生的位置不同——R3LIVE 在子系统末端，FAST-LIVO2 在数据入口就共享地图。
