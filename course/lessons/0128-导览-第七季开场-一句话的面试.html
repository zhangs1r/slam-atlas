1. 本季要回答什么：一句六年前的判断

回到第一季。那时我们读 0011 课《深度学习视觉 SLAM》，作者把深度学习在 SLAM 里的角色分成四类，最后落下一句后来被反复引用的判断：

$$深度学习 \;\text{先吃掉}\; 「特征匹配」\;\text{与}\; 「场景检索 / 回环」$$

这句话在说什么：当年这句话只是一个预言式的判断——作者觉得，比起直接去估位姿、去建几何地图，深度学习最可能、也最先「攻陷」的，是 SLAM 流水线里那两个「认东西」的环节：前两帧之间哪些点是同一个点（匹配），以及现在看到的场景以前有没有来过（检索/回环）。

这一季（阶段 G，24 节课、31 篇论文）要做的，就是把这句话兑现成一张账单：它到底吃掉了没有？吃到什么程度？哪些地方其实吃不动？我们把它拆成四个战场，逐个给结论。下面这张图是整季的地图。

2. 四个战场地图：到底在谁的地盘上打架

为了让你读后面 23 节不迷路，先把四个战场各自「管 SLAM 流水线的哪一段」讲清楚。这里先给直觉，细节在对应课里展开。

战场 在流水线里管哪段 手工时代怎么做 学习式怎么替
① 匹配 前端（检测+描述）与中间端（匹配/数据关联） SIFT/ORB 描述子 + 最近邻 + 比值检验（0011/0004） GNN+最优传输、去检测器、轻量前端（0129–0133）
② 检索/回环 回环检测（识别「来过没有」） 词袋 BoW（ORB-SLAM 0043、DBoW2 0134） CNN/Transformer 描述子、端到端回环（0135–0140）

一个先说清楚的归类：本季头几节（0129–0133）在「匹配」战场里。但这里要提前纠正一个容易混的点——SuperGlue / LoFTR / LightGlue 是「中间端」（吃前端的产物、吐匹配），而 SiLK 是「前端」（检测器+描述子）；RAFT 更不是特征匹配，它是稠密光流。这几篇的精确归类，我们会在各自课里显式讲清，别被「特征匹配子块」这个大筐带偏。

4. 本季方法论暗线：复杂与极简之争

除了四个战场，这一季还有一条贯穿始终的方法论暗线，读的时候一定要带着它看：「复杂度往上加」和「复杂度往下减」两条路线在打架。

往上加复杂度（0129–0131）

SuperGlue 把匹配做成一个带图神经网络、最优传输、注意力的大型可学习模块；LoFTR 进一步去掉检测器、上 Transformer；LightGlue 在它基础上继续精细化。它们的共同直觉是：「匹配这件事太难，得用更聪明的模型才搞得定」。

往下减复杂度（0132 / 0133 / 0146）

RAFT 用一套「4D 相关体 + 循环迭代」的统一机制做稠密对应，SiLK 把前端退回「极简两卷积 + 余弦相似度」，DPVO 用图像块跟踪替代稠密光流。它们的共同直觉是：「与其堆模块，不如找一个简单机制反复迭代」。

6. 读完后你应该能回答

这是本季的「自测清单」。如果读完 24 节后你能用自己的话答出下面六问，这一季就算读透了（具体数字与结论分散在各节，不要求现在就会）：

  1. 第一季 0011 那句话兑现了几成？ 匹配、检索、端到端位姿、基础模型这四个战场，各自被「吃掉」到什么程度？
  2. SuperGlue 凭什么比「描述子相似度 + 比值检验」强？ 它把匹配这个 NP 难的指派问题，换成了什么可学习的机制？
  3. 「不用检测器」是不是总比「用检测器」好？ LoFTR 在什么场景下碾压 SuperPoint+SuperGlue，又在什么场景下吃亏？
  4. 极简路线赢在哪？ SiLK 只用余弦相似度 + 互近邻，为什么能和 heavy 的 SuperGlue 掰手腕？RAFT 的「简单机制反复迭代」又妙在哪？
  5. 学习式回环有没有真的压住假阳性？ 回到第一季 0014 的铁律：一次假阳性就能毁掉整张地图，本季 0140 要正面回答这个问题。
  6. 基础模型到底是「吃掉几何」还是「给几何当外包」？ 0147–0150 那条线，边界到底划在哪？

课后练习

  1. 用一句话向没读过论文的人解释：为什么第一季 0011 说「深度学习先吃掉匹配与检索」，而不是「先吃掉估位姿」？
    展开查看答案

    因为「匹配」和「检索」本质上是「认东西」——判断两处观测是不是同一个点、这个场景以前来没来过。这类「识别/比对」任务恰好是深度学习最擅长、也最早成熟的；而「估位姿」「建几何」是严格的几何推理，有物理约束和全局一致性要求，深度学习很难直接取代，只能从「给几何当输入/零件」的角度切入。所以当年作者的判断是：先动的会是流水线两端的「认东西」环节。

  2. 本季头几节（0129–0133）同属「特征匹配子块」，但 SiLK 和 RAFT 的归类与 SuperGlue/LoFTR/LightGlue 并不相同。请说出至少两处区别。
    展开查看答案

    ① SiLK 是前端（检测器+描述子），它替换的是 SuperPoint 那类「先找点再描述」的模块，匹配只靠余弦相似度+互近邻（MNN），不含 GNN/最优传输/Transformer；而 SuperGlue/LoFTR/LightGlue 是中间端（middle-end），吃前端的产物、吐匹配。② RAFT 是稠密光流（逐像素运动场），不是稀疏特征匹配；它提供的是「稠密对应」，和 SuperGlue 那条稀疏匹配线是不同范式。所以把它们都塞进「特征匹配」一个筐里是粗糙的归类，后文会逐一纠正。

  3. 本季的方法论暗线是「复杂 vs 极简」。请各举一篇「往上加复杂度」和「往下减复杂度」的代表作，并说明它们各自的赌注。
    展开查看答案

    往上加：SuperGlue（0129）——赌注是「匹配太难，必须用图神经网络+最优传输这种重模块才搞定」。 往下减：SiLK（0133）或 RAFT（0132）——赌注是「与其堆模块，不如找一个极简机制（余弦相似度 / 4D 相关体+循环迭代）反复迭代就能扛住难度」。两条线都没消失，胜负取决于场景对「精度」还是「速度/轻量」更敏感。

  4. 看第 3 节的流水线图：学习式方法有没有替换掉「后端 BA」这根骨架？它实际替换的是什么？
    展开查看答案

    没有替换后端 BA 的骨架本身。实际被替换的是喂给 BA 的匹配结果（前端+中间端那段，0129–0133）和回环的识别模块（0134–0140）。换句话说，几何优化的「发动机」还在，但「发动机吃进去的燃料（对应点）」和「判断要不要回环的哨兵」换成了可学习的模块——这正是「先吃掉匹配与检索」的精确含义。
