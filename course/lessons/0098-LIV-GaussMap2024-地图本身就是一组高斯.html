LIV-GaussMap（2024）：地图本身就是一组高斯

不再存点云，而是一团能直接被光穿过的椭球——建图和渲染合流了 🟢

本节目标

读完你应该能：说清为什么把融合结果存成高斯比点云 / 体素更适合渲染；讲明高斯由激光点初始化、用球谐表达视角相关颜色；并指出它相对 3DGS 的根本差别与「建图即渲染」的意义。

和前面课程怎么接

它直接承自第一季 0015 3D 高斯泼溅与第二季 0036–0039 NeRF / Plenoxels（球谐），以及第三季 0071 神经隐式建图。本质是把 3DGS 的「SfM 初始化」换成「激光几何初始化」。LIO 一侧仍属第四季 0084 FAST-LIO2 的直接配准谱系（自适应体素引 VoxelMap [12]）。

1. 它要解决什么

LIV-GaussMap 想解决一个上两篇都没碰的问题：「融合出来的地图，能不能直接拿来渲染新视角？」

R³LIVE / R³LIVE++ 存的是点云——点云「有洞、对非朗伯表面（玻璃、金属）会模糊」，而且本质不是为渲染设计的。新视角合成（NeRF / 3DGS）能渲染得很漂亮，却不关心地图结构，外推差、低纹理场景靠 COLMAP 容易失败。本文的回答是：用多模态融合，让激光给准结构、视觉给多视角外观，建出「无洞、可视角相关渲染」的高斯地图。

原文的出发点原话大意是：现有 LiDAR-Visual 系统多在朗伯假设下用「带图像块的点」或「着色像素」表示，点云有洞、对非朗伯模糊；而 NeRF / 3DGS 重 PSNR 却忽视地图结构。本文因此把融合结果直接存成可微的 3D 高斯（椭球表面高斯 + 球谐系数）——一句话，「建图与渲染合流」的辐射场地图。

2. ★ 为什么存高斯比点云 / 体素更适合渲染

先回答「为什么是高斯，不是点云或体素」。关键在「可微渲染」：高斯是一个连续、平滑、有体积的概率团，可以被「泼」到图像上。

点云：有洞、非朗伯模糊

离散点之间有缝隙，一个像素可能「没点可投」；玻璃 / 金属这种反射随视角变的表面，贴一个固定颜色会糊掉。

体素：存的是标量

体素（如 TSDF，第二季 0034/0035）存的是「到表面的距离」之类标量，要渲染还得额外建网格、再贴图，步骤多。

高斯：自带一切渲染所需

每个椭球自带位置 + 朝向 + 大小 + 颜色 + 不透明度，光线穿过它们按深度与透明度叠出像素色——地图本身就是渲染图元。

那个「光线穿过高斯叠出颜色」的渲染公式（原文式 12，可微光栅化的 alpha 混合）：

$$ \hat I_n(\mathbf{q})=\sum_{i=1}^{M}\Big[c_i\,\sigma_i\,G_i^{2D}(\mathbf{q})\prod_{j=1}^{i-1}\big(1-\sigma_j G_j^{2D}(\mathbf{q})\big)\Big] $$

$c_i$ 是颜色，$\sigma_i$ 是不透明度，$G_i^{2D}$ 是该高斯投影到图像的 2D 高斯。从近到远把每个高斯「按透明度一层层叠」上去，就得到像素 $\mathbf{q}$ 的颜色。这正说明：高斯生来就是为「被光线穿过」设计的。

3. ★ 高斯是怎么长出来的（由激光点初始化）

这一步最容易被猜错，必须按原文来：高斯是由激光点初始化出来的，不是由视觉深度出来的。

原文的三类操作里，A 是「激光初始化」（式 1–5）：先用 LiDAR-惯性系统（自适应体素，VoxelMap 式）得到位姿和表面，再把每个体素里的激光点拟合成一个平面，由平面的协方差得到一个扁椭球，沿法向压扁成表面高斯。具体：

$$ \bar{\mathbf{p}}=\frac1N\sum \mathbf{p}_i,\qquad \Sigma_{\mathbf{n},\bar{\mathbf{p}}}=\frac1N\sum(\mathbf{p}_i-\bar{\mathbf{p}})(\mathbf{p}_i-\bar{\mathbf{p}})^T $$
$$ G_i^{3D}({}^w\mathbf{p})=e^{-\frac12({}^w\mathbf{p}-{}^w\mathbf{p}_i)^T\Sigma_{\mathbf{w}\mathbf{p}_i}^{-1}({}^w\mathbf{p}-{}^w\mathbf{p}_i)} $$

前半是「这个体素里所有激光点的均值与协方差」；后半就是那个 3D 高斯——协方差 Σ 决定椭球朝哪、有多大。还有一个细分判据 $\eta=\lambda_{\min}/\sqrt{\lambda_{\min}^2+\lambda_{\text{mid}}^2+\lambda_{\max}^2}$，平面越厚越要细分。

每个高斯存什么参数？原文列出：位置 ${}^w\mathbf{p}_i$、协方差 / 尺度 $\Sigma_{\mathbf{w}\mathbf{p}_i}$、颜色（以球谐系数表示）、不透明度 $\sigma_i$。注意：颜色不是直接存 RGB，而是存球谐系数——这就引出下一节。

4. ★ 视角相关颜色：球谐（SH）

这是本篇和前两篇最不同的地方，也是它真正「可渲染」的关键。颜色不再是一个固定 RGB，而是一个随观察方向变化的函数——用球谐（Spherical Harmonics, SH）表示。

球谐是第二季 0039 Plenoxels 就用过的工具（把「颜色依赖方向」展开成一组基函数），也是第一季 0015 3D 高斯泼溅表达视角相关颜色的同一招。本文用 2 阶球谐，每个高斯 27 个系数：

$$ c(\theta,\phi)=\sum_{\ell,m}k_\ell^m\sqrt{\frac{2\ell+1}{4\pi}\frac{(\ell-m)!}{(\ell+m)!}}\,P_\ell^m(\cos\theta)\,e^{im\phi} $$

$(\theta,\phi)$ 是「从高斯看向相机的方向」的球坐标。换句话说：同一个表面，从正面看和斜着看，颜色可以不一样——这正是 R³LIVE++ 做不到、而这里做到了的事。回看 0097 课的纠正：视角相关反射是「球谐」负责的，现在你看到它具体落在这篇。

5. ★ 它怎么和状态估计耦合

这里要诚实说清：LIV-GaussMap 的耦合，比 R³LIVE 那一支「同一状态 x」要松。

原文本意（务必分清）

位姿来自一个独立的激光-惯性里程计（基于自适应体素，VoxelMap 式，文中引 [12]），它先把位姿和表面估好、用来初始化高斯；之后视觉只参与精修高斯（用图像光度梯度优化 SH 系数与结构），不参与位姿估计，也不与高斯联合优化。所以：几何 / 位姿是一条独立的 LIO 流水线给的，高斯地图是被「喂」了几何初稿后再单独优化出来的。

对比一下三篇的耦合松紧：

篇 视觉那一支 位姿谁来估 耦合松紧
R³LIVE / ++ VIO 进同一状态 x LIO + VIO 共估 紧（同一 x）
LIV-GaussMap 只精修高斯（SH + 结构） 独立 LIO 给，不联合优 较松

所以本篇的「融合」重点不在于「多传感器共用一个状态」，而在于「激光给一份免费又准确的几何初稿，视觉拿它当起点去长一张可渲染地图」。这一点下一节还要展开。

6. ★ 相对 3DGS 的差别（非常重要）

很多人会把 LIV-GaussMap 当成「又一篇 3D-GS」。错。它们最大的差别在几何从哪来。

3D-GS（第一季 0015）

几何初稿来自 SfM 的稀疏点云——点稀疏、尺度不一定准、低纹理场景容易失败，之后全靠图像光度梯度慢慢把高斯「长」出来。

LIV-GaussMap（本篇）

几何初稿来自密集的激光点——尺度真实、表面直接由激光给出，再用图像光度梯度精修 SH 与结构。

这个差别带来三个具体好处（原文实验支持）：① 初始化更准（不用从稀疏 SfM 点慢慢长）；② 尺度真实（激光给的是米，不是 SfM 的未知尺度）；③ 建图更快 / 更稳，尤其在外推（看训练时没见过的视角）时明显更好。

7. 实验数字：渲染质量与速度

  • 平台：Intel i9-12900K 3.50 GHz + 单张 RTX 4090（注意：需要 GPU，不是纯 CPU）。
  • 数据集：公开 FusionPortable（Ouster OS1-128）、FAST-LIVO（Livox Avia）；自采 Device I（RealSense L515 固态）、Device II（Livox Avia）。
  • 新视角合成（表 II）：本文 PSNR 插值 32.787 / SSIM 0.926 / LPIPS 0.190；外推 PSNR 19.220 / SSIM 0.803 / LPIPS 0.331。
  • 对比 3D-GS：插值 31.899 / 0.913 / 0.240，外推 15.111 / 0.647 / 0.502——外推显著优于 3D-GS。
  • 速度：训练 14m25s，渲染 43 FPS（3D-GS 为 131 FPS，本文因密集激光点更慢，但仍实时渲染）。
  • 消融：Case IV（激光初始化 + SH + 位置 / 姿态精修）全场景优于 3D-GS；LiDAR 初始化显著改善 CD / EMD / F-score 等结构指标。

8. 收尾：建图与渲染合流

把三支放在一起看，这条线就通了：

第一季 0015（3D 高斯泼溅）
↓ 第二季 0036–0039（NeRF / Instant-NGP / Plenoxels 球谐）
↓ 第三季 0071（神经隐式建图）
↓ 本篇 LIV-GaussMap：第一次让「融合出来的地图」直接可渲染

它让「建图」与「渲染」合流了。 前一篇还在「给点云存物理量颜色」，本篇直接把融合结果存成「能被光线穿过的高斯」——建图的同时就把渲染要的东西备好了。这正是本项目最长的一条线索（地图里到底存什么：TSDF → 体素哈希 → 点云 → 高斯）的又一站，也是「融合结果可渲染」这一支的收口。

原文承认的局限

① 训练 / 渲染比 3D-GS 慢（密集激光点）；② 光度优化会轻微牺牲结构精度（pose 精修使 F-score 略降）；③ 依赖良好 LIO 位姿（位姿不与高斯联合优）；④ 玻璃 / 过 / 欠扫描仍需结构精修缓解；⑤ 需要 RTX 4090，非纯 CPU 实时。

三篇一句话定位

R³LIVE：激光建几何 + 相机贴色（点云）；R³LIVE++：把色升级成与曝光无关的辐射量（点云）；LIV-GaussMap：把结果存成可渲染椭球高斯（辐射场）。越来越「渲染友好」。

    SH 负责视角相关的颜色：同一个表面从不同方向看，颜色可以不同。它用 2 阶、每高斯 27 个系数表示。这正是第一季 0015 3D 高斯泼溅与第二季 0039 Plenoxels 用过的同一工具——本文把「视角相关颜色」接到了这条线上。

  4. LIV-GaussMap 的位姿是怎么来的？它和 R³LIVE 的「同一状态 x」有何不同？
    展开查看答案

    位姿来自一个独立的激光-惯性里程计（自适应体素，VoxelMap 式），不与高斯联合优化；视觉只精修高斯（SH + 结构），不参与位姿。

    对比 R³LIVE：那一支是 LIO 与 VIO 共用同一个状态 x（紧耦合）；本篇的耦合更松——几何初稿由独立 LIO 给，高斯地图单独优化。它的「融合」重点是「激光给准确几何初稿 + 视觉长可渲染地图」。

  5. 相对 3D-GS，LIV-GaussMap 在「几何从哪来」上有何差别？带来什么好处？
    展开查看答案

    3D-GS 的几何初稿来自 SfM 稀疏点（稀、尺度不定、低纹理易失败），靠光度梯度慢慢长；本篇来自密集激光点（尺度真实、表面直接给）。

    好处：初始化更准、尺度真实、建图更快更稳，尤其外推（新视角）PSNR 19.2 vs 3D-GS 15.1，明显更优——因为激光给了免费又准确的几何初稿。
