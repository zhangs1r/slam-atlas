和前面课程怎么接

本块全部建立在第三季 0043–0045（ORB-SLAM）之上——八篇里有七篇是「在 ORB-SLAM 上打一层动态剔除补丁」。0005（SW-NDT）是全项目第一次碰动态的激光侧做法，0158 会专门对照。0147 讲的 SAM / DINOv2 就是动态剔除现成的「语义零件」，0121（WildGS-SLAM）用特征不确定度当动态信号且不靠深度语义。多机块的 0140「回环假阳性铁律」与「判错会怎样」是同一类「错了就崩」的张力。

1. 这一块我们到底拆掉了什么

导览课（0152）说过：前七季默认了三件事，本季逐个戳破。动态环境块专门戳第一件——「环境是静止的」。前面所有的 SLAM 都把地图点当成永远不动的钉子，BA 里每个点只贡献一个「它该出现在哪」的约束。可真实世界里有人走来、车开过，这些「钉子」其实在动。一旦把动的点当静的塞进 BA，整条轨迹就会被拽歪。

所以动态 SLAM 的核心问题只有一句话：怎么判断「哪些点此刻在动」，判错了怎么办？ 八篇论文（0153–0156 覆盖）给出的答案可以归成两路「怎么判」和四种「判出来怎么处理」。

互动判断

下面这句话对不对：「只要把会动的东西全删掉，SLAM 就安全了，不用管别的。」

2. 两条技术路线：几何 vs 语义

「怎么判断在动」在工程上只有两条路线，而且常常组合使用：

几何路线

靠「运动残差」：同一地图点在新老帧里该长得一样。用重投影误差、对极约束、多视角深度一致性、场景流来量「它偏了多少」。偏太多就判动。不认识物体，只认运动。代表：DSLAM（2022，点相关图）、CRF 长时一致（2022）、Dynam-SLAM（2023）。

语义路线

靠「类别先验」：分割网络先说「这是人 / 车，是可动类」，直接把整类当潜在动态。它认识物体，但不一定知道它此刻动没动——停着的车也会被划进动态候选。代表：DynaSLAM（2018）、DS-SLAM（2018）、室外动态（2023）、WF-SLAM（2022）。

一个关键观察：纯几何法不依赖训练数据 / GPU（DSLAM 30.65 ms、CRF 16–18 fps 都接近 ORB-SLAM2 的实时性），但靠「动静统计差异」赌场景里静态点占多数；语义法先拿到「可动类」先验更省心，却要为分割网络付出 25–195 ms 不等的算力，而且永远背着一个隐患——它分不清「可动」和「此刻在动」。

3. 四种处理哲学的代价账

「判出来是动态的」之后怎么处理？八篇可以收进四种哲学。下面这张账本把每家按这三笔账摊开：实时性（每帧多花多少 ms）、静态场景代价（安静时会不会反而变差）、是否输出动态轨迹（除了定位还给你什么）。

方法（年）路线哲学实时性代价静态场景代价输出轨迹
DynaSLAM（2018）几何＋语义删＋inpaint非实时（CNN 195＋几何 334＋inpaint 208 ms）略亏（删了可动类静态特征）否
DS-SLAM（2018）语义＋几何删~16.8 fps（语义线程并行）略亏（站着的「人」被删）否
DSLAM（2022）纯几何删（连通分量）近实时 30.65 ms，无需 GPU几乎不亏否
DynaSLAM II（2021）语义实例留＋追踪10–12 fps（唯一实时 MOT）略降（seq0001 2.31＞1.95）是（6DoF＋box）
室外动态（2023）语义＋场景流删（区分动静）非实时（分割太慢）少动态时提升有限否
CRF（2022）纯几何删（长时一致）16–18 fps（CPU）几乎不亏否
WF-SLAM（2022）语义＋几何降权非实时 310 ms增益薄（sitting 仅 5.43%）否
Dynam-SLAM（2023）几何＋IMU造虚拟路标滑动窗口 10 帧近实时模糊序列略亏否（转虚拟约束）

账本读下来有三条规律：① 纯几何法在静态场景几乎不亏本（DSLAM、CRF 不删「可动类先验」），语义删除派在静止可动物体场景会略降；② 实时性普遍是痛点，只有纯几何两篇接近 ORB-SLAM2 的实时；③ 只有 DynaSLAM II 输出动态物体轨迹，其余大多只过滤 / 降权，定位之外的信息为零。

3.1 静态场景下的代价（空房间也要付的钱）

这张图回答 §九.1 点名的「静态场景下的代价」：一个空无一人的房间，本来没有任何东西在动，但防动态的流水线仍在跑——分割网络照样要把「人 / 车」整类标一遍，哪怕房间里根本没有。这笔「安静时也要付的算力 + 误删风险」就是动态方法的隐性账单。

3.2 第四种哲学：把动态变成「虚拟路标」

前面三种哲学（删、留＋追踪、降权）都在「减少动态点对 BA 的坏影响」。Dynam-SLAM（2023）走了第四条路：当动态点太多、静态点不够时，反而拿动态点造「虚拟路标」补约束——假设物体在帧间近似匀速，用当前运动预测它下一帧该在的位置，当成一条「静态约束」塞回 BA。这把「坏数据」反转成「补丁」。

4. 判错了会怎样：两种代价的验收

动态检测只有两种判错，而且后果完全不对称。验收一个动态 SLAM 好不好，就看它在这两头压得怎么样：

代价一：误删静止可动物体

把「停着的车 / 站着的人」当成动态删掉 → 损失本可定位的静态特征 → 精度略降。这是「保守删除的亏本」，通常不致命，但会在静态场景拖累你。DynaSLAM II 在 KITTI seq0001 上 Ours 2.31 ＞ ORB-SLAM2 1.95，就是「给动态物体太多自由度」的实锤。

代价二：漏判真动物体

把「真在走的人」当成静态塞进 BA → 污染 BA → 整条轨迹被拽歪，这是「漏检的崩盘」，比误删严重得多。所有方法都靠更严的阈值（如 Dynam 的 χ² 99% 分位 11.34）和长时统计来压制它。

用加权 BA（WF-SLAM 的 Eq.6）可以一句说清「降权」哲学如何处理这两头：不是删点，而是让可靠点贡献大、不可靠点贡献小。

$$\{R^*,t^*,w_i^*\} = \arg\min \frac{1}{2} w_i \sum_i \lVert x_i - \pi(R X_i + t) \rVert^2$$

这句话在说什么：这个式子在算「最优的相机旋转 R、平移 t，以及每个特征点的权重 w_i」。它和 ORB-SLAM2 唯一的不同，是给每个重投影误差乘了个权重 w_i——权重大的点（大概率是静态）说了算，权重小的点（可能是动态）说了不算。所以它不硬删点而是软降权：漏判了真动物体时，这颗点的权重会被慢慢压低，不至于一下子污染整条 BA；误删静止可动物体时，它本就被当成「语义动态」给了低权重而不是清零，留了余地。这就是「降权」比「硬删」更稳的地方。

互动判断

某动态 SLAM 在「停着的车」场景精度略低于原版 ORB-SLAM2，在高动态行人场景精度远超 ORB-SLAM2。这算失败吗？

5. 横向链接与下一步

动态块不是孤岛，它和另外三块互相咬合：

  • 动态 ↔ 语义：判断「动」最省力的办法就是用语义分割把「人」整类剔掉——这正是 0153 与 0159（SemanticFusion）交叉的地方。0158 会专门讲「语义通道怎么被动态检测借用」。
  • 动态 ↔ 多机：多机场景里，别的机器人本身就是「动态物体」。0173 附近的 D²SLAM 专门处理「近场另一个机器人」的精确相对状态——动态检测的多机版。
  • 动态 ↔ 回环假阳性：第七季 0140 的「回环假阳性铁律」与这里的「判错会怎样」是同一类张力——一个错边就能毁掉整张图，所以都靠更严的阈值 / 统计一致性来压。
  • 动态 ↔ 事件相机：事件相机最强的场景恰恰是高速运动（不产生运动模糊），与动态块天然互补，175–178 会展开。

下一节（0158）是动态块的延伸对照：一条往激光侧看（回链 0005 的 SW-NDT，全项目第一次碰动态），一条往语义侧看（借 SemanticFusion 2017 的语义通道，理解「可动类先验」到底从哪来）。

课后练习

  1. 把下面八篇按「是否需要语义分割网络」分成两组，并各举一个代表数字说明其代价：DynaSLAM、DS-SLAM、DSLAM、DynaSLAM II、室外动态、CRF、WF-SLAM、Dynam-SLAM。
    展开查看答案
    需要语义分割：DynaSLAM（CNN 195 ms，静态略亏）、DS-SLAM（只取 person）、DynaSLAM II（实例分割，seq0001 2.31＞1.95）、室外动态（SegNet，非实时）、WF-SLAM（Mask R-CNN，310 ms）。不需要语义分割（纯几何）：DSLAM（30.65 ms，无 GPU）、CRF（16–18 fps CPU）、Dynam-SLAM（靠场景流＋IMU，需 stereo＋IMU 但无分割）。纯几何组的共同卖点是「静态场景几乎不亏本且更实时」。
  2. 为什么 DynaSLAM II 在 KITTI seq0001 上比原版 ORB-SLAM2 还差（2.31 vs 1.95），却被评价为「范式跃迁」？
    展开查看答案
    因为它把动态物体从「删」改成「留＋追踪」，给每个可动类物体加了位姿和速度自由度。当物体实际静止时这些自由度近似零、无害；但当物体真在动时，这些运动线索反过来帮相机定位。seq0001 多停驶车，给了额外自由度反而略亏；这是「为动场景付费、静态场景小亏」的取舍，所以仍算从「删」到「留」的范式跃迁。
  3. 「造虚拟路标」只在什么条件下才有意义？如果场景里静态点本来就够多，Dynam-SLAM 还用得着它吗？
    展开查看答案
    只在「动态点太多、静态点不够，BA 约束不足」时才需要——用动态点的帧间匀速假设造出额外约束补位。若静态点本来就充足，虚拟路标没有增量价值，常规只靠静态点做 BA 即可。这也解释了 Dynam-SLAM 在静态 EuRoC 上「关掉动态特征检测（w/o DFT）几乎一样准」的现象。
  4. 一个验收指标：若要证明某动态 SLAM「没漏检」，你会优先看哪种测试序列的结果？为什么不直接看静态序列？
    展开查看答案
    优先看高动态占比序列（如 TUM fr3/walking_xyz、KITTI 1003-0047 这类多行人多车）的 ATE——若它显著优于 ORB-SLAM2，说明漏检被压住了。静态序列只能验证「误删的亏本」小不小，验证不了最致命的「漏检」，所以不能直接用静态序列当验收。
