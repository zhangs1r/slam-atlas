YOLO（2016）：一步到位的检测

把「先提一堆候选框、再一个个判」整条流水线扔掉，只留一个网络——这一步为什么能快几十倍？🚗 这一课讲清那个 7×7 的网格，也讲清 SLAM 圈里出现频率最高的这个检测零件，它的毛病正好被 SLAM 论文反复引用。

本节目标

读完你应该能：① 说清两阶段与单阶段检测路线在流水线上的差别，以及各自为什么慢 / 为什么难训；② 讲出 YOLO 的网格规则——「哪个格子负责哪个物体」；③ 复述 45 FPS / 63.4 mAP 与 Fast YOLO 155 FPS；④ 指出 YOLO 自述的三大缺陷，并说明 SLAM 论文为什么抱怨它的框；⑤ 分清45 FPS 的 63.4 mAP 与 VOC2007 上 person 单类的 59.2 AP 这两个数不能直接比。

和前面课程怎么接

★ 上一课 0190 FCN 讲「涂色」，本课讲「画框」——YOLO 只借用了 FCN 的一个前置认知：一次卷积就能处理整张图。★ 第八季 0153–0159 动态环境块是本课最重要的落地点：那一块里几乎每个方法都在用 YOLO 当「动态物体先验框」，2016_YOLO 是 SLAM 圈出现频率最高的检测零件。★ 本课末尾会点一句：你以后看到的 YOLOv3 / v5 / v8 检测器，训练时用的损失属于一九三课 Focal Loss 那一族，但 SLAM 论文只引 YOLO、不引它的损失。★ 概念上，本课就地补齐 IoU、候选框、mAP、anchor 四个词——缺一个就读不懂一九二与一九三。

1. 先补四个概念：IoU、候选框、anchor、mAP

这四篇检测/分割论文里，有四个词被反复使用却几乎从不解释。它们不是 YOLO 发明的，但 YOLO 全篇都在用。我们先花五分钟把它们补上——不补这四个，后面的公式和数字都会变成噪音。

IoU：两个框有多重合

交集面积 ÷ 并集面积，取值 0 到 1。两个框完全重合是 1，完全不沾边是 0。它是「框画得准不准」的通用尺子：YOLO 的置信度定义要用它，Mask R-CNN 判正负样本要用它，Focal Loss 分配 anchor 也要用它。生活类比：两张便利贴贴在同一只猫上，重叠的部分越大，说明两张贴得越一致。

候选框 proposal：可能是物体的区域

先不管它是什么，只先圈出「这里大概有东西」的一堆框。R-CNN 那一代用 Selective Search 生成约 2000 个；后来 Faster R-CNN 改用 RPN 学出来 1 到 2 千个。两阶段检测的全部精髓就是「用候选框当第一道闸门」。

anchor：预先设好的参考框

在特征图的每个位置上，预先摆好几个不同大小、不同长宽比的「空框」，让网络去判断「这个框里有没有东西、要往哪儿挪」。这就是「anchor（锚框）」。Focal Loss 那篇里每张图有 10 万个 anchor 位置，而两阶段的候选只有 1 到 2 千——这个数量差就是一九三课全部问题的根源。

mAP：检测精度的总分

先把每个类画成一条「精确率-召回率」曲线，曲线下的面积就是 AP；把所有类的 AP 平均起来就是 mAP。关键是 AP 还要在多个 IoU 阈值下平均——所以有 AP50（IoU 判据 0.5，松）和 AP75（0.75，严）之分。看到 mAP 先问「IoU 阈值是多少」，这是第九季 0180 那条纪律在检测这边的版本。

再补一个「不用解释但必须记住」的事实：YOLO 把检测重新定义为回归问题——直接从图像像素回归出空间上分离的框和对应的类概率。原文摘要的第一句就是这个意思。它不是「改进了一个分类器」，而是换了一个问题定义。

2. 两阶段 vs 一步到位：扔掉整条流水线

先看 YOLO 之前的人怎么做。当时的检测界主流是「改造分类器去做检测」：拿一个分类器，在图上各种位置、各种尺度上反复跑。具体两条路：

  • DPM 用滑窗：在整图上按均匀间隔的位置跑分类器。慢，而且每个尺度都要重跑一遍。
  • R-CNN 用候选框：原文对这条流水线的拆解非常具体，值得原样记住——Selective Search 生成候选框 → 卷积网络提特征 → SVM 打分 → 线性模型调框 → NMS 去重。每一段都得单独调参，整个系统跑一张图要 40 秒以上。

这条流水线的毛病不只是慢，还有两个更本质的：

  1. Pipeline 太长、不能联合优化。你在最后发现框偏了，没办法把误差一路传回去改前面的特征。每一段都是各管各的。
  2. 看不到上下文。R-CNN 系方法只看一个个小区域，原文说得很直白：Fast R-CNN mistakes background patches in an image for objects because it can't see the larger context——只看一小块，就容易把背景里一块像东西的纹理误当物体。

YOLO 的解法极其粗暴也好懂：把整条流水线扔掉，只留一个网络。输入一张图，跑一次卷积网络，直接吐出所有框和类别。只有一步，所以可以端到端按检测性能优化。原文的原话是整条流程「是一个单一网络」，可以直接 end-to-end 优化。

3. ★ 网格：每个格子只负责中心落在它里面的物体

扔掉流水线之后，一个必须回答的问题冒出来了：没有候选框了，那「谁去预测哪个物体」这件事，由谁决定？

YOLO 的答案是这一课的核心，原文只有一句话，但它是整个方法的地基：

原文的关键一句

If the center of an object falls into a grid cell, that grid cell is responsible for detecting that object.

人话翻译：把图切成 S×S 的格子。一个物体的中心落在哪个格子里，那个格子就负责检测这个物体。注意依据的是中心，不是「面积重叠最多」，也不是「谁挨得近」——就是中心。

具体到 VOC 数据集上，原文用的是 S = 7、B = 2、C = 20：图切成 7×7 共 49 格；每格预测 2 个框；每格还预测 20 个条件类概率。每个框输出 5 个数：

$$\text{每个框} = \big(x,\; y,\; w,\; h,\; \text{confidence}\big)$$

这句话在说什么：$(x,y)$ 是框中心相对该格边界的偏移（归一化到 0 到 1 之间）；$(w,h)$ 是框的宽高相对整张图归一化（也落在 0 到 1 之间）；confidence（置信度）定义为一个乘积：

$$C = \Pr(\text{Object})\times \mathrm{IOU}_{\text{pred}}^{\text{truth}}$$

这句话在说什么：置信度 =「这里真的有东西吗」乘以「我框得准吗」。格子里没物体时它应该是 0；有物体时，希望它正好等于预测框与真值框的 IoU。

它为什么这么算：用一个数同时表达「有没有」和「框得准不准」这两件事。如果只写「有没有」，那框画歪了也拿满分；如果只写 IoU，那空格子也可能因为乱猜出一个恰好重合的框而得高分。乘起来，两个条件必须同时满足。

数字账：每格输出 $B\cdot 5 + C = 2\times 5 + 20 = 30$ 个数，整个网络一次前向吐出的是 7×7×30 的张量。一算就知道：每图共 98 个框（7×7×2），而两阶段路线要处理约 2000 个候选框——少了二十倍。

还有一个细节很关键：每个格子只预测一组类概率，与 B 无关。也就是说，同一格里两个框共享同一套 20 个类概率。原文的网格设计还有一个副产品——它天然抑制重复检测：因为格子之间是分工的，不太会出现「同一个物体被十几个框同时报出来」，所以 NMS 在这里只是锦上添花（原文说 NMS 只 adds 2-3% in mAP），不像 R-CNN / DPM 那样是命脉。

谁做「负责」的那个框？原文的规则是：每格里当前 IoU 最高的那个预测器负责。这促成了预测器之间的专门化——各自会慢慢擅长不同的尺寸、长宽比和类别，从而把召回率提上去。

4. 损失函数：原文式 (3) 已损坏，本课用重建版

YOLO 的损失是把好几笔账分开计、分别加权。这是本课最需要小心的地方，所以先把一句提醒放在最前面。

⚠️ 必须先说明：原文式 (3) 在语料库里已经损坏

我们拿到的 md 版本里，第 2.2 节的这段损失公式被 OCR 严重破坏：求和的上下限被写成了 i=0 to ∞、出现了 B² 与 B³、权重里冒出一个原文并不存在的 λ_such，指示函数也被替换成了毫无意义的符号。本文档不得直接引用，照抄就是传播错误。

下面这一版是按正文的文字描述重建的——权重 λ_coord = 5、λ_noobj = 0.5、宽高开根号、两个指示函数，这些都能在正文文字里逐一核对到。请以一个「重建版」的心态读它，并记住这件事本身：这就是为什么本课程坚持所有数字都回原文核对。

$$ \begin{aligned} L=\;& \lambda_{\mathrm{coord}}\sum_{i=0}^{S^2}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\mathrm{obj}}\Big[(x_i-\hat{x}_i)^2+(y_i-\hat{y}_i)^2\Big]\\ +\,& \lambda_{\mathrm{coord}}\sum_{i=0}^{S^2}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\mathrm{obj}}\Big[(\sqrt{w_i}-\sqrt{\hat{w}_i})^2+(\sqrt{h_i}-\sqrt{\hat{h}_i})^2\Big]\\ +\,& \sum_{i=0}^{S^2}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\mathrm{obj}}(C_i-\hat{C}_i)^2\\ +\,& \lambda_{\mathrm{noobj}}\sum_{i=0}^{S^2}\sum_{j=0}^{B}\mathbb{1}_{ij}^{\mathrm{noobj}}(C_i-\hat{C}_i)^2\\ +\,& \sum_{i=0}^{S^2}\mathbb{1}_{i}^{\mathrm{obj}}\sum_{c\in\text{classes}}\big(p_i(c)-\hat{p}_i(c)\big)^2 \end{aligned} $$

这句话在说什么：把「框位置偏了」「框大小偏了」「有物体的格子置信度不对」「没物体的格子置信度不够低」「类别判错」这五笔账分开计、分别加权，再加起来。符号表如下：$S$ 是网格边长（VOC 用 7），$B$ 是每格预测的框数（2）；$\mathbb{1}_{i}^{\mathrm{obj}}$ 表示格子 $i$ 里出现了物体；$\mathbb{1}_{ij}^{\mathrm{obj}}$ 表示格子 $i$ 的第 $j$ 个预测器「负责」该真值框；$\mathbb{1}_{ij}^{\mathrm{noobj}}$ 是它的反面。带帽子的 $\hat{x}$ 是预测值，不带的是真值。

它为什么这么算：原文自己给平方和误差列了两条极具体的「不完美」理由：(a) 它把定位误差和分类误差等权地看，这显然不合理；(b) 每张图里大量格子没有物体，这些格子的置信度会被往 0 推，原文原话是 often overpowering the gradient from cells that do contain objects——它们会压过那些真有物体的格子传来的梯度，导致训练早期就发散。这第 (b) 条正是 λ_noobj = 0.5 的直接理由：把没物体的那笔账压低一半。

数字账（以 VOC 为例，$S=7$、$B=2$）：有物体的格子只有 3 个左右，而没物体的格子有 46 个、每格 2 个预测器，也就是约 92 笔「无物体」置信度账，对比约 3 笔「有物体」账。如果两者权重一样，梯度的绝对主力就是那 92 笔——这正是 λ_noobj = 0.5 要压的东西，也正是一九三课要把这件事做到极致的地方。

关于宽高那一项还有一个巧思：宽高先开根号。原文的理由是，小框偏一点点和大框偏同样多，在大框上「无所谓」，在小框上「很致命」，直接算平方和会让大框的误差吃掉全部注意力。开根号之后，小框的小偏差和大框的小偏差受到的重视程度就接近了。

推理时怎么用这些输出？原文式 (1) 是这么把两项乘起来的：

$$\Pr(\text{Class}_i\mid\text{Object})\ast\Pr(\text{Object})\ast\mathrm{IOU}_{\text{pred}}^{\text{truth}}=\Pr(\text{Class}_i)\ast\mathrm{IOU}_{\text{pred}}^{\text{truth}}$$

这句话在说什么：「这个框是什么类」乘以「这里真的有东西吗、框得准吗」，得到一个分数——既管类别、也管定位质量。所以一个框可能类别猜对了，但因为框画歪了、IoU 低，最后得分仍然很低。数字上：如果类别概率是 0.9、置信度是 0.4，那这个框的最终分数只有 0.36，会被排在很后面。

最后是激活函数（原文式 (2)），也一并给出：

$$\phi(x)=\begin{cases}x, & x>0\\ 0.1x, & \text{otherwise}\end{cases}$$

这句话在说什么：这就是 leaky ReLU——负半轴不归零，而是保留 1/10 的斜率。它为什么这么算：普通 ReLU 在负半轴恒为 0，一旦某个神经元的输入长期为负，它的梯度就永远是 0，这个神经元就「死掉」了；留一条小缝，它还有机会被救回来。

5. 关键数字：45 FPS / 63.4 mAP，以及一堆对手

YOLO 的数字是它最有说服力的部分。先把主角列出来，再列它当时的对手，最后特意提醒一个容易被误读的地方。

YOLO（主角）

VOC 2007 上 45 FPS / 63.4 mAP。原文称可以「以不到 25 毫秒的延迟处理流式视频」。

Fast YOLO（更快的版本）

155 FPS / 52.7 mAP，只有 9 个卷积层。原文的说法是：mAP 是其他实时检测器的两倍。

YOLO VGG-16（更准的版本）

21 FPS / 66.4 mAP。用一个更大的骨干换精度，速度掉一半多。

对手：Fast R-CNN

0.5 fps / 70.0 mAP。精度更高，速度却差了两个数量级。

对手：Faster R-CNN

VGG-16 版 7 fps / 73.2 mAP；ZF 版 18 fps / 62.1 mAP。

对手：DPM

30Hz 版 30 fps / 26.1 mAP；100Hz 版 100 fps / 16.0 mAP——快是快，精度低得离谱。

把这张表读一遍就明白 YOLO 的定位了：它不是当时最准的，但它是第一个把「准」和「快」同时拉到一个可用区间的。而更有意思的是下面这两个数字。

它错得「和两阶段不一样」

Fast R-CNN 的 top 检测里有 13.6% 是背景假阳性（不含任何物体的框），而 YOLO 只有它的约三分之一。原文解释：YOLO 看得到全图，所以背景误检率显著更低。

所以它们能互补

Fast R-CNN 单独是 71.8，与 YOLO 组合后是 75.0（+3.2）；而它与其他 Fast R-CNN 变体组合只涨 0.3 到 0.6。增益来自「错得不一样」，不是普通 ensemble。

★ 一个必须提醒的易误读点：原文 §4.5 的 Figure 5 表里，YOLO 的 VOC 2007 AP 写的是 59.2。这个数字是 person 单类的 AP，而 Table 1 里的 63.4 是 20 类的 mAP。两者口径不同，不能直接比较——这也是为什么我们前面要花力气先讲清 mAP / AP 的区别。

6. 它不完美在哪：小物体成堆会漏，定位是第一大错源

原文的自我检讨非常具体，恰好也是 SLAM 论文最常引用它的原因。

  1. 空间约束太硬，成堆的小物体必漏。原话：YOLO imposes strong spatial constraints … each grid cell only predicts two boxes and can only have one class. This spatial constraint limits the number of nearby objects.每格只能有两个框、且只能有一个类别——所以「一群鸟」这种挤在一起、又都归到同一格的情况，它是注定要漏的。
  2. 对不常见的长宽比和形态泛化差。原话：it struggles to generalize to objects in new or unusual aspect ratios or configurations。
  3. 用了相对「粗」的特征来预测框。原话：uses relatively coarse features for predicting bounding boxes——因为经过多次下采样，特征图上的一个点已经代表原图一大片了。
  4. ★ 最主要的问题是定位不准。原文原话：our loss function treats errors the same in small bounding boxes versus large bounding boxes … Our main source of error is incorrect localizations.而它的自评是：YOLO still lags behind state-of-the-art detection systems in accuracy … it struggles to precisely localize some objects, especially small ones。

为什么最后一条对 SLAM 特别要命？因为 SLAM 用检测器不是为了「知道图里有个人」，而是为了把这个人身上的像素/特征点剔掉。而 YOLO 给的是一个矩形框——框里必然混着背景。SLAM 论文里把这件事说得很明白，我们在下一节展开。

还有一处 OCR 问题要如实标注：原文 Table 3（VOC 2012 排行榜）在抽取时列与值已经错位——表头里出现了「bike 82.9」「bottle 62.7」这类「数值挤进表头」的现象，该行还被截断。所以本课不引用任何 VOC2012 的分项数字。另外第 2.2 节损失公式的损坏已在上一节说明，此处不再重复。

7. 和前面课程怎么接：这个零件在前八季出现过的地方

第八季 0153–0159 动态环境块是本课最重要的落地点。那一整块的问题意识是一样的：SLAM 假设场景是静止的，但现实里有人有车，只要有人走过，特征匹配就会把动态物体的特征点当成静态地标，把轨迹带歪。于是大家几乎都在同一个位置上放了一个检测器——先把「可能动的物体」框出来，再把框里的特征点剔掉。而它们放的那个检测器，绝大多数就是 YOLO。

逐条看语料库里的实证（都是原文可查的）：

2022_YOLO-SLAM —— 最典型的落地

原文：设计并构建了一个轻量的 Darknet19-YOLOv3 检测网络，接入 SLAM 系统，用来产生定位动态物体所需的语义信息。它把 YOLOv3 的骨干从 Darknet-53 换成 Darknet-19，理由是表里的实测速度：Darknet-53 只有 78 FPS，Darknet-19 有 171 FPS（权重从 159 MB 降到 80 MB，Top-1 从 77.2 降到 74.1）。检测结果作为先验框，再交给 depth-RANSAC 做几何筛选——注意这个「先语义、后几何」的两级结构。

2023_OVD-SLAM —— 给出了最珍贵的耗时数字

原文：方法充分利用 RGB-D 相机的深度信息以及 YOLOv5 的先验信息。它给出了 YOLO 的实测耗时 7.1 ms，整系统 Tracking 33.4 ms（对比 ORB-SLAM3 的 19.8 ms）。这是「检测器在 SLAM 里到底占多少预算」的现成答案——和一九二课 Mask R-CNN 的 195 ms 一比，你就知道 SLAM 圈为什么更爱用检测而不是分割了。

2023_SG-SLAM —— 说出了这个零件最要害的毛病

原文先复述前人的做法：Zhang 等用 YOLO 获取动态物体的语义信息，再根据语义信息剔除动态特征点；接着直接指出问题——the way YOLO extracts semantic information by bounding box will cause a part of static feature points to be wrongly regarded as outliers and eliminated（YOLO 用边界框来提取语义信息的方式，会导致一部分静态特征点被误当成外点剔除）。它自己的选型理由也值得记：用目标检测网络而不是语义分割网络、加上多线程与关键帧建图，正是为了克服实时性短板。

DGM-VINS 的参考文献里直接列了 YOLO-SLAM；SuMa 的参考文献里是 YOLOv3；Kimera 也是把检测/语义融进实时建图库的早期代表。它们共同说明：YOLO 是 SLAM 圈出现频率最高的检测零件，没有之一。

还有一条反向证据很值得写进课里：YOLO-SLAM 的参考文献里引的是 YOLO / YOLO9000 / YOLOv3 三个版本，而它在实验里比较的对象是 ORB-SLAM2、DS-SLAM、RDS-SLAM。这说明 SLAM 圈引用 YOLO 时，普遍只引到「方法名」这一层，并不引 2016 那篇论文里的结构细节——而这恰恰是本季存在的理由：你读的那些论文，默认你早就知道这些词。

再往上一层看。第八季的动态块与语义块有一个共同的痛点：语义前端太慢。一九二课会给出一个刺眼的数字——Mask R-CNN 约 195 ms 一张图，也就是约 5 fps，而 SLAM 要实时。于是你会看到各种「降本」招数：换更轻的骨干（YOLO-SLAM 的 Darknet-19）、放后台线程、隔几帧跑一次、或者干脆只用检测不用分割（SG-SLAM 的选择）。

这条「精度 vs 实时性」的张力，是第十季全季的暗线。而 YOLO 之所以能成为最高频的零件，正是因为它站在了这条线上的一个甜点上。但它的甜是用「只知道框、不知道像素」换来的——这就是为什么第八季的方法必须再加一层几何约束：零件不完美，所以 SLAM 要加几何约束。

互动判断

某 SLAM 系统用 YOLO 框出「人」，然后把框内所有特征点全部剔除。这个做法为什么会出错？

8. 读完你应该能回答

  1. 两阶段与单阶段检测的流水线各是什么样？为什么两阶段「好训」而单阶段「难训」？
  2. YOLO 的网格规则是什么？「哪个格子负责哪个物体」的判断依据是什么？为什么每格里两个框共享一组类概率？
  3. VOC 设置下 S、B、C 各是多少？每格输出多少个数？整个张量是什么形状？每图一共多少个框？
  4. YOLO 的置信度是怎么定义的？为什么要把「有没有物体」和「IoU」乘起来？
  5. λ_noobj = 0.5 这一项是为了解决什么问题？宽高为什么要先开根号？
  6. YOLO 自述的最主要错误是什么？它在背景误检上比 Fast R-CNN 好多少？这两件事为什么能让它们组合起来涨 3.2 个点？
  7. 为什么 SLAM 论文用 YOLO 的框去剔动态特征点会误伤静态点？这个「误伤」在 SG-SLAM 里被怎么描述？

课后练习

  1. 一张 448×448 的图，S=7、B=2、C=20。请算出：一共多少个格子、每格输出多少个数、整个输出张量的形状、每图一共多少个候选框。
    展开查看答案
    格子数 7×7 = 49；每格输出 B×5 + C = 2×5 + 20 = 30 个数；张量形状 7×7×30；每图共 49×2 = 98 个框。对比：Selective Search 一类的候选框法每图要约 2000 个。
  2. 「YOLO 在 VOC 2007 上 AP 是 59.2」与「YOLO 在 VOC 2007 上 mAP 是 63.4」——这两句话哪里有问题？
    展开查看答案
    59.2 是原文 §4.5 Figure 5 表里 person 单类的 AP；63.4 是 Table 1 里 20 类平均的 mAP。两者类别范围不同，不能直接比较，也不能说「哪个更高」。所以引用时必须把「哪一类 / 多少类平均 / IoU 阈值多少」说清——这与第九季 0180 那条「看到轨迹误差先问真值多准」是同一类纪律。
  3. YOLO 承认「每格只能报两个框、且只能有一个类别」。请举出一个会因此漏检的真实场景，并说明这类漏检对 SLAM 意味着什么。
    展开查看答案
    场景：一群挤在一起的鸟、一排并肩走的人、货架上贴着的一排相同商品——多个小物体的中心都落在同一格附近，而该格最多只能交出两个框、一组类概率，于是漏检。对 SLAM 的含义：漏检意味着有动态物体没被剔掉，它的特征点仍会参与位姿估计，污染轨迹。所以 SLAM 不能只靠语义前端一道闸门，必须再加几何一致性检查（如 DynaSLAM 的多视图几何、YOLO-SLAM 的 depth-RANSAC）。
  4. 为什么本课要把 YOLO 的损失函数标成「重建版」？这样做和不加说明地照抄，差别在哪？
    展开查看答案
    因为语料库里的 md 版本该式已被 OCR 破坏：求和上下限写成 i=0 to ∞、出现 B² 与 B³、权重里出现原文并不存在的 λ_such、指示函数被替换成无意义符号。照抄等于把这些错误当成原文传出去。重建的依据是正文文字（λ_coord = 5、λ_noobj = 0.5、宽高开根号、两个指示函数），并显式告知读者这是重建版。这就像一九三课要提醒「Table 2 行列错位」、一九二课要提醒「Table 2c 的空白列容易被读反」一样——诚实地标注不确定性，是本课程的一条硬纪律。
