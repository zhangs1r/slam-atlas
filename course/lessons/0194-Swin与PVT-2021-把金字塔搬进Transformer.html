前置补丁：ViT 与 Q/K/V 自注意力（不补这个，后面的词全是天书）

在讲 Swin 和 PVT 之前，必须先把它们要打倒的那个对手讲清楚——那就是 ViT（Vision Transformer，2020）。ViT 的想法极其干脆：图像不是不能当句子读吗？那就把它切成小块当词。

具体做法是：把一张 $224\times 224$ 的图切成 $16\times 16$ 的小方块（叫 patch），一共 $14\times 14 = 196$ 块。每一块拉直成一个向量，再乘一个线性层映射到固定维度，于是得到 196 个 token（可以理解成 196 个「视觉单词」）。这些 token 加上位置编码（告诉网络「你是第几行第几列的词」），然后送进一个标准的 Transformer 编码器。整个网络里，从头到尾都是这 196 个 token，分辨率一次都没变。

这就是 ViT 的柱状结构（columnar）：一根粗细不变的柱子，从头通到尾。它的输出是单一尺度的特征图，而且分辨率很低——$224$ 的图只剩 $14\times 14$。

自注意力到底在算什么

Transformer 的发动机叫自注意力（self-attention）。它把每个 token 变成三个角色：

  • Q（Query，查询）：我这个 token 想找什么；
  • K（Key，键）：我这个 token 能提供什么线索；
  • V（Value，值）：如果别人来找我，我交给它什么内容。

然后拿每个 Q 去和所有的 K 比对一遍，算出「我该在谁身上花多少注意力」，再按这个权重把所有 V 加权求和。

$$\mathrm{Attention}(Q,K,V) = \mathrm{Softmax}\!\left(\frac{QK^{T}}{\sqrt{d}}\right)V$$

这句话在说什么：$QK^{T}$ 是一个「谁该看谁」的打分表，形状是 $(\text{token 数})\times(\text{token 数})$；除以 $\sqrt{d}$（$d$ 是每个头的维度）是为了把分数压回合理范围；Softmax 把每一行变成一组加起来等于 1 的权重；最后乘 $V$，得到「按权重混好的新特征」。

它为什么这么算：这是「全局建模」——每个 token 都能直接看到所有 token，不像卷积只能看邻域。这既是它的优点，也是它的灾难。

形状账：一张 $224\times 224$ 的图，patch 取 $16\times 16$，token 数 $hw = 14\times 14 = 196$。那张 $QK^{T}$ 的打分表就是 $196\times 196$。如果为了检测/分割要提分辨率，把 patch 换成 $4\times 4$，token 数立刻变成 $56\times 56 = 3136$，打分表变成 $3136\times 3136$ ——参数量没变，但注意力矩阵大了 256 倍。PVT v1 的原文里就记着这件事：直接把细 patch 喂给 ViT，32G 显存的卡会直接爆（Table 6 的 ViT-Small/4 一行写着 Out of Memory）。

所以本节两个主角的共同起点是同一句话：ViT 的输出是「单尺度、低分辨率」的，而且注意力是「二次复杂度」的；而检测和分割要的恰恰是「多尺度 + 高分辨率」。

1. Swin：把注意力关进窗户里，再让窗户错位

Swin Transformer 的完整标题是 Swin Transformer: Hierarchical Vision Transformer using Shifted Windows（移位窗口的层次化视觉 Transformer）。名字里两个词就是它的两招，我们一个一个来。

第一招：层次化（Hierarchical）——像 CNN 一样分四级

Swin 把网络分成 4 个 stage。stage 之间不靠卷积降采样，而是靠一个叫 Patch Merging 的层：把相邻的 $2\times 2$ 个 patch 在通道方向拼起来，再做一次线性映射。效果是 token 数减少 4 倍（分辨率减半）、通道数翻倍。原文明确说了这个设计的目标：让最终的特征图分辨率变成 H/4、H/8、H/16、H/32，与 VGG 和 ResNet 这类典型卷积网络完全一致——这样下游的 FPN、检测头、分割头就都能原样接上去。

第二招：移位窗口（Shifted Windows）——先把注意力关小，再让窗户错位

这一招才是 Swin 的灵魂。它的逻辑是这样的：

① 先把注意力关进窗户里。不划算让每个 token 看全图，那就把特征图切成一个个 $M\times M$（默认 $M = 7$）的不重叠小窗，自注意力只在窗内算。这一步叫 W-MSA（Window Multi-head Self-Attention，窗口多头自注意力）。

② 但窗与窗之间就断了联系。只在自己那扇窗里算，意味着左上角的窗永远看不到右下角的窗。这显然不行。

③ 于是下一层把窗户整体挪半格。在相邻两个 block 之间，把窗口划分整体平移 $(\lfloor M/2\rfloor, \lfloor M/2\rfloor)$ 个像素。原来在两个不同窗口里的邻居，现在落进同一个新窗口了——跨窗信息就这样接上了。这一步叫 SW-MSA（Shifted Window MSA）。

于是整个网络是「一层常规、一层移位」交替往前走的。原文的公式（3）就是把这个节奏写出来：$\hat{\mathbf{z}}^{l}$ 走 W-MSA，$\hat{\mathbf{z}}^{l+1}$ 走 SW-MSA，中间各自夹一个 MLP 和两条残差连接。

$$\Omega(\mathrm{MSA}) = 4hwC^{2} + 2(hw)^{2}C$$ $$\Omega(\mathrm{W}\text{-}\mathrm{MSA}) = 4hwC^{2} + 2M^{2}hwC$$

这句话在说什么：这两个式子都是「算一次注意力要花多少计算量」的估算。$h,w$ 是特征图的高和宽（以 patch 计，所以 $hw$ 就是 token 总数），$C$ 是通道数，$M$ 是窗口边长（默认 7）。式子里 $4hwC^2$ 这一项是「把 token 投影成 Q/K/V 并做输出投影」的开销，两种注意力都一样；真正的差别全在第二项。

它为什么这么算：标准注意力里，那个「谁该看谁」的打分矩阵是 $(hw)\times(hw)$ 的，所以第二项是 $2(hw)^2 C$——对 token 数是二次的，图一大就爆炸。而窗口注意力里，每个 token 只需要和自己窗内那 $M^2$ 个 token 比对，所以那一项变成 $2M^2hwC$——只要 $M$ 固定，它对 $hw$ 就是线性的。原文的结论一句话：前者对 patch 数 $hw$ 是二次的，后者在 $M$ 固定（默认 7）时是线性的。

形状账（具体数字走一遍）：拿 Swin-T 的 stage 1 举例。输入 $224\times 224\times 3$，patch 是 $4\times 4$，所以特征图是 $56\times 56$，通道 $C = 96$。此时 $hw = 56\times 56 = 3136$。

  • 标准注意力的第二项：$2\times 3136^{2}\times 96 \approx 1.89\times 10^{9}$；
  • 窗口注意力的第二项：$2\times 7^{2}\times 3136\times 96 \approx 2.95\times 10^{7}$；
  • 比值 $\dfrac{3136}{49} = 64$。正好是一层特征图里的 token 数除以一个窗口的 token 数——也就是说，窗口注意力把最吃资源的那一项直接砍到了六十四分之一。

而且这一招还有一个原文专门点出的工程好处：同一个窗口里的所有 query 共享同一套 key，这让显存访问变得规整（原文原话是 facilitates memory access in hardware）；相比之下，早年的滑动窗口注意力方案「不同的 query 像素要不同的 key 集合」，实际延迟反而比卷积网络大得多。所以移位窗口最初其实是一个省内存访问的工程选择，不只是理论动机。

2. PVT v1：不关窗户，而是把 K/V 压小

同年（2021）的另一篇是 PVT，完整标题是 Pyramid Vision Transformer: A Versatile Backbone for Dense Prediction without Convolutions。请注意标题最后那五个词——「without Convolutions」（免卷积）是标题的一部分，这一点后面第 4 节要专门讲，因为课程清单在这里出过一处错。

PVT 的目标和 Swin 一模一样：把金字塔搬进 Transformer，做出一个能替代 CNN 主干的、面向稠密预测的通用主干。原文说 PVT 是第一个面向各种像素级稠密预测任务的纯 Transformer 主干。但它走的是另一条路。

第一招：金字塔——用 patch 的尺寸替代卷积的 stride

PVT 也是 4 个 stage，stage 之间用 patch embedding 层：对上一级特征图做不重叠的切块，展平后做线性投影。关键设计是切块的尺寸逐级增大，于是 stride 依次是 4、8、16、32，token 数逐级下降，通道数逐级上升，得到特征金字塔 $\{F_1, F_2, F_3, F_4\}$，可以直接喂给 FPN、RetinaNet、Mask R-CNN、Semantic FPN 甚至 DETR。

原文有一句话说得很清楚，堪称 PVT 的工程翻译：不像 CNN 主干用「不同的卷积 stride」来得到多尺度特征图，PVT 用的是逐级收缩的 patch embedding——用 patch 尺寸替代卷积 stride，这就是它「免卷积」招牌的核心动作。

第二招：SRA——把 K/V 在空间上先压一刀

光有金字塔还不够。浅层那些 stage 的特征图仍然很大（stage 1 是 H/4 × W/4），自注意力还是吃不消。PVT 的第二招是 SRA（spatial-reduction attention，空间缩减注意力）：在手上前，先把 K 和 V 在空间上降采样。

$$\mathrm{SR}(\mathbf{x}) = \mathrm{Norm}\!\left(\mathrm{Reshape}(\mathbf{x}, R_i)\,W^{S}\right)$$ $$\mathrm{head}_j = \mathrm{Attention}\!\left(QW_j^{Q},\ \mathrm{SR}(K)W_j^{K},\ \mathrm{SR}(V)W_j^{V}\right)$$

这句话在说什么：第一个式子定义了一个叫 $\mathrm{SR}$ 的操作，它把输入序列 $\mathbf{x}$ 的空间维度缩小。第二个式子是关键——注意 $Q$ 外面没有套 $\mathrm{SR}$，而 $K$ 和 $V$ 外面套了。这正是「只压缩 K/V 的空间尺寸、不动 Q」的写法。

它为什么这么算：注意力那个吃资源的打分矩阵是 $(\text{Q 的长度})\times(\text{K 的长度})$。我们不想动 Q（要保留每个位置自己的查询），那就把 K 的长度压小——打分矩阵的面积就跟着按比例缩小了。原文的量化说法是：这样做的计算与显存开销比标准多头注意力低 $R_i^2$ 倍。

形状账（具体数字走一遍）：设 stage $i$ 的输入序列 $\mathbf{x}$ 形状是 $(H_iW_i)\times C_i$，缩减比 $R_i = 8$。那么：

  • $\mathrm{Reshape}(\mathbf{x}, R_i)$ 把它重排成 $\dfrac{H_iW_i}{R_i^{2}}\times (R_i^{2}C_i)$ —— token 数变成原来的 $1/R_i^2$（这里是 1/64），每个 token 的维度被撑成 $R_i^2$ 倍（这里是 64 倍）；
  • $W^{S}\in\mathbb{R}^{(R_i^{2}C_i)\times C_i}$ 是一个线性层，作用是把被撑大的那一维压回 $C_i$；
  • 最后 $\mathrm{Norm}$ 是 LayerNorm。输出形状是 $\dfrac{H_iW_i}{R_i^{2}}\times C_i$。
  • 于是打分矩阵从 $H_iW_i\times H_iW_i$ 缩到 $H_iW_i\times \dfrac{H_iW_i}{R_i^{2}}$ ——面积直接少了 64 倍。

这就是为什么 PVT 敢把 token 数很大的浅层 stage 拿来做全局注意力：它的注意力从来不切窗，而是把 K/V 先缩小，再让每个 Q 去看缩小后的全局 K/V。

原文把这个卖点说得很直白：相比传统 CNN 主干那种「随网络深度增加而增大的局部感受野」，PVT 始终产出一个全局感受野。请注意这句话与 Swin 的叙事几乎相反——Swin 卖的是「局部窗口 + 线性复杂度」，PVT 卖的是「全局感受野」。这就是本课最值得对照的一对。

4. 一处必须纠正的清单：这里讲的是 PVT v1，不是 PVTv2

这是本季第三处「课程清单与论文正文不符」，也是本课必须先说清楚的一件事。

纠正：清单写「PVTv2（2021）」，正文其实是 PVT v1

课程清单把这一篇标成 PVTv2，但打开正文，一级标题是 Pyramid Vision Transformer: A Versatile Backbone for Dense Prediction without Convolutions ——清单漏掉了结尾的「without Convolutions」五个词，于是把 v1 当成了 v2。

更关键的是：PVTv2 是本文同作者的后续工作，它根本不在本项目的语料库里。证据是 PVT v1 自己的正文里写着「我们最近提出了一个方案 PVTv2」，并在参考文献里给出了 PVTv2 的条目（arXiv 2106.13797）。也就是说，

  • PVTv2 的三个核心卖点——线性 SRA、卷积前馈、重叠 patch embedding——在本课里一个字都不能出现。它们属于另一篇语料库里没有的论文，写进来就是无据捏造。
  • 本课讲的每一句、每一个数字，都来自 v1 自己的正文。

而且 PVT v1 身上有一处必须如实写出来的「标题张力」

这件事很值得学，因为它教的是怎么读一个名字。

PVT v1 的标题和摘要高调宣称 without Convolutions，贡献点第一条还自称「第一个纯 Transformer 主干」。但正文里其实有松动：它在相关工作里把 Inception 系列的多路卷积核、ResNeXt 的分组卷积列为「有效性已被验证」的先例；而更要紧的是——它的续作 PVTv2 恰恰是靠把卷积要素加回来（卷积前馈、重叠 patch embedding 等）取得提升的。

这不矛盾，而是说明一件很重要的事：「免卷积」不是终局，而是一次路线上的尝试。原文自己也没把话说死——它在讨论里承认「针对 CNN 设计的那些模块（SE、SK、空洞卷积、剪枝、NAS）本工作都没有考虑」，还承认「基于 Transformer 的视觉模型仍然处在发展的早期阶段」。

这里给读者一个可迁移的判断习惯：看到一篇论文标题里写着「without X」或者「X-free」，不要立刻把它当成定论，而要去看它的后续工作是继续沿着这条线走，还是把 X 续回来了。续作把东西加回来，往往比标题更有信息量。

顺带说一句与本季主题相扣的话：连课程清单都会把 PVT v1 和 PVTv2 记混，正说明「凭名字猜内容」这件事有多危险——这恰好是本季「补名词」主题最好的一个注脚。

5. 它不完美在哪：零件的缺陷，为什么会变成 SLAM 的约束

本季有一条贯穿全季的要求：每个零件都要讲「它不完美在哪」。Swin 和 PVT v1 的毛病不一样，但都能连到 SLAM 的设计上。

① Swin 的毛病：速度不是因为算法慢，而是因为内核没优化

原文很诚实地写了：虽然表格里 Swin 的吞吐看着不差，但它的实现用的是「PyTorch 内置算子，而这些算子并不都经过良好优化」，而对手 ResNe(X)t 是「由高度优化的 cuDNN 函数搭起来的」；作者直言「彻底的算子级内核优化超出本文范围」。另外与 DeiT 的比较也不完全公平——DeiT 只有单一分辨率特征图、根本没法直接做检测，作者是人为给它加了反卷积层造出层次特征才搭上比较的。

② Swin 实现的另一个「不便宜的地方」：移位要额外处理

移位会把窗口数从 $\lceil h/M\rceil \times \lceil w/M\rceil$ 变成 $(\lceil h/M\rceil+1)\times(\lceil w/M\rceil+1)$。最朴素的补零做法在窗口数少的时候会带来 2.25 倍的额外计算（从 $2\times 2$ 变 $3\times 3$）。作者用「循环移位到左上 + 掩码」解决，使批窗口数保持不变，这个实现相对朴素补零在 Swin-T/S/B 上分别再快 13% / 18% / 18%。

③ PVT v1 的毛病：分类上没赢，输入一大就变慢

原文自己承认得很干脆：金字塔结构对稠密预测有好处，但对图像分类几乎没带来提升（PVT-Large 的分类 top-1 err 是 18.3，与 ViT/DeiT-Base/16 的 18.3 打平）。而且它承认当输入尺度变大时，PVT 的 GFLOPs 增长速度比 ResNet 快，只在输入不超过 $640\times 640$ 时两者相当——原文的结论原话是「我们的 PVT 更适合中等分辨率输入」。在 COCO 常用的 800 短边设定下，PVT-Small 的 RetinaNet 甚至比 ResNet-50 更慢，要降到 640 短边才反超（51.7 ms vs 55.9 ms）。

④ 这条线索怎么接到 SLAM：一个零件只有「够快」才可能进实时系统

本季的暗线是「精度 vs 实时性」。第八季 0155 与 0156 那一块讲的动态环境处理，痛点是语义前端太慢——Mask R-CNN 单张图 195 ms（约 5 fps），而 SLAM 要实时。骨干网络正是这条代价链的第一环：主干慢，后面所有环节都慢。

于是现实里 SLAM 系统的选择常常很务实：不用最贵的骨干，而是选一个速度/精度权衡合适的。Swin 的作者自己就把贡献定位成「取得最好的速度-精度权衡」，而不是绝对精度第一——这句话值得记住，因为 SLAM 里要的往往正是这个。

另外还有一层：这两个零件在语料库里的存在感极不对称。Swin 有真正的主干级落地（地点识别），PVT v1 一次实体引用都没有。这不是评价谁更优秀，而是一个读论文时要养成的习惯：看到「某方法用了某某主干」时，先去确认这个「某某」在不在你要用的那条技术线上。

最后连回第九季：这些检测/分割的零件在评测里用 IoU、AP、mAP 衡量，而 0180 的 ATE/RPE 量的是轨迹——两套尺子。看到本课这些数字（58.7 box AP、40.4 AP）时，先问一句「这是哪个指标、IoU 阈值是多少」。

读完你应该能回答

1. ViT 为什么不适合检测/分割？

因为它是柱状结构，输出单一尺度、低分辨率的特征图；而检测/分割要的是多尺度 + 高分辨率。想提分辨率就得把 patch 切细，token 数平方级上涨，注意力矩阵直接爆显存。

2. 自注意力的二次复杂度从哪一项来？

从 $\Omega(\mathrm{MSA}) = 4hwC^{2} + 2(hw)^{2}C$ 的第二项来——打分矩阵是 $(hw)\times(hw)$ 的。第一项 $4hwC^2$ 是线性的，第二项才是瓶颈。

3. 移位窗口在干什么？

把自注意力关进 $M\times M$ 窗口（默认 $M=7$）拿到线性成本；再在下一层把窗口整体挪 $(\lfloor M/2\rfloor,\lfloor M/2\rfloor)$ 个像素，让原来的跨窗邻居落进同一个窗，把跨窗连接补回来。

4. PVT 的 SR(x) 在压什么？

压 K 和 V 的空间长度（token 数变成 $1/R_i^2$，每 token 维度撑成 $R_i^2$ 倍，再由 $W^S$ 压回 $C_i$）。Q 不压，所以注意力仍然是全局的，只是看的是缩小后的全局 K/V。

5. 为什么说这两篇是「同目标、反路径」？

同目标：都是 2021 年、都为稠密预测做 4-stage 金字塔主干。反路径：Swin 是局部化（切窗 + 移位），PVT 是稀疏化（压 K/V 尺度）——一个卖线性复杂度，一个卖全局感受野。

6. 清单错在哪？

清单标「PVTv2」，正文其实是 PVT v1（标题漏了结尾的 without Convolutions）。PVTv2 不在语料库里，它的线性 SRA、卷积前馈、重叠 patch embedding 都不能写。而且要如实写出标题张力：v1 拿「免卷积」当招牌，续作 v2 又把卷积加回来了。

课后练习

  1. 用你自己的话解释：为什么「窗口注意力」的第二项 $2M^{2}hwC$ 在 $M$ 固定时对图像尺寸是线性的，而在标准注意力里那一项是二次的？
    展开查看答案
    标准注意力里，每个 token 都要和全部 token 比对，所以参与比对的组合数是 $(hw)\times(hw)$，对 token 数 $hw$ 是二次的。窗口注意力里，每个 token 只和自己所在窗内的 $M^2$ 个 token 比对，所以组合数是 $hw \times M^2$。因为 $M$ 是固定常数（默认 7），$M^2 = 49$ 也是常数，于是整个式子的增长只由 $hw$ 决定——是线性的。换句更直白的话：图变大时，token 变多，但每个 token 的「朋友」数量不变。
  2. 走一遍形状账：某 stage 的特征图是 $64\times 64$、通道 128，窗口 $M=7$。窗口注意力的第二项 $2M^{2}hwC$ 与标准注意力的第二项 $2(hw)^2C$ 相比，大约是几分之一？
    展开查看答案
    $hw = 64\times 64 = 4096$，$C = 128$。
    标准注意力第二项 $=2\times 4096^{2}\times 128$；窗口注意力第二项 $=2\times 49\times 4096\times 128$。
    两者之比 $=\dfrac{49}{4096}\approx \dfrac{1}{83.6}$，也就是大约八十四分之一。
    注意这个比值其实就是 $\dfrac{M^{2}}{hw}$——特征图里的 token 越多、窗口相对越小，省得越多。这也正是 Swin 在最浅层（token 最多）收益最大、在深层收益收敛的原因。
  3. PVT 的 $\mathrm{SR}(\mathbf{x})$ 如果把 Q 也一起压了，会有什么后果？
    展开查看答案
    SRA 的结构是 $\mathrm{Attention}(QW^{Q},\ \mathrm{SR}(K)W^{K},\ \mathrm{SR}(V)W^{V})$——Q 保持原长，只有 K、V 被压。如果连 Q 也压，输出序列的长度就会跟着缩短，每个位置自己的查询就没了，输出的特征图分辨率会掉一档，浅层「给分辨率」这件事就做不成了。注意打分矩阵的行数等于 Q 的长度、列数等于 K 的长度：只压列不压行，才能既省算力又保住输出分辨率。
  4. Swin 的作者说自己「追求的是速度-精度权衡而不是绝对精度」，这句话在 SLAM 语境下为什么特别重要？
    展开查看答案
    因为 SLAM 是实时系统。第八季动态环境块里 Mask R-CNN 单图 195 ms（约 5 fps）就已经被抱怨「跑不到帧率」，一个骨干如果只追精度不要速度，后面整条流水线都没法实时。所以在 SLAM 里选骨干，第一步往往不是比谁 AP 高，而是先划一条延迟预算线。原文里还有一处很具体的速度-精度对立可以引：PointPillars 只用 16 ms（约 60 Hz），但它的精度普遍不如体素方法——这条对照下一课（0196）会展开。
  5. 「免卷积」这个招牌，为什么不能直接当成定论来记？
    展开查看答案
    因为 PVT v1 的续作 PVTv2（不在本语料库）恰恰是靠把卷积要素加回来取得提升的。一篇论文的标题说的是它当时的路线选择，不是这条路线最终的结论。判断一个「without X」是不是终局，要看后续工作：如果续作把 X 又加回来，说明那个 X 里有当时没被替代的价值。这个习惯对读 SLAM 论文同样适用——很多「不用 IMU」「不用回环」的方案，续作都会补回去。
