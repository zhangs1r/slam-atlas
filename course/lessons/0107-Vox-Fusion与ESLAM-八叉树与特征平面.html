Vox-Fusion 与 ESLAM：八叉树与特征平面

本节目标

读完你应该能：说清 NICE-SLAM 的网格为什么占内存；讲清 Vox-Fusion 用八叉树「只在表面开盒子」的思路；讲清 ESLAM 用三张平面拍扁三维内存账的做法；并用一张表横向比较两篇。

和前面课程怎么接

Vox-Fusion 的八叉树 + Morton 编码，和第二季 0034 Voxel Hashing（体素块 + 哈希、懒惰/稀疏分配）是同族「稀疏 + 快速索引」思想，只是装的是神经特征而非 TSDF 标量。ESLAM 把第一季 0033 KinectFusion 的 TSDF 当成逐点监督信号而非显式体素。两者都是对上一节 NICE-SLAM「稠密预分配、立方内存」的直接回应。

1. 组课框架：两篇回答同一个问题——「格子」怎么摆才省内存

NICE-SLAM 把单 MLP 换成三层特征网格，细节立起来了。但它留了一个代价：网格是预先按整个场景稠密铺满的。场景越大，格子数量按体积（边长的三次方）暴涨，而且很多格子落在空荡荡的空气里，白占内存。原文（Vox-Fusion 第 52 行、ESLAM 第 35/51 行）都点名了这个痛点。

于是这两篇走了两条不同的省内存之路，但问的是同一个问题：特征网格的「格子」到底该怎么摆？

Vox-Fusion（2022）

只在有东西的地方开格子。用一棵八叉树动态分配稀疏体素：空旷处只留一个大块，家具表面才细分出小体素。格子仍是三维体素，但数量被压到最少。

ESLAM（2022）

用平面代替体素。把三维信息拆到三个互相垂直的特征平面（tri-plane）上，内存从「体积 O(L³)」降到「三张面积 O(L²)」，还顺手去掉了预训练。

2. Vox-Fusion：用八叉树「只在表面开盒子」

Vox-Fusion 在 NICE-SLAM 的「网格」思路上做减法。它的核心设定：

  • 显式八叉树 + Morton 编码：用一棵树管理体素，只在有表面的地方动态长出叶子，并能快速增删（第 52 行）；
  • 体素顶点挂共享特征嵌入：每个体素存一个 16 维 embedding，顶点被相邻体素共享以消除边界缝（第 75 行）；
  • 只有一层体素网格（边长 0.2 m，第 192 行），并不是 NICE 的三层；
  • 解码成 SDF 而非占用：过 SDF 解码 MLP 得到标量符号距离 \(s\) 与颜色。

查询某点时，三线性插值取最近体素顶点的特征 \(e\)，再过 MLP \(F_\theta\) 得 \((c_i,s_i)\)。它同样做联合优化：tracking 锁网络只优 6-DoF 位姿；mapping 联合优化几何与位姿，用 RGB / 深度 / free-space / SDF 四类损失。关键帧按「会分配多少新体素」的比例选择（第 128 行）。

这一篇的卖点是动态扩张：场景边界未知时，它也能一边走一边往树上长新盒子，而不会像 NICE 那样被迫预先分配整场网格。

3. ESLAM：用三张平面把三维拍扁

ESLAM 走的是另一条更激进的路：干脆不存三维体素，改成存三个互相垂直的二维特征平面（tri-plane）。它把 NICE 的「三维体素网格」拍扁成平面，内存随场景边长从 O(L³) 变成 O(L²)。

具体存什么：

  • 粗 / 细各 3 张平面（xy / xz / yz 三个朝向），几何 6 张 + 外观 6 张 = 共 12 张平面，每张 32 通道；
  • 粗平面分辨率几何/外观均 24 cm，细平面几何 6 cm、外观 3 cm（第 213 行）；
  • 查询某 3D 点：把它投影到三张平面，各做双线性插值取 4 邻域 → 粗特征相加、细特征相加 → 拼接成 \(f_g(p)\)，过两层 MLP 解码 TSDF \(\phi_g(p)\)。

这里 TSDF 的角色很特别——它既是渲染用的几何，也是逐点监督信号：free-space 逼 1、截断区内逼深度真值（式 7）。这比只靠渲染误差收敛快得多，也正好把第一季 0033 KinectFusion 的 TSDF 思路「神经化」了。

另一大卖点：免预训练。NICE 的解码器是冻结先验，ESLAM 的解码器从头随机训，所以对新场景更灵活。代价是它接受「遗忘换内存」——更新特征适应新几何时会动到旧区域，靠保留关键帧 + 算力回放缓解（第 270 行）。

ESLAM 的速度账

Replica 上 FPT 仅 0.18 s，比 NICE 的 2.10 s、iMAP* 的 5.20 s 快约 10 倍；内存增长 O(L²)：Replica 参数 6.79 M、ScanNet 17.63 M（表 4）。这就是「平面代替体素」省下来的账。

5. 小结：两条省内存之路殊途同归

把这两篇放回「地图里存什么」的整条线索看：iMAP 把一切塞进一个 MLP 权重，NICE-SLAM 拆成三层网格，而本节这两篇开始认真对付「网格的内存账」。它们手法不同，但共同前提完全一致——都拒绝「把整个场景稠密占满」：

Vox-Fusion：靠「稀疏」省

八叉树只在有表面的地方细分体素，空旷处只留一个大块。它守住了「局部更新 + 动态扩张」，场景边界未知也能边走边长。

ESLAM：靠「降维」省

tri-plane 把三维体素拍成三张平面，内存从 O(L³) 降到 O(L²)，还去掉了预训练。代价是「遗忘换内存」。

这两条路都为后面的工作铺了台阶：Co-SLAM 用 hash 网格继续把参数压到极小，Point-SLAM 则把特征从「固定结构」彻底换成「跟随场景的点」。下一节先看 Co-SLAM 怎么把「低频连贯」与「高频锐利」并成一股绳。

课后练习

  1. NICE-SLAM 的网格为什么占内存？Vox-Fusion 与 ESLAM 各自用什么办法把这笔账降下来？
    展开查看答案

    NICE 的网格是预先按整个场景稠密铺满的，格子数随体积 O(L³) 暴涨，空气里的格子白占内存。

    Vox-Fusion：用八叉树只在有表面的地方动态细分体素，空旷处只留一个大块——靠「稀疏」省。

    ESLAM：用三张正交特征平面代替体素，内存从 O(L³) 降到 O(L²)——靠「降维」省。

  2. Vox-Fusion 的八叉树 + Morton 编码，和第二季哪一节课的思想同族？它装的内容有何不同？
    展开查看答案

    同族于第二季 0034 Voxel Hashing（体素块 + 哈希、懒惰/稀疏分配）——都是「稀疏 + 快速索引」。

    不同在于：Voxel Hashing 装的是 TSDF 标量，而 Vox-Fusion 的体素顶点挂的是 神经特征嵌入，要过 MLP 解码 SDF。也就是说，数据结构一脉相承，承载的内容从「显式标量」换成了「隐式特征」。

  3. ESLAM 里 TSDF 扮演了哪两个角色？为什么这让它比只靠渲染误差收敛更快？
    展开查看答案

    TSDF 既用于渲染（当几何），又作为逐点监督信号：free-space 逼 1、截断区内逼深度真值（式 7）。

    只靠渲染误差时，信号要经过「渲染 → 比真图 → 反传」一长链，弱且慢；而 TSDF 监督是直接拿每个采样点的深度真值去逼它的符号距离，点对点地校正，所以收敛快得多。这也等于把第一季 0033 KinectFusion 的 TSDF 思路神经化了。

  4. ESLAM 说「免预训练」，这相对 NICE-SLAM 的冻结解码器是优点还是新麻烦？请结合原文承认的局限谈。
    展开查看答案

    优点是更灵活：解码器从头随机训，不被预训练先验锁死，对新场景泛化更好（这正是 NICE 的短板）。

    代价是它接受「遗忘换内存」：更新特征适应新几何时，会动到共用同一张平面的旧区域（第 270 行）。它靠保留关键帧 + 大量算力回放缓解，但这是真实存在的取舍。所以「免预训练」不是免费午餐，而是把 NICE 的「泛化上限」问题换成了「遗忘」问题。
