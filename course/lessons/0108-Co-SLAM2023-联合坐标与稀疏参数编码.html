和前面课程怎么接

Co-SLAM 的 hash 编码与第二季 0038 Instant NGP 的多分辨率哈希直接同族——它明确用了 Instant NGP 的 hash 编码。区别在于 Instant NGP 是离线、可整场先训，而 Co-SLAM 是在线一边建一边训 + 并联 one-blob 补其「不会补洞」的短板。

2. one-blob 编码是什么：为什么不直接用 hash

Co-SLAM 的地图由两路并联组成。要理解它，先要理解「为什么需要两路」。

  • 纯坐标 MLP（iMAP 那一路）：平滑、连贯，能补洞（没看见的地方会合理猜测），但慢、易遗忘；
  • 纯参数网格（NICE 那一路）：快、记细节好，但不会补洞、缺连贯性（原文 Figure 2 直接展示）。

于是 Co-SLAM 想：别二选一，两个都留。它用 one-blob 坐标编码 \(\gamma(x)\) 提供低频连贯 / 补洞的先验，用多分辨率 hash 特征网格 \(V_\alpha\) 提供高频局部 / 快收敛。one-blob 是作者对多频正弦位置编码的一种替换设计——它把坐标映射成一段平滑的「blob」（钟形）基，专门负责大块、连贯的形状，而不是去硬记高频细节。

为什么要 one-blob 而不是直接上 hash？因为只有 hash 会「快但不补洞」。把坐标编码那一路并进来，正是为了补 hash 的这块短板。

3. 联合编码：低频与高频如何并联、各管什么

查询某点时，两路各自产出特征，拼接后喂进解码器：

$$f_\tau(\gamma(x),V_\alpha(x))\mapsto (h,s),\qquad f_\phi(\gamma(x),h)\mapsto c$$

其中 \(\gamma(x)\) 是 one-blob 坐标编码（低频、连贯、补洞），\(V_\alpha(x)\) 是多分辨率 hash 网格插值特征（高频、局部、快），两者拼接后先过几何解码器 \(f_\tau\) 出 SDF \(s\) 与中间量 \(h\)，再过颜色 MLP \(f_\phi\) 出颜色 \(c\)。

  • 低频支路（坐标编码）：负责大块连贯形状、负责「没观测到的地方也能合理猜」；
  • 高频支路（hash 网格）：负责局部细节、负责快收敛；
  • 并联：两路特征拼成一条向量，一起进解码器——互补而非替代。

4. 全局 BA：允许对所有关键帧做联合优化

这是 Co-SLAM 相对前几篇的一个范式突破。前面 NICE-SLAM 的 BA 是局部的：只在「与当前帧有视觉重叠」的若干关键帧里做（因为 NICE 改一处牵动全局，只能小窗口）。Co-SLAM 因为用了 hash 网格（局部性好），可以放开手脚做全局 BA：

  • mapping 阶段从所有关键帧的全局池里随机采样 \(N_g\) 条光线；
  • 交替优化场景参数 θ 与累积位姿梯度（第 116–126 行）；
  • 因此不需要存储完整关键帧图像，也不需要关键帧选择——每帧只存约 5% 像素。

前几篇（iMAP / NICE）因为信息挤在全局结构里，只能做局部或窗口 BA，鲁棒性差；Co-SLAM 用「局部性好的 hash + 并联坐标编码」换来了「可以从整条轨迹取光线」的自由。下面这张图把「局部 BA 窗口」和「全局 BA 大池」画成对比。

5. 速度数字：标题就强调 real-time

Co-SLAM 的实时性是其卖点（标题与摘要都强调 real-time）。关键数字：

指标 Co-SLAM 对照（NICE）
帧率（Replica）17.4 FPS0.91 FPS
帧率（ScanNet / TUM）12–13 Hz0.1–1 Hz
参数量仅 0.26 M17.4 M
Replica Depth L1 (cm)1.511.90

相比 NICE，Co-SLAM 在精度相近或更好的前提下，速度提升了约 10–20 倍，参数量却只有零头（0.26 M vs 17.4 M）。它原文承认的局限：依赖 RGB-D、对光照变化与深度不准敏感；未做信息引导采样（仍随机像素）；不做回环（第 203 行）。

互动判断

Co-SLAM 为什么能放弃「关键帧选择」这一步、直接做全局 BA？

课后练习

  1. 为什么 Co-SLAM 不直接用 hash 网格、还要并联一路 one-blob 坐标编码？请结合 Fig. 2 说明。
    展开查看答案

    因为只有 hash 会「快但不补洞、缺连贯」。Fig. 2 三栏对照：坐标编码能补洞但慢、参数（hash）编码快但不补洞、并联两者又快又补全。

    one-blob 坐标编码提供低频连贯先验与补洞能力，hash 提供高频细节与快收敛。两者并联拼接进解码器，正好互补——所以不是「二选一」，而是「两个都留」。

  2. 用一句话解释「联合编码（joint encoding）」里低频支路与高频支路各管什么频段。
    展开查看答案

    低频支路（one-blob 坐标编码）：管大块连贯形状、负责补未观测区；高频支路（hash 多分辨率网格）：管局部细节、负责快收敛。

    查询点的特征 = 两路特征拼接后一起喂解码器，即 \(f_\tau(\gamma(x),V_\alpha(x))\mapsto(h,s)\)，再 \(f_\phi(\gamma(x),h)\mapsto c\)。注意是「并联进同一向量」，不是加权求和。

  3. Co-SLAM 的「全局 BA」和 NICE-SLAM 的「局部 BA」在做法上有何本质区别？为什么前者更鲁棒？
    展开查看答案

    NICE 的 BA 只在「与当前帧有视觉重叠」的相邻关键帧窗口里做（因为单 MLP/稠密网格改一处牵动全局）；Co-SLAM 从所有关键帧的全局池随机采样光线做 BA，且不需要关键帧选择（每帧只存约 5% 像素）。

    更鲁棒的原因：全局 BA 参考了整条轨迹的约束，不会像局部窗口那样因短期漂移累积而失准。敢这么做，根子在于 hash 网格局部性好——改一处只动附近，才允许从全轨迹取光线。

  4. Co-SLAM 在速度上相对 NICE 提升多少？报出具体数字，并指出它仍没解决什么。
    展开查看答案

    Replica 上 17.4 FPS vs NICE 0.91 FPS（约 19 倍）；ScanNet/TUM 上 12–13 Hz vs 0.1–1 Hz。参数量仅 0.26 M（NICE 17.4 M）。

    仍没解决：依赖 RGB-D、对光照/深度误差敏感、未做信息引导采样、不做回环（第 203 行）。回环这条债要等本季后半段才还。
