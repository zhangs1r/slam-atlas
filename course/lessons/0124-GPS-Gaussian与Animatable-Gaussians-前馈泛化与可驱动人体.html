和前面课程怎么接

这两篇回答的是第二季 0027 课（COLMAP）那条老路的反面：离线 SfM 逐场景优化。本季 3DGS 原著（0116）与 0117 MonoGS 走的也都是逐场景优化，正是 0027 的延续。而「免优化」这条诉求，还直接对上第一季 0011 课承认的六个不成熟环节里的「泛化」那一条。

1. 题眼：能不能不要「针对每个场景再优化一遍」

先把这一节的问题立起来。到目前为止，本季讲的 3DGS 都遵循同一个套路：

$$\text{拍一圈照片} \;\longrightarrow\; \text{跑几十分钟优化} \;\longrightarrow\; \text{得到这一场景的高斯}$$

这条流水线在第二季 0027 课（COLMAP）就已经定型了：先离线做一遍 SfM 把位姿和稀疏点解出来，再基于它做后续重建。3DGS 原著（0116）与 MonoGS（0117）只是在「后续重建」这一步换成了高斯，前面的路子没变——每个新场景，都要从头优化一遍。

这件事在离线重建里可以接受（反正跑一次）；可一旦你想做「实时」的东西，它就立刻变成死结：来一个新的物体、新的人、新的一间房，你就得等几十分钟。GPS-Gaussian 的摘要里有一句话点得很准：原来的高斯泼溅与神经隐式方法都「 necessitate per-subject optimizations 」——它们天生要求针对每一个主体（每个人、每个场景）单独优化。

这里必须补一句诚实的说明。本季的写作规范里，这一课原先列的是「GPS-Gaussian ＋ GridFormer 组课」。我在核对时发现：GridFormer 那篇的标题是「Residual Dense Transformer with Grid Structure for Image Restoration in Adverse Weather Conditions」，全文讲的是图像去雨 / 去雾 / 去雪，正文没有任何高斯、泼溅、三维或新视角合成的内容。它跟 3D 高斯毫无关系，属于被错标进来的。所以这一课改成 GPS-Gaussian（前馈免优化）＋ Animatable Gaussians（姿态可驱动）——两篇都是人体方向、都属于「非 SLAM 但方法可借鉴」，组在一起更顺。

2. GPS-Gaussian：一次前向推理直接出结果

先看它的定位。原文摘要里的关键一句是：不同于需要「逐主体优化」的原版高斯泼溅与神经隐式方法，我们引入定义在源视图上的高斯参数图，直接回归高斯泼溅的属性，从而做到即时的新视角合成，不需要任何微调或优化。

所以「Generalizable（可泛化）」在这里的意思很具体，一点都不玄：网络只在训练阶段见过大量不同的人，训练完之后，来一个从来没见过的人，不需要针对他重新优化，直接前向推理就能渲染出他的新视角。原文 Fig. 1 的图注用了三个词把这件事说得很干净——「without any fine-tuning or optimization」。

它的做法可以拆成四步（原文 Fig. 2）：

① 选两个相邻视角

给一个目标新视角，先挑出离它最近的两个源视角（原文：the adjacent two views）。注意是两个——这是「稀疏视角」设定，不是几十个相机围着拍。

② 估深度

两个视角的图像先过共享的图像编码器，再由一个双目的迭代式深度估计器（binocular depth estimator）分别预测两张深度图。原文说得很清楚：双目立体里「深度估计」等价于「视差估计」，而且它两个视角都要深度图（不像经典做法只算参考视角的），这样更对称、更好并行。

③ 深度当位置图、RGB 当颜色图

每个源视角上，深度图就是 3D 位置图，RGB 图就是颜色图；其余的高斯参数（旋转、缩放、不透明度）逐像素回归出来。这一步就是把 2D 抬到 3D 的关键。

④ 两个视角的高斯合并渲染

两张参数图各自反投影到 3D，聚合成一个高斯集合，再直接泼溅渲染到目标视角。整条链路完全可微，可以端到端训练。

关于输入，有一件必须讲清楚的事：它并不是「随手两张手机照片就行」。原文的设定是「以人为中心的场景 + 稀疏的多相机视角」，而且在把像素反投影到 3D 的公式里明确用到了相机参数 $K$、还提到用的是校正过的双目（rectified stereo）——也就是说相机是已知、可用的。原文没有专门讨论标定问题，但这个前提写在它的公式里，我们在读的时候不能忽略。

速度与训练数据：2K 分辨率的新视角合成，超过 25 FPS，单张现代显卡。对比实验统一在 RTX 3090 上、用两张 1024×1024 的源图像来测「合成一个新视角」的时间；它和 FloRen 都用了 TensorRT 加速推理。训练数据是大量人体扫描数据（THuman2.0、Twindom 以及自采的真实数据），文中明确说是「从大量人体扫描里学到人体的先验」。

3. 逐像素的高斯参数图：2D 是怎么被抬到 3D 的

「pixel-wise（逐像素）」这个词值得单独讲一节，因为它是这套方法的核心技巧。

回忆一下 3DGS 原本的做法：一整个场景的高斯是「优化出来」的——从一个 SfM 稀疏点云开始，然后靠跳来跳去的梯度去挪位置、改大小、改颜色。高斯是空间中的一堆点，没有天然的编号顺序。

GPS-Gaussian 换了一个思路：不要「空间中的点」，而要「图像上的图」。它在源视图的图像平面上定义一组参数图（parameter maps）——原文列了五种：位置 $\mathcal{M}_p$、颜色 $\mathcal{M}_c$、旋转 $\mathcal{M}_r$、缩放 $\mathcal{M}_s$、不透明度 $\mathcal{M}_\alpha$。

关键在于：图像是二维的、有规则网格的、CNN 最擅长处理的东西。把高斯参数放到图像平面上，就可以用普通 2D 卷积网络来回归它们——这正是原文说的「用 2D CNN 的强大表达能力」，也是它相对隐式方法（纯 MLP）的一个结构性优势。而位置那一项不用网络猜，直接由深度图给出，再通过相机投影矩阵 $P$（用相机参数 $K$）反投影到 3D。

$$\text{源视图像素} \;\to\; \text{深度 + RGB + 回归出的参数} \;\to\; \text{反投影成 3D 高斯} \;\to\; \text{聚合渲染}$$

这样做有两个直接好处：① 一个像素对应一个高斯，数量天然有限、结构规整（不会像原版 3DGS 那样靠自适应密度控制长出几百万个）；② 位置由深度决定，几何与颜色是解耦的——深度准不准，直接决定高斯在哪儿。

最后一个设计是联合训练，原文 §4.3 讲了它的两个动机，很值得记：（a）如果两个源视角的深度估计器各自独立训练，两张深度图会对不齐，导致 3D 表示不一致——所以两个视角的深度要一起训；（b）经典的立体匹配深度估计本质是个 2D 任务（在两张图之间找像素对应），而可微渲染能提供三维层面的辅助信息，反过来又能提升深度的精度。这是一个互相帮忙的关系：更准的深度让高斯参数更准，可微渲染又让深度更准。

说完能做什么，再说不能做什么——这一篇的边界必须写清楚，原文自己也承认了：

三条边界（必须记住）

① 只在人体上验证过。它的训练数据全是人体扫描（THuman2.0、Twindom、自采真实人体数据），学到的是「人体长什么样」的先验。它对桌子、房间、街道没有任何证据。

② 它依赖深度估计。整个框架的几何全靠那个双目深度模块，深度不准，高斯的位置就不准。

③ 它明确说了「没见过的大姿态 / 遮挡下泛化未保证」。换句话说，「可泛化」是有范围的——泛化到「新的人」，不保证泛化到「新的动作幅度」。

以及最要紧的一条：它不是 SLAM。它只做新视角合成，不估计相机位姿、不做回环、不建长期地图。它属于「免优化新视角合成」这条分支。它给 SLAM 的价值在于方法可借鉴（比如「把参数放到 2D 图上再抬到 3D」这个技巧），而不是它本身能当 SLAM 用。

4. Animatable Gaussians：让高斯跟着姿态动

第一篇解决的是「来一个没见过的人」；第二篇解决的是另一个问题：同一个人，摆出不同的姿势怎么办？

先说清楚它的目标：「Pose-dependent（姿态相关）」在这里的意思是——高斯的属性是跟着姿态变的。不是我优化出一套固定的高斯然后死板地渲染，而是我输入一个姿态，就预测出一套与之匹配的高斯。原文的标题写得很直接：Learning Pose-dependent Gaussian Maps for High-fidelity Human Avatar Modeling。

它的流程分两大步，看下面这张原图最清楚：

把两段拆开讲。

第一步：重建一个角色专属模板（character-specific template）。从一个接近 A-pose 的帧出发，先优化一个标准的 SDF 与颜色场去拟合多视角图像（用 SMPL 蒙皮 + SDF 体渲染），再用 Marching Cubes 把模板网格抽出来，最后把 SMPL 顶点的蒙皮权重扩散到模板表面，得到一个可形变的参数化模板。

这里要专门提醒一句，免得和 0122 课混淆：这里的 SDF 与 Marching Cubes 是用来做「模板网格」的——它是这套方法的内置传统重建步骤，跟「高斯怎么抽网格」没有关系。高斯本身并不是从 SDF 里长出来的，它们是挂在模板表面上、以 2D 参数图的形式存在的。原文还特意说了为什么要用「角色专属模板」而不是直接用 SMPL-X：因为像长裙这种衣服，拓扑跟 SMPL-X 根本不一致（原文 Fig. 8 的消融就是在比这个）。

第二步：把 3D 模板参数化到 2D 图上。为了能用强大的 2D 网络（这里是基于 StyleGAN 的 StyleUNet），就得先把 3D 表示摊成 2D。原文的做法很聪明：把 canonical（标准姿态）的模板沿正交投影投到正面和背面两个视角，于是得到两张「正/背高斯图」（canonical Gaussian maps）——图上每一个像素就是一个 3D 高斯，带着位置、协方差、不透明度、颜色。原文说，虽然只用正背两张图来参数化，但因为投影是正交的，侧身和手部的高斯也照样能被覆盖到（Fig. 4 专门展示了侧身高斯）。

第三步：从姿态预测高斯图，再把它驱动起来。给一个驱动姿态：

  1. 先把模板用 LBS（线性混合蒙皮）变形到该姿态，把变形后的顶点坐标渲染成正背两张位置图——这张位置图就是「姿态条件」；
  2. 把位置图送进 StyleUNet，输出两张姿态相关的高斯图；
  3. 把这些 canonical 高斯用 LBS 变换到 posed 空间——注意是位置和协方差一起变（原文给的就是位置与协方差两个量的变换公式），因为高斯是各向异性的，光搬位置不转朝向会错；
  4. 可微光栅化渲染到目标相机。

公式上，LBS 就是那套经典的「按蒙皮权重把几根骨头的变换加权平均」：$W(p)=\left(\sum_k w_k M_k(p)\right)p$。看得出它就是「一根骨头一个变换，按权重混起来」。

还有一个设计叫姿态投影（pose projection），很值得记：用 PCA 把驱动姿态信号投影回训练姿态的分布里，并把每个分量限制在 $\pm 2\sigma$ 以内。理由说得很实在——这是数据驱动的方法，直接外推到训练分布之外的姿态，结果一定不好看；与其硬推，不如把姿态拉回到「训练时见过的合理范围」里再插值。原文 Fig. 10 专门做了这个消融。

速度和局限：动画帧率在对比中居前，评测硬件是 RTX 3090、分辨率 1024×1024。原文承认两条局限：① 建模板需要多视角视频（不是随便拍一张就行）；② 它是 per-character 的——换一个人得重新建模板，并不具备跨身份泛化能力。

这第 ② 条尤其要和上一篇对照着记：GPS-Gaussian 是「跨人零样本」，Animatable Gaussians 是「单人多姿态」。两篇都叫「泛化」，但泛化的方向完全不同——一个是泛化到新的人，一个是泛化到新的姿态。

5. ★ 一个必讲的对照：0011 说的「泛化」被回应了多少

这一节要往回接一条很具体的旧线索。第一季 0011 课（深度学习视觉 SLAM 2023）在结尾总结了原文承认的六个不成熟环节，其中第四条叫「泛化」。原文那一段的大意是：

「没有数据集能覆盖真实部署的全部情形（暴雨大雪、动物横穿、临时施工、道路损坏、异常驾驶……），数据还偏向常见样本（如直行）。更深一层：对抗样本能在输入上做人眼不可见的微扰就完全骗过模型——所以『仅在未见数据集上测试是不够的』，需要能证明泛化性的新方法。」

把这段话拆开，它其实提了两个层次的问题：

浅一层：分布覆盖

训练数据覆盖不到真实世界的全部情形，所以「在没见过的数据上跑一遍」不等于「泛化好」。

深一层：评价标准本身不可靠

「 merely testing on unseen dataset is not sufficient 」——需要在压力条件下评估，甚至要有能证明泛化性的新方法。

现在回头看 GPS-Gaussian。它确实是在回应这条线索，而且回应得有分量：

  • 它把「每个新场景都优化一遍」这件事从结构上去掉了——不是优化得更快，而是根本不做优化；
  • 它在没见过的人身上直接出结果（Fig. 1 的题眼就是 unseen），而且是实时的；
  • 它把成本挪到了训练阶段：用大量不同的人、不同的衣服、不同的姿态去训练一个先验——这正是「靠数据覆盖分布」这件事的直接实践。

但边界非常窄，必须诚实指出。0011 课担心的那些情形——暴雨大雪、动物横穿、临时施工——这条方法一个都没碰。它只在人体上有证据；它的「泛化」指的是泛化到新的人，而且原文自己承认「没见过的大姿态与遮挡下泛化未保证」。所以更准确的表述是：

换句话说：它证明了「免优化」这条路是通的，但没有证明「免优化」在开放世界通用。这两句话差别很大，读论文时千万别混。

互动判断

小明读完这两篇之后说：「3D 高斯终于解决了泛化问题——以后来一个新场景，不用优化直接就能出结果。」这个说法哪里不对？

顺带把 0011 那条线索的另外一半也接上：0011 课讲的另一句是「深度学习先吃下匹配与检索」——因为分类预训练能白送「认」的能力。而这两篇论文走的是「深度学习吃掉「重建」这一环」：不是把匹配做快，而是把「优化求解」整个换成一个网络前向。这是同一条思路（把难的手工环节换成学出来的映射）往更深处的延伸，也是本季反复出现的一个模式。

还有一条对照组值得放在这：第二季 0027 课（COLMAP）代表的是标准的离线 SfM 路线——逐场景解一遍位姿与稀疏结构。3DGS 原著与 MonoGS 都是它的延续。GPS-Gaussian 与 Animatable Gaussians 则站在它的反面：不针对这个场景解一遍，而是靠训练时见过的大量相似场景把答案「背」下来。但请注意时间的先后：这两篇仍然需要多相机、需要标定、需要一次性的模板重建——它们不是「不需要任何准备」，而是把准备从「每次」挪到了「一次」。

6. 横向对比与判断

两篇都是人体方向，都非 SLAM，但泛化的方向完全相反。摆在一起看：

「泛化」泛的是什么 泛化到没见过的人（跨身份零样本） 泛化到没见过的姿态（同一个角色）

我们的判断

GPS-Gaussian 更「敢」。它直接在结构上去掉了优化步骤，把整件事变成一个回归问题——这是一个路线级的选择，改变了「3DGS 必须逐场景优化」这个默认前提。它对 SLAM 的启发也最实在：「把参数表示成 2D 图、再抬到 3D」这个技巧，完全可以搬到「来一个新房间就立刻出一版高斯」这件事上。

Animatable Gaussians 更「稳」。它仍然有一次性建模板的成本，但它拿到的是「任意姿态即时渲染」这种极其实用的能力，而且在衣物褶皱这类细节上正面赢了 MLP 系方法。它的贡献是工程与表示层面的（把 SMPL + LBS + 2D CNN 这几样成熟工具拼到高斯上），不是路线层面的。

两篇的共同边界也一样刺眼：都只在人体上成立。把它们称作「3D 高斯的泛化」是过头的话——更准确的说法是「在人体这个被约束得很紧的域里，3D 高斯可以不逐场景优化」。0011 课那句「泛化不成熟」，到今天仍然只被回答了一小块。

下一节换一个完全不同的角度：不再问「好不好用」，而问「跑得起来吗」——几百万个高斯到底占多少显存，以及那个被原版 3DGS 一直容忍的渲染伪影。

课后练习

  1. 请解释 GPS-Gaussian 里「Generalizable（可泛化）」这个词具体指什么。它和「训练得更快」是一回事吗？
    展开查看答案

    不是一回事，差别很关键。

    「可泛化」在这里指的是：训练完之后，来一个网络从来没见过的（unseen）人，不需要针对他做任何微调或优化，一次前向推理就能渲染出他的新视角。原文摘要的措辞是「without any fine-tuning or optimization」，Fig. 1 的题眼就是「unseen human performers」。

    对比原版 3DGS：原版要先拿到某个场景的照片，再针对这个场景跑一遍优化，才能得到这个场景的高斯。换一个人、换一个场景，就得重来。GPS-Gaussian 把「针对这个场景优化」这一步从结构上去掉了。

    和「训练更快」的区别：训练更快说的是「同一个训练流程跑得更省时间」；而这里说的是推理时不再需要训练/优化。前者是效率问题，后者是流程结构问题。当然，代价是它在训练阶段要吃掉大量人体扫描数据（THuman2.0、Twindom 等）来学到人体先验——成本没有消失，只是从「每次使用时」挪到了「一次性训练时」。

    还要记住它的适用范围：只在人体上验证过；依赖深度估计；原文自己都说「未见大姿态/遮挡的泛化未保证」。所以这个「可泛化」是被框住的。

  2. GPS-Gaussian 用「逐像素的高斯参数图」。请说明这样表示有什么好处，以及位置这一项为什么不用网络回归。
    展开查看答案

    好处有三条。

    ① 能用 2D CNN。图像平面是规则的二维网格，卷积网络最擅长；把高斯参数放到图像平面上，就等于把重建问题变成了一个「图像到图像」的回归问题。原文特别提到，纯 MLP 有低频偏置（这一点在 Animatable Gaussians 里也说了），而 2D CNN 的表达能力更强，能回归出更高频的细节。

    ② 数量天然规整、结构清晰。一个像素对应一个高斯，不会像原版 3DGS 那样靠自适应密度控制在空间里长出几百万个位置混乱的高斯。

    ③ 几何与外观解耦。位置图与颜色图是分开的两张图，谁出问题一眼就能看出来。

    位置为什么不回归：因为位置有一个比网络更可靠的来源——深度。原文的做法是：先把两个源视角的图像送进双目深度估计器（双目里深度估计等价于视差估计），得到深度图；然后用相机投影矩阵 $P$（用到相机参数 $K$）把像素反投影到 3D，位置就定了。让网络去「猜」一个三维坐标既不稳定也没必要，而深度本身就是几何的物理量。

    这也解释了为什么它要强调联合训练：两个源视角的深度必须一起训（否则两张深度图对不齐，3D 表示不一致）；而可微渲染又能提供三维层面的辅助监督，反过来提升深度精度。深度更准 → 高斯位置更准 → 渲染更好 → 梯度回传让深度更准，是个正循环。

  3. Animatable Gaussians 里同时出现了 SDF、Marching Cubes 和 3D 高斯。请说清它们各自扮演什么角色；并说明为什么这里用 SMPL-X 反而不如「角色专属模板」。
    展开查看答案

    三者的分工：

    ① SDF + Marching Cubes 用在第一步「建模板」上——先优化一个 canonical 的 SDF 与颜色场去拟合多视角图像（用 SMPL 蒙皮 + SDF 体渲染），然后用 Marching Cubes 从 SDF 场里抽出模板网格。这一步用的完全是传统神经隐式重建那一套。

    ② 3D 高斯才是最终的表示。它们是挂在模板表面上的：把 canonical 模板沿正交投影投到正 / 背两个视角，得到两张高斯图，图上每个像素就是一个 3D 高斯（位置、协方差、不透明度、颜色）。之后每一步驱动（LBS、StyleUNet 预测、可微光栅化）都是在高斯上做。

    这一点务必和 0122 课的 SuGaR 区分开：SuGaR 面对的问题是「怎么从高斯里抽出网格」，所以它要处理高斯与 mesh 的关系；而 Animatable Gaussians 用 SDF + MC 只是为了造一个内部模板，高斯不是从 SDF 长出来的，它是从 2D 高斯图来的。两处的 SDF/MC 出现在完全不同的位置，不要混。

    为什么不用 SMPL-X：原文 Fig. 8 的消融给出答案——SMPL-X 表示不了长裙，因为长裙的拓扑跟 SMPL-X 的身体模型根本不一致，直接套用会导致对没见过的姿态泛化很差。而「角色专属模板」是从输入视频里自适应重建出来的，它能把衣服的基本形状也学进去（原文的用词是 adaptive to the wearing garments）。所以对宽松衣物（尤其是长裙）而言，专属模板明显更好。

  4. 本节最后把这两篇与第一季 0011 课的「泛化」那条线索对上了。请说明：它们回应了这条线索的哪一部分，又完全没碰到哪一部分？
    展开查看答案

    回应了哪一部分：0011 课说「泛化不成熟」，其中一层含义是「没有数据集能覆盖真实部署的全部情形，所以要靠数据去覆盖分布」。这两篇正是这条思路的实践——GPS-Gaussian 用大量不同的人、不同的衣服、不同的姿态去训练一个先验，训练完之后对新的人零样本直接出结果；它把「逐场景优化」这一步从结构上去掉，证明了「不针对每个场景优化也行」这件事在某个域里是通的。

    完全没碰哪一部分：0011 课担心的那些情形——暴雨大雪、动物横穿、临时施工、道路损坏、异常驾驶，以及对抗样本——这两篇一个都没有涉及。它们的世界是：人体、稀疏多相机、相机已标定、受控采集。

    所以更准确的表述是：它们回应的是「泛化」这条线索里「靠数据先验替代逐场景优化」这一小块，而且只在一个被约束得很紧的域（人体）里成立。GPS-Gaussian 原文自己都承认「未见大姿态/遮挡下的泛化未保证」，Animatable Gaussians 更是明确说自己是 per-character（换人要重训）。

    另外还有一条值得对照的差异。0011 课讲的另一句是「深度学习先吃下匹配与检索」——那是把「认」的能力学出来。而这两篇吃的是更后面的一环：把「优化求解」整个换成网络前向。这是同一条思路（把难的手工环节换成学出来的映射）往深处又走了一步。至于它能不能对付开放世界，到今天仍然没有答案。
