Mask R-CNN（2017）：实例分割与 RoIAlign

它是整套课里在 SLAM 论文中出现频率最高的一个零件——但你只记住「它很准」是不够的。⚙️ 这一课要把两件事讲透：那条只多花了 20% 开销的第三条分支，以及那个「改一个取整符号就换回一大截精度」的算子。

本节目标

读完你应该能：① 说清实例分割与语义分割到底差在哪（一句话：要不要数个体）；② 讲出 Mask R-CNN 在 Faster R-CNN 上加的那第三条分支是什么，以及为什么掩码用 sigmoid 而不是 softmax；③ 画出 RoIPool 的取整错位与 RoIAlign 的双线性插值的区别，并说出它换回了多少精度；④ 复述 5 fps / 195 ms 这组数字，并解释 SLAM 论文为什么一边用它一边抱怨它。

1. 先分清三个词：这一课要补上的是最后一块

我们在 0190 课用「两只挨在一起的猫」把三个词摆开过一次。这里把它收口，因为恰恰是语义分割与实例分割之间的那道缝，决定了本课全部的技术细节。

  • 目标检测（0191 YOLO）：返回两个框 + 标签 cat, cat——知道有两只、知道大概在哪，但不知道边界。
  • 语义分割（0190 FCN）：返回一张图，所有属于猫的像素涂成同一色——两只连成一片，分不出个体。原文原话是语义分割 classif[ies] each pixel into a fixed set of categories without differentiating object instances。
  • 实例分割（本课 Mask R-CNN）：返回两张独立的掩码——既知边界，又知个体。

那「分得出个体」这件事，在数学上靠什么实现？靠一个非常小的改动：语义分割对每个像素做「多分类」，类别之间互相竞争（softmax，所有类概率加起来等于 1）；实例分割给每个类各出一张「是 / 否」的二值图，类别之间不竞争（sigmoid）。

这一个小解耦值多少钱？原文的消融实验给了答案：在 ResNet-50-C4 上，per-pixel softmax 是 24.8 mask AP，换成 per-pixel sigmoid 是 30.3——整整 +5.5 个点（$\mathrm{AP}_{50}$ 还多 +7.1、$\mathrm{AP}_{75}$ 多 +6.4）。原文把它当作「best 结果的关键」之一。

为什么差这么多？因为 softmax 会强行让「掩码」和「分类」两件事绑在一起互相制约——每个像素必须在 80 个类里抢一个名额，于是模型被迫在画形状的同时还要反复重新判定类别；而 sigmoid 让掩码分支只回答一个更单纯的问题：「在这个框里，属于类 k 的像素是哪些？」类别判定已经交给分类分支了，掩码不必再操心。分工一旦清楚，两边都能做得更好。

2. 第三条分支：在 Faster R-CNN 上加了什么

Mask R-CNN 的起点是 Faster R-CNN。这是它之前的实例检测标准件，结构可以一句话说完：先用 RPN（Region Proposal Network）从图上找出可能是物体的候选框，再对每个候选框取一块特征，做两件事——判它是什么类、把框往哪儿挪。也就是两条并列的输出分支。

这里要就地补三个词：

  • RPN（区域候选网络）：Faster R-CNN 用来生成候选框的小网络。它替代了 R-CNN 那一代用 Selective Search 手工生成的约 2000 个候选，直接把候选框学出来，数量 1 到 2 千。这就是 0191 课里说的「两阶段的第一道闸门」。
  • RoI（Region of Interest，感兴趣区域）：候选框在特征图上圈出来的那一块。后面的所有算子都作用在一块 RoI 上。
  • RoIPool：把大小不一的 RoI 特征块，统一压成固定尺寸（比如 7×7）的算子。因为后面的全连接层要求固定输入尺寸。这个算子就是下一节的主角。

Mask R-CNN 做的事，原文在 §3 开篇一句话就说完了：

原文的关键一句

Faster R-CNN has two outputs for each candidate object, a class label and a bounding-box offset; to this we add a third branch that outputs the object mask.

人话翻译：Faster R-CNN 对每个候选物体本来有两个输出——一个类标签、一个框偏移；我们在这之上加了第三条分支，输出物体的掩码。

这条分支长什么样？原文的描述是：它是一个作用在单个 RoI 上的小 FCN，逐像素预测，输出 $K\cdot m^2$ 维（$K$ 个类各一张 $m\times m$ 的二值掩码）。COCO 上 $K=80$、$m=28$。这个「小孩」之所以能这么简单，是因为分类的活已经被别人干完了——它只需要回答形状。

有两个细节特别值得记：

  1. 掩码用 per-pixel sigmoid + 二值交叉熵，而不是 FCN 惯用的 per-pixel softmax + 多项交叉熵。上一节已经解释过，这值 +5.5 AP。
  2. 推理时是串行的，训练时是并行的。训练时三条分支一起算；推理时先跑分类与回归、做 NMS、然后只对得分最高的 100 个框跑掩码分支。原文明确说这样做不但更快，而且更准——因为用的是「更少、更准的 RoI」。这是一个「故意不对称」的设计，很值得学。

还有一个更微妙的发现：类特定掩码与类无关掩码几乎一样好——29.7 与 30.3 mask AP。原文对它的解读是：这进一步凸显了我们方法中的分工——分类已经在别处做完了，掩码只需回答「形状」。这条正好解释了为什么第三条分支可以这么简单。

另外，掩码分支用 FCN 头（全卷积，conv 256→256→256→256→256→80）比用 MLP 头（全连接，fc 1024→1024→80·28²）高 2.1 mask AP（33.6 对 31.5）。原文的解释是：FCNs improve results as they take advantage of explicitly encoding spatial layout——能显式编码空间布局的方法更好。这句话就是 0190 课那个核心论点在两年后的直接回响：能保住空间信息的结构，就是更强。

3. ★ RoIAlign 与那一个取整符号

这一节是 Mask R-CNN 全文最漂亮的地方，也是本课篇幅最重的一节——它比「加第三条分支」更值得讲，理由有三条，每条都有原文数字撑腰：

  1. 它的增益在最苛刻的设置下高达 +7.3 mask AP、+10.5 mask AP75，是约 50% 的相对提升；
  2. 它是少见的「改一个取整符号就换回一大截精度」的案例，最适合讲「工程细节有多值钱」；
  3. 但更重要的是——SLAM 论文抱怨 Mask R-CNN 慢的时候，说的就是它。这是一个「精度很高、落地很痛」的真实摩擦。

问题出在哪：RoIPool 的两次取整

先讲清为什么会有这个问题。原文的逻辑链特别干净：掩码是像素到像素的任务，所以 RoI 特征必须与输入精确对齐。但 Faster R-CNN 在设计时根本没考虑过输入输出之间的像素级对齐——它的核心算子 RoIPool 是做粗粒度空间量化的。

具体来说，RoIPool 会做两次取整：

  1. 把 RoI 的边界坐标（一个浮点数）除以 stride 然后向下取整；
  2. 再把 RoI 切成 $m\times m$ 个 bin 时，每个 bin 的边界再取整一次。

这些取整对「判类别」无所谓——差半个像素格，人还是人。但对「画像素级掩码」是致命的：采样点整体被拽偏了，掩码边界自然对不上真实轮廓。

生活类比：你要照着原图描一幅画，但底下的格子纸和原图错开了半个格子。远看还认得出是什么，近看线条全是错的。

一句话说明 OCR 疑点（重要）：原文描述这一步时写的是 computing [x/16]，md 版本把取整符号压成了方括号，语义从「向下取整」弱化成了「取整」。按 §3 后文自证（原文写 we use x/16 instead of [x/16]、以及 removes the harsh quantization），正确的读法是向下取整 $\lfloor\cdot\rfloor$。本课一律写「向下取整」。

它的改法：不取整，直接插值

RoIAlign 的改动小到近乎可笑。原文原话是：we avoid any quantization of the RoI boundaries or bins（i.e., we use x/16 instead of ⌊x/16⌋）——RoI 的边界和 bin 都不做任何量化。然后在每个 RoI bin 内，取 4 个规则分布的采样点，用双线性插值算出这些点的精确特征值，再聚合（max 或 average）。

原文还给了一句很关键的注脚：这里用的是浮点连续坐标，不做取整。这一点对零基础读者很重要——原文把「坐标除以步长」和「不取整」用了同一个符号 x/16，容易让人误以为是个坐标变换，其实它的意思只是「保留浮点坐标」。

为了证明「对齐」才是关键，原文还专门做了一个对照实验：把另一篇工作 MNC 的 RoIWarp 也拉来比。RoIWarp 同样用了双线性重采样，但它仍然在做量化，结果效果只和 RoIPool 打平。原文由此下结论：这 demonstrating the crucial role of alignment——真正起作用的不是「插值」，而是「不对齐」这件事被修掉了。

还有一个细节能佐证这一点：RoIAlign 对聚合方式（max 还是 average）不敏感——30.2 对 30.3，几乎没差别，所以论文后面一律用 average。这说明收益全部来自「对齐」，而不是聚合方式。

为什么 stride 越大，对齐越要命？这组数字很能说明问题：在 stride 16 的骨干上，RoIAlign 带来约 +3 点提升；而在 stride 32 的骨干上，提升变成 +7.3（AP75 甚至 +10.5）。道理也不难：stride 越大，一个像素格代表的原图区域越大，取整带来的物理位移就越大。原文对这件事的总结值得直接引用：

原文的关键一句

RoIAlign largely resolves the long-standing challenge of using large-stride features for detection and segmentation.

人话翻译：RoIAlign 基本解决了「想用大 stride 特征做检测与分割」这个长期难题。也就是说，它不只是修了一个小 bug，而是把「用粗特征」这条路重新打通了——粗特征便宜，能用了就意味着整条流水线都能变快。

还有一条证据能证明「对齐」的通用性：对齐不只是分割需要，关键点检测更需要。原文的人体关键点实验里，即使在最细层 stride 只有 4 的 FPN 骨干上，RoIAlign 仍把关键点 AP 从 59.8 抬到 64.2（+4.4）。原文的原话是：keypoint detections are more sensitive to localization accuracy，所以 alignment is essential for pixel-level localization, including masks and keypoints——对齐对所有像素级定位任务都是必需的。

★ 一个 OCR 疑点，务必注意：原文 Table 2c 里 RoIPool 那一行的 align? 与 bilinear? 两列在 md 里是空白的（原表应该是两个叉）。如果照着空白读，会得出「RoIPool 也支持对齐」的结论——恰好把这张表的结论读反了。本课不依赖这张表，但提醒你回原文核对时留意。

4. 损失函数：三笔账一起算

Mask R-CNN 的损失定义得很干净——就是三笔账相加：

$$L=L_{cls}+L_{box}+L_{mask}$$

这句话在说什么：这个损失定义在每一个被采样的 RoI 上。$L_{cls}$ 是分类损失，与 Fast R-CNN 的定义完全相同；$L_{box}$ 是边框回归损失，同样与 Fast R-CNN 完全相同；$L_{mask}$ 是掩码分支的损失——掩码分支对每个 RoI 输出 $K m^2$ 维向量（$K$ 张 $m\times m$ 的二值掩码），对它施加 per-pixel sigmoid，$L_{mask}$ 就是平均二值交叉熵。

它为什么这么算：一个 RoI 要算三笔账——它是什么类（$L_{cls}$）、它的框该往哪儿挪（$L_{box}$）、它的像素轮廓长什么样（$L_{mask}$），三笔相加一起反传。三笔里掩码那笔有个特殊规则：只在 RoI 被判为正样本（与真值框 IoU 大于等于 0.5）时才存在，而且只在你答对的那个类上收账。

数字账：COCO 上 $K=80$、$m=28$，所以每个 RoI 的掩码分支要吐出 $80\times 28^2 = 62720$ 个数；但对一个真值类为 $k$ 的 RoI，其中只有 1 张（第 $k$ 张）参与损失计算，另外 79 张的输出完全不产生任何损失。这也是「类之间不竞争」在损失层面的具体表现。

掩码的真值怎么定义？原文一句：The mask target is the intersection between an RoI and its associated ground-truth mask.——掩码真值就是「这个 RoI」与「它对应的真值掩码」的交集。也就是说，掩码分支学的不是「整只猫的形状」，而是「框内那一块猫的形状」。

最后再放一次那段最关键的对比，原文原句：

原文的关键一句

This is different from common practice when applying FCNs to semantic segmentation, which typically uses a per-pixel softmax and a multinomial cross-entropy loss. In that case, masks across classes compete; in our case, with a per-pixel sigmoid and a binary loss, they do not.

人话翻译：把 FCN 用在语义分割上的常见做法是 per-pixel softmax + 多项交叉熵，那样类与类的掩码是互相竞争的；我们用 per-pixel sigmoid + 二值损失，它们不竞争。

这句话为什么值 5.5 个 AP？因为竞争意味着「一个像素只能属于一个类」。在真实场景里，一个像素确实只属于一个物体，所以竞争听起来合理——但问题在于：模型此时还得顺带重新做一遍分类判断。一旦分类判断出错，掩码也跟着错，两个错误互相放大。解耦之后，掩码分支只需要回答一个纯粹的形状问题，两个任务各干各的，都做得更好。

5. 关键数字与「它不完美在哪」

先把成绩单摆出来，再讲它落地时的真实摩擦——后者才是 SLAM 读者最该记住的部分。

精度（COCO test-dev，mask AP）

ResNet-101-C4 33.1 → ResNet-101-FPN 35.7 → ResNeXt-101-FPN 37.1。对手：MNC（COCO 2015 冠军）24.6；FCIS+OHEM（COCO 2016 冠军）29.2；FCIS+++（带多尺度 + 翻转 + OHEM）33.6——被 35.7 的无技巧版直接超过。

速度（★ 本节最重要）

5 fps / 约 200 ms 每帧。ResNet-101-FPN 共享特征版 195 ms/图（Nvidia Tesla M40）+ 15 ms CPU 后处理；ResNet-101-C4 版要 400 ms——原文因此「不建议在实践中用 C4 变体」。掩码分支相对 Faster R-CNN 只增加约 20% 开销。

掩码解耦的收益

per-pixel softmax 24.8 → sigmoid 30.3（ResNet-50-C4），+5.5 mask AP。

RoIAlign 的收益

stride 16：26.9 → 30.3；stride 32：23.6 → 30.9（+7.3），AP75 21.6 → 32.1（+10.5）。摘要写作「improves mask accuracy by relative 10% to 50%」。

掩码头：FCN 还是 MLP

FCN 头 33.6 对 MLP 头 31.5，高 2.1。原文理由：能显式编码空间布局的方法更好——这正是 0190 课那个论点的回响。

采样与规模

IoU 大于等于 0.5 的 RoI 为正样本，正负比 1:3；每图 RoI 数 N = 64（C4）或 512（FPN）；推理用 300（C4）/ 1000（FPN）个候选，掩码只跑得分最高的 100 个框，阈值 0.5 二值化。训练 8 GPU、等效 minibatch 16、160k 迭代。

它不完美在哪（一）：慢，而且是被 SLAM 论文点名地慢

这是本课最需要读者带走的一条。195 ms 一张图就意味着约 5 fps，而 SLAM 要实时。语料库里的抱怨都很直接：

  • 2022_RGB-D_SLAM_in_Dynamic 的原话：state-of-the-art segmentation methods such as Mask R-CNN are still computationally intensive and often have to be run in a background thread in practice to amortize their cost over several frames——得分摊到好几帧上才跑得动。
  • MaskFusion（2018）把这件事写进了它的设计动机：当前的 SOTA 方法 Mask-RCNN 无法在帧率下运行。
  • MID-Fusion（2019）的做法是干脆把它放到离线 / 后台线程里预计算，用公开权重、不微调。
  • DynaSLAM（2018）引了一手数字：He 等报告 Mask R-CNN 在 Nvidia Tesla M40 上每张图 195 ms，并据此自承自己的系统「不面向实时操作优化」。

它不完美在哪（二）：边界不精，而且会「看不见」某些可移动物体

  • MaskFusion 的第一条观察就是：当前的分割方法擅长发现物体，但倾向于给出不完美的物体边界（tend to provide imperfect object boundaries）。注意这是「拿它当零件用」的一手证据，比任何二手评价都可靠。
  • EM-Fusion（2019）也说：虽然前景概率提供了分割线索，但它不足以支撑鲁棒跟踪，因为 Mask R-CNN 的实例分割并不精确。
  • PanopticFusion（2019）指出另一类问题：当物体只有一小部分可见时，Mask R-CNN 给出的类别标签常常不确定——即使掩码本身是准的。
  • DynaSLAM 自己承认的能力边界最值得记：there are objects that cannot be detected by this approach because they are not a priori dynamic, but movable——有些物体检测不到，因为它们「不是先验动态的，但是可移动的」（比如被人拿着的书、被推动的椅子）。这一条直接引出了它后面的多视图几何第二级筛选。

把这四条放在一起看，本季那条暗线就非常清楚了：Mask R-CNN 是一个很强的零件，但它慢、边界不精、还会漏掉「可移动但非典型动态」的东西。所以 SLAM 论文的做法从来不是「信它就好」，而是语义给先验、几何做裁判——这正是下一节要详细对账的内容。

再说一句作者自己的诚实之处：原文明确写了 our design is not optimized for speed，还说更好的速度精度折中「超出了本文范围」；同时承认 RPN 默认与 Mask R-CNN 不共享特征；多任务也并非全部互惠——加关键点分支会略微拉低 box / mask AP，原文说 while keypoint detection benefits from multitask training, it does not in turn help the other tasks。这些自述的「不」，恰恰是它可信的原因。

6. 和前面课程怎么接：这个零件在前八季出现过的地方

Mask R-CNN 是本组被引用最多的一篇，没有之一——语料库里 grep 它命中 18 个真实论文文档，其中至少 8 篇 SLAM / SLAM 相关论文把它当作核心组件。而它的主战场就是第八季 0153–0159 动态环境块。

先说清那一块的问题意识：SLAM 的默认假设是「场景是静止的」，而现实里有人有车。动态物体的特征点会被当成静态地标参与匹配，把轨迹带歪。所以大家都要在系统里加一个「把会动的东西找出来并剔掉」的环节。而它们找东西用的零件，就是 Mask R-CNN。

2018_DynaSLAM —— 最经典的「用 Mask R-CNN 剔人」范式

原文：我们实验里用的是 Mask R-CNN，它是物体实例分割的 SOTA。Mask R-CNN 能同时得到逐像素的语义分割与实例标签；本工作用的是逐像素语义分割信息，而实例标签在未来可以用来跟踪不同的运动物体。它的做法是分割那 19 类「潜在动态或可移动」的物体（人、自行车、车、摩托车、飞机、公交、火车、卡车、船、鸟、猫、狗、马、羊、牛、象、熊、斑马、长颈鹿）。它引的耗时依据就是 195 ms/图，并据此自承系统不是为实时优化的。

2018_MaskFusion —— 改用实例级掩码，并说出它的毛病

原文：MaskFusion 充分利用实例级语义分割，把语义标签融进一个 object-aware map——不像此前那些做体素级语义分割的语义 SLAM 系统。它的设计动机里有三条观察，其中两条是在说零件：(i) 当前分割方法擅长检测物体，但倾向于给出不完美的物体边界；(ii) 当前的 SOTA 方法 Mask-RCNN 无法在帧率下运行。

2019_MID-Fusion / 2019_EM-Fusion

MID-Fusion 把 Mask R-CNN 预计算在 GPU 上（用公开权重、不微调），每个物体存进各自的八叉树体素模型；图注写着「移动的人因 Mask R-CNN 的语义标注被剔除」。EM-Fusion 更直接：前景概率不足以支撑鲁棒跟踪，因为 Mask R-CNN 的实例分割并不精确——它把零件的不精确当成了方法设计的动机。

2023_SG-SLAM —— 一段把家谱捋清楚的原文

原文一口气列了四条：Bescos 等用 Mask R-CNN 的语义分割结果 + 多视图几何来检测动态物体并剔除外点；Yu 等用光流做运动一致性检查，同时用 SegNet 在独立线程里做语义分割；Wu 等用 YOLO 检测先验动态物体；Chang 等用 YOLACT 分割动态物体。一句话把 0190、0191、0192 三个零件全串起来了。

2022_WF-SLAM —— 把内部结构讲得最完整的一段

原文：WF-SLAM 首先采用在 MS COCO 上训练好的 Mask R-CNN 做语义分割生成掩码；Mask R-CNN 的网络结构是在 Faster-RCNN 与 FCN 基础上改进的……它在每个 ROI 上加一条掩码预测分支，扩展了 Faster-RCNN；这条新分支与原有的分类分支和边框回归分支并列；掩码分支本质上就是一个小小的、做逐像素掩码预测的 FCN 网络。这段话几乎就是本课前三节的现成教材。

2023_DGM-VINS / 2022_Accurate_Dynamic_SLAM

DGM-VINS 把 Mask R-CNN 当作精度 / 速度基线，自己改用条件卷积的实例分割网络；2022_Accurate_Dynamic_SLAM 明确写「像 MaskFusion 那样，我们用 Mask R-CNN 预测的掩码识别动态区域，例如人」。它们共同说明：在动态 SLAM 这个子领域里，「实例分割」几乎就等于 Mask R-CNN。

把这些引用串起来，可以看到一个很清楚的结构：DynaSLAM 是第一代范式（语义掩码剔除 → 多视图几何把关），MaskFusion / MID-Fusion / EM-Fusion 是第二代（走向实例级、走向 object-aware map），而它们全都在同一个瓶口上卡住——慢和不精。

这也回答了本课开头提出的那个问题：为什么 SLAM 论文一边大量使用它、一边抱怨它？因为 195 ms/图这道门槛是硬的。SLAM 要 30 fps，它只给 5 fps，中间差了六倍。所以你会看到各种绕法——放后台线程、隔帧跑、预计算、或者干脆退回到更快的检测方案（这正是 0191 课里 SG-SLAM 的选择）。

再往上看一层。第八季那些「语义 + 几何双保险」的设计，正是被本课这个零件的缺陷逼出来的：

  • 因为边界不精（MaskFusion 的原话），所以不能只用掩码剔点，要用多视图几何再筛一遍；
  • 因为看不见「可移动但非先验动态」的物体（DynaSLAM 的原话），所以必须有第二级基于几何的筛选；
  • 因为标签会不确定（PanopticFusion 的原话），所以标签要按概率融合，而不是硬赋值；
  • 因为跑不到帧率（MaskFusion 与 2022_RGB-D_SLAM_in_Dynamic 的原话），所以要放后台、要分摊、要降频。

零件不完美，所以 SLAM 要加几何约束。这句话在 Mask R-CNN 上体现得最完整——它是本季与第八季最重要的连接点。

最后回指一条横向纪律：第九季 0180 提醒「看到轨迹误差，先问真值有多准」。检测与分割这边对应的提醒是：看到 mask AP，先问是 AP50 还是 AP75。它在本课尤其有用——RoIAlign 的收益恰好主要体现在更严的 AP75 上（+10.5 对 +7.3）。因为 AP75 要求预测框与真值框的 IoU 达到 0.75 才算对，「边界画得准不准」在这个指标里被放大了。看不懂这一点，就看不出「对齐」为什么值那么多钱。

课后练习

  1. 用「两只挨着的猫」讲清三个词，并指出实例分割是靠哪一行数学设置把「个体」保下来的。
    展开查看答案
    目标检测：返回两个框加 cat 标签，知道有两只、知道大概在哪，但不知道边界。语义分割：所有猫像素涂同一色，两只连成一片，不区分个体。实例分割：返回两张独立掩码，既知边界又知个体。保下个体靠的是掩码用 per-pixel sigmoid + 二值交叉熵（每类各出一张二值图，类与类不竞争），而不是语义分割惯用的 per-pixel softmax + 多项交叉熵（类间竞争）。这一行差别在 ResNet-50-C4 上值 +5.5 mask AP（24.8 到 30.3）。
  2. RoIPool 与 RoIAlign 的区别，能不能简化成「一个准一个不准」？为什么不能？
    展开查看答案
    不能——那样就丢掉了机制。真实的区别是：RoIPool 对 RoI 边界除以 stride 后向下取整，切 bin 时再取整一次，采样点因此整体被拽偏；RoIAlign 不做任何量化（保留浮点坐标），在每个 bin 内取 4 个规则采样点用双线性插值算出精确值再聚合。原文特意用 MNC 的 RoIWarp 做对照：RoIWarp 也用了双线性重采样，但仍在量化，结果只和 RoIPool 打平——这就证明了起作用的是「对齐」，不是「插值」。另外 RoIAlign 对 max / average 聚合不敏感（30.2 对 30.3），也说明收益全部来自对齐。
  3. 某 SLAM 系统用「Mask R-CNN 检测到的 19 类潜在动态物体」直接剔除特征点。请指出至少两处会出错的地方，并各给一条对策。
    展开查看答案
    出错点一：掩码边界不精（MaskFusion 原话：tend to provide imperfect object boundaries），所以掩码内会混进静态背景点、掩码外会漏掉动态点 → 对策：加多视图几何一致性检查（DynaSLAM 的做法），让几何做裁判。
    出错点二：看不见「非先验动态但可移动」的物体（DynaSLAM 原话：not a priori dynamic, but movable，如被人拿着的书、被推动的椅子）→ 对策：同样靠第二级几何筛选补上，而不是靠扩大类别表。
    （还可补：跑不到帧率，195 ms/图约 5 fps，对策是后台线程 / 隔帧 / 预计算。）
  4. 为什么可以说 RoIAlign「不只是修了一个小 bug」？请从「大 stride 特征」的角度回答。
    展开查看答案
    因为 stride 越大，一个特征图像素格代表的原图区域越大，取整造成的物理位移也越大。数据上：stride 16 时 RoIAlign 提升约 +3 点，stride 32 时提升 +7.3（AP75 甚至 +10.5）。而大 stride 特征意味着更便宜、更快的骨干。原文因此总结：RoIAlign largely resolves the long-standing challenge of using large-stride features for detection and segmentation——它把「用粗特征」这条路重新打通了，所以不只是修 bug，而是打开了一条更便宜的路。
  5. 本课提到一条 OCR 疑点：Table 2c 里 RoIPool 行的两列是空白。如果照着空白读，会得出什么错误结论？
    展开查看答案
    那两列是 align? 与 bilinear?，原文应为两个叉（表示 RoIPool 既不支持对齐、也不用双线性）。若照着空白读，会误以为「RoIPool 也支持对齐」，从而得出「RoIAlign 和 RoIPool 差别不大」的结论——恰好把这张表的结论读反了。这与 0193 课里「Table 2 行列错位」是同一类问题：md 抽取的表格不可全信，关键结论要回正文或原 PDF 核对。
