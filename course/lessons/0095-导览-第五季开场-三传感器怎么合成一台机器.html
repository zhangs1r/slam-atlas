第五季开场：三种传感器怎么合成一台机器

前四季我们把视觉、激光、惯性各自拆开看过一遍了；这一季要干的是一件更实在的事——把它们装进同一台机器里 🎛️

本节目标

读完这一节，你应该能说清：为什么要把三种传感器放在一起（各自的短板正好互补）、融合有哪两种根本不同的哲学、以及这一季要沿着哪几条线索读。

和前面课程怎么接

这一季是前三季的合流：第三季 0057／0058 的 VINS-Mono 做的是「视觉 + 惯性」，第四季 0078 的 LIO-SAM 做的是「激光 + 惯性」——本季把第三条腿（剩下的那个传感器）接上去。

1. 前三季留下了什么，这一季要接什么

先看一眼我们走过的路，你会明白为什么「融合」是必然的下一步。

第三季（视觉主干）讲透了一台视觉 SLAM 能有多精巧：从 ORB-SLAM 的三线程，到 DSO 的光度标定，再到 VINS-Mono 把 IMU 拉进优化。但视觉有一个它自己解决不了的老问题——单目没有尺度。第 0024／0025 课就说过：单目只有「方向」信息，尺度不可观。整季下来，我们看到大家用了六种办法去绕它（回顾第 0040 课那张「尺度暗线六站」的图）。

第四季（激光主干）换了个传感器，麻烦一下子少了一半：激光雷达直接给你三维点，尺度天然是真的、深度不用猜。可它也带来了两个新麻烦——一帧扫描要花时间（所以要做运动畸变补偿），以及点太多而且地图一直在长（于是有了 ikd-Tree 那一整套）。而且激光在几何退化的地方会失灵：一条笔直均匀的长走廊、一片开阔得只有海面和天空的地方，激光「看不出自己动没动」（第 0076／0084 课）。

看出来了吗？视觉的短板正好是激光的长处，激光的短板又正好是视觉的长处。这不是巧合——在讲「融合」的论文里，这句话几乎是所有作者的写作动机。

而 IMU 是第三个角色：它高频（几百赫兹）、短期极准，能补上「相机和雷达都太慢」的那一段；但它单独跑会漂，需要别人替它定住长期基准。

三者拼在一起，正好各补一块。这一季要读的 9 篇，就是这件事的九种做法。

2. 三个传感器各擅长什么、各怕什么

在讨论「怎么融合」之前，先把三个角色的「性格」记牢——因为它们的所有设计取舍，都是在回避各自的弱点。

把这三张卡片放在一起，你会发现一件很舒服的事：它们的短板几乎不重叠。

视觉撑不住的地方

黑暗、白墙、光照突变 → 激光不受光照影响，几何退化时也还能提供点（虽然此时点约束变弱）。

激光撑不住的地方

长走廊、笔直隧道、开阔地 → 只要墙上有纹理，视觉就能靠外观把位移认出来。

两者都撑不住的地方

剧烈运动、快速旋转 → IMU 几百赫兹的高频信息正好补这一段。

当然，现实没有这么理想。融合系统真正要解决的，是「把三种不同频率、不同噪声特性、甚至不同时间戳的数据，写进同一个估计问题里」——这句话说起来轻巧，本季 9 篇论文全都在解它。

4. 一条最长的暗线：地图里到底存什么

这是本项目从第二季一路铺到现在的一条线索，而它在这一季走到了最有意思的两步。

想想看：SLAM 建出来的「地图」，到底是一堆什么东西？这个问题的答案，几乎每两三年就会换一次。

课次 地图里存什么 为什么这么选
第二季 0033
KinectFusion		 每个体素存一个标量（到最近表面的截断距离） 表面就是「距离为零」的那层，可以直接用 raycasting 找出深度
第二季 0034
Voxel Hashing		 只给表面附近的体素块分配内存，用哈希表找 稠密网格内存随体积的三次方爆炸，而表面只占极少一部分
第四季 0084
FAST-LIO2		 存点，但用一棵能做增量插入/删除的树（ikd-Tree）管起来 地图一直在长，静态 k-d 树每次更新都要重建，撑不住
本季 0100
FAST-LIVO2		 每个体素存的不是点，而是一块拟合好的平面（中心 + 法向 + 统计量） 视觉可以直接拿这块平面当几何约束——深度不用自己估了
本季 0098
LIV-GaussMap		 存一组椭球高斯（位置 + 形状 + 颜色 + 透明度） 地图本身就能直接渲染——不需要先提取表面再画

看出来这个趋势了吗？地图的存储单元一路在「变厚」：从「一个数字」（距离），到「一个点」，到「一块平面」，最后到「一坨可以画出来的体积」。

每变厚一次，都是因为下游要用它的人变多了：一开始只有「找最近点」要用（所以存点就够）；后来视觉也想用它（所以存平面，视觉拿去就能算光度误差）；再后来渲染器也想用它（所以干脆存成可画的高斯）。

5. 建图与渲染的合流

接着上面那条线索往下想一步，你会撞上本季另一个很漂亮的转折。

回忆一下：第一季第 0015 课讲 3D 高斯泼溅时，我们强调过一个词——显式 vs 隐式。当时 NeRF 那种「把场景塞进网络权重」的做法被叫做隐式，3D 高斯那种「直接存几何图元」的做法被叫做显式。到了第二季 0036–0039，我们又把 NeRF → Instant NGP → Plenoxels 这条加速路线走了一遍。第三季 0071 讲了神经隐式怎么接进 SLAM。

但那些工作有一个共同点：它们是「离线重建」或「用图像重建」——输入是一堆照片，输出是一个可以慢慢优化出来的场景。

这一季的 0097 和 0098 把这件事翻了过来：它们在做 SLAM 的同时，直接长出一张能被渲染的地图。而且因为多了激光这一路，几何是白送的——不用像 3DGS 那样从稀疏点云和光度梯度里慢慢「猜」出来。

换句话说：「建图」和「渲染」这两件事，在这一季合流了。以前你得先建好地图、再想办法把它画出来；现在地图本身就是画得出来的东西。

6. 看不见的地基：时间同步、外参、退化

前面讲的都是「算法」。但融合系统真正让人头疼的，往往是那些不写在标题里的东西。

本季最后两节课（0102、0103）专门讲这件事。它们提醒我们三件容易被忽略的事实：

① 时间是三个层次的问题

硬件触发同步 → 在线估计时间偏移（第三季 0057 VINS-Mono 里那个 $t_d$ 就是干这个的）→ 外参标定。任何一层出问题，融合都会变成「两根错位的绳子硬拧在一起」。

② 外参不是出厂量一次就完事

震动、温度、安装误差都会让它漂。0103 那篇干脆把外参当成一个待估变量，一边跑一边标——而且要靠「车动起来、转个弯」才能标得准（这叫可观性）。

③ 退化是融合最该发光的地方

第四季 0076 讲过一个数字：一条 200 米的隧道里，纯激光的位移误差高达 56%。融合的价值恰恰在退化时才真正体现出来。

这也是为什么本季要读一篇数据集论文（0102 里的 FusionPortable）：融合系统的失败常常来自同步与标定，而这些问题只有带真值的多传感器数据才能客观暴露出来。这一点和第一季 0009 课讲的 DARPA 地下挑战赛是同一个道理——「在实验室能跑」和「在真实系统里能跑」之间隔着一整个工程量级。

另外说明两件关于素材的事，免得你读的时候困惑：

  • 0102 里的 AdaFusion，它的真实用途是地点识别（place recognition）——也就是「我是不是来过这儿」，而不是估计位姿。路线图把它标成了「注意力式融合网络」，没说清用途，课里会写明这个差别。
  • 0103 里的那篇，题目里的「多传感器」其实是多台同一种传感器（多激光雷达），不是「激光 + 视觉 + 惯性」。它的价值和这一季仍然一致：把「传感器之间的未知关系」当成待估变量——这和异源融合是同一类难题。

8. 怎么读这一季（三种读法）

速览型（约 2 小时）

只读 0095（本节）+ 0100（FAST-LIVO2）+ 0103（收官）。抓住「两种融合哲学」和「地图里存什么」两条线就够了。

系统型（约 6 小时）

按顺序读 0096 → 0103。这是本季的推荐路径：第一组建立直观，第二组啃硬骨头，第三组理解工程。

研究型（约 12 小时）

额外做两件事：① 把 0096（并行）与 0100（统一）做一次逐条对比；② 读 0098 时回头翻第一季 0015（3D 高斯），问自己「多一路激光，到底改变了什么」。

读完这一季，你应该能回答

  1. 为什么说「融合的价值在退化时才真正体现」？举一个激光退化、视觉能救场的场景。
  2. 同样是紧耦合，「两条流水线并行」和「统一状态统一地图」分别是什么意思？各举一篇。
  3. 「地图里存平面」相比「存点」，给视觉带来了什么便利？
  4. 为什么说「建图与渲染在这一季合流了」？这条线和第一季的 3D 高斯是什么关系？
  5. 为什么车必须「动起来、转个弯」，多雷达的外参才标得准？

课后练习

  1. 用「三句话」向一个刚学完第四季的人介绍这一季在干什么。
    展开查看答案

    参考答案（三句话）：

    ① 第四季把激光 + 惯性做好了、第三季把视觉 + 惯性做好了，这一季把第三条腿接上——三种传感器合成一台机器。

    ② 三者的盲区几乎不重叠，所以互补不是「多加保险」而是真的各补一块：激光怕退化、相机怕黑暗与无纹理、两者都怕剧烈运动，而 IMU 正好补最后那块。

    ③ 融合有两种哲学——「两条流水线并行、末端合流」（R³LIVE）与「统一状态、统一地图」（FAST-LIVO 系）；而这一季还顺带把「地图里存什么」这条从第二季铺过来的暗线推到了「存平面」和「存高斯」。

  2. 下面这个说法哪里不对：「既然是融合，那当然是把三个传感器的结果都算出来再平均一下最稳。」
    展开查看答案

    那是松耦合，而且是松耦合里最粗糙的一种。问题出在「再平均一下」：

    ① 三个结果不独立——它们描述的是同一个位姿，而且往往用了同一批数据，直接平均会把同一份信息重复计算，导致「过度自信」（第四季 0061 课 OpenVINS 讲的「一致性」问题就是这个）。

    ② 权重没法固定——黑夜里视觉结果不能信，长走廊里激光结果不能信。平均意味着你事先得知道谁可信，可这恰恰是你不知道的。

    ③ 真正的紧耦合是把三种原始测量（像素、点、加速度）放进同一个待估问题，让优化自己决定各自该有多重——这正是本季 0099／0100 在做的事。

  3. 回看「地图里存什么」那张表（第二季 0033 → 本季 0098），解释为什么存储单元会一路「变厚」。
    展开查看答案

    因为用它的人变多了：

    ① 最初只有「找最近点/求距离」要用 → 存一个标量（TSDF）或一个点（ikd-Tree 里的点）就够；

    ② 后来视觉也要用它当几何约束 → 存点不够了，因为视觉需要的是「表面在哪、朝哪边」，于是拟合成平面（0100）；

    ③ 再后来渲染器要用它 → 平面也不够，因为渲染需要颜色、透明度、方向相关性，于是干脆存成高斯（0098）。

    所以这张表的每一行，背后都是「下游需求推动存储形式升级」，而不是单纯的算法炫技。

  4. 如果只能给这个系统加一个「免费」的改进（不加硬件、不改算法），你会加什么？为什么？
    展开查看答案

    参考答案：把时间同步做扎实（硬件触发 + 在线估计残余时偏）。

    理由：本季最后两课（0102 的数据集、0103 的外参标定）都在暗示同一件事——融合系统的失败很少来自「算法不够聪明」，多半来自「数据对不齐」。时间错几毫秒，在高速运动下就等于把两个传感器的观测放到了两个不同的位姿上，这时再好的优化器也只能去拟合一个互相矛盾的方程组。

    这也解释了为什么第三季 0057 课要专门花一节讲 VINS-Mono 的在线时偏估计——那个 $t_d$ 看起来不起眼，却是整条链路的地基。
