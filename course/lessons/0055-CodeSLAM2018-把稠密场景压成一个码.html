和前面课程怎么接

1. 这一节要回答什么

先把上一篇留下的问题复述清楚。滑块 SLAM（dense SLAM）想要一张完整的深度图——每个像素都有深度值，这样才能做遮挡判断、做 AR 的物理交互、做出好看的重建。但它有个根本困难：

假设你的深度图是 $640\times480$，那就是 30 多万个未知数。如果你把每个像素的深度当成一个独立的待优化变量塞进位姿和深度一起优化，会发生两件事：问题太欠定（30 万个未知数却只有几十万个观测）、算不动。所以过去所有稠密方法都不得不做近似。

原文在引言里把这件事的后果说得很清楚（第 13 行）：主流 SLAM 因此分裂成两派——

稀疏派（sparse SLAM）

用少量特征点表示几何。好处是可以严格做联合概率推断（位姿和结构一起估，还知道它们之间怎么相关）；坏处是地图残缺，原文说它「cannot be used in interactive robotics tasks or advanced augmented reality applications」

稠密/半稠密派（dense / semi-dense）

追求几何完整。代价是放弃严格推断——「discarding variable cross-correlations and alternating between tracking and mapping」，也就是把互相关丢掉，位姿和地图只好轮流优化

所以这一节的命题就是：能不能有一种表示，既保持稠密，又只有很少的参数，从而重新拿回「联合优化」的能力？

2. 打掉一个前提：「稠密」不等于「参数多」

上面那个「30 万未知数」的推论其实藏着一条假设：每个像素的深度是彼此独立的。原文 1 节直接把这个假设挑出来质疑，而且理由很朴素：

「自然场景的几何并不是一团随机分布的占据与非占据空间，而是呈现出高度的秩序。」（原文：the geometry of natural scenes is not a random collection of occupied and unoccupied space but exhibits a high degree of order）

它的意思可以用日常经验来理解——你看一张室内照片，桌面的深度、墙面的深度、地面的深度都不是逐像素乱跳的，而是成片地、有规律地变化。既然如此，为什么要给每个像素都配一个独立的未知数？

原文顺势给出了一个更理想化的图景：如果一个场景能被分解成「一组语义物体（比如一把椅子）+ 每个物体的内部参数（椅子大小、几条腿）+ 一个位姿」，那么表示它需要的参数会少到难以置信——这是 SLAM++ 那类「物体级 SLAM」指的方向。

但作者随后就承认了这条路的边界：这种人工设计的稠密抽象「are limited in the fraction of natural, cluttered scenes which they can represent」——真实世界太杂乱，你没法事先给所有东西都设计好参数模型。

于是这篇的核心思路就浮出来了

不去手工设计几何抽象，而是让网络自己学出一个：训练一个自编码器（autoencoder），把深度图压进一个低维瓶颈，让网络自己去找「该怎么用少量数字描述一张深度图」。这就是 code。

3. 核心：把深度图压成一串数字

先把符号写出来，它简单到只有一行（原文式 1）：

$$D = D(I, \mathbf{c})$$

读法：深度图 $D$ 是图像 $I$ 和一个「码」$\mathbf{c}$ 的函数。给定一张图像和一小串数字，解码器就吐出整张稠密深度图。

这个式子里最值得注意的是 $I$ 的位置。如果你做一个「朴素」的自编码器——输入深度图、输出深度图——瓶颈会把细节全部滤掉，重建出来的深度是糊的。下面这张就是原文拿出来的反面教材：

作者的破解办法，是这篇论文最关键的一个想法：把图像强度作为条件喂进去（intensity-conditioned），于是 code 只需要承担「图像预测不出来的那部分信息」。原文说得极明白：

「我们不需要编码完整的深度信息，只需要保留那些无法从图像强度中恢复的部分。」（原文：We do not need to encode the full depth information, but only need to retain the part of the information which cannot be retrieved from the intensities.）

原文还有一句很漂亮的比喻：图像提供局部细节，code 提供更全局的形状参数（"the image providing local details and the code as supplying more global shape parameters"）。而且作者特意强调，这些「全局形状参数」不是人工设计的几何变换，而是学出来的、倾向于对应场景里的语义实体——用原文的话，这可以看作「a step towards enabling optimisation in general semantic space」。

原文还做了一个很有意思的观察（5.1 节）：把「深度对 code 各维的偏导」画出来后发现，code 的每一项似乎对应图像上的特定区域，而且在某种程度上尊重图像给出的边界。原文也老实承认这些区域「seem to be slightly fragmented」（略显破碎），并提醒最终的还原「always be a linear combination of the effect of all code entries」——是全部项合起来起作用的，不能孤立地读某一维。

4. 网络长什么样，以及那个关键取舍

网络结构本身是「U-Net + 变分自编码器」的组合，理解到这个程度就够用了：

上半：U-Net 提特征

把输入图像分解成一堆卷积特征。有下采样也有带跳连的上采样

下半：VAE 学 code

标准变分自编码器，中间嵌两个全连接层（各 512 个输出通道）作为瓶颈，然后从高斯分布里采样出 code

条件化：拼接

把上半那套图像特征按对应分辨率拼到下半的编解码器里——这就是「conditioned on intensity」的实现方式，没有更玄的东西

这里要替一个常见误解正名：「两个 512 通道的全连接层」说的是瓶颈层的宽度，不是 code 的维度。原文 5.1 节明确写了参考配置：code size = 128。这个数字是怎么定的？原文和图 5 给了答案：

一个细节：它预测的是「均值 + 不确定度」

原文不是直接回归深度值，而是预测每个像素的均值 $\mu$ 和不确定度 $b$。为什么？论文给出的理由很实用——「允许网络减弱困难区域的代价，从而把注意力集中在能被很好解释的部分」。它的损失函数用的是拉普拉斯分布的负对数似然（原文式 2、3）：

$$-\log p(\tilde{d}\mid \mu,b) = \frac{|\tilde{d}-\mu|}{b} + \log(b)$$

注意这里是 Laplace（拉普拉斯）分布，不是 Gaussian（高斯）。原文的理由是 Laplace 的尾巴更重。这个 $b$ 还有第二个用途：测试时用来衡量重建的可靠程度——也就是同一套「不确定度」思想（0054 的融合也在用），从深度预测一直贯穿到后面的优化。

5. 为什么偏偏要一个线性解码器

这一节讲的是原文里我认为最容易被读者跳过、但实际最「工程师」的一段。原文 2.1 节提到，他们专门为深度解码器使用了恒等激活（identity activation）以避免非线性；为了弥补这带来的表达力损失，又加了一个巧妙的补丁——把每一处拼接从 $[L_1, L_2]$ 改成 $[L_1, L_2, L_1\odot L_2]$（多一维逐元素乘积），这样图像对 code 的影响仍然保留。

为什么非要做这个看起来很别扭的设计？答案在 3 节末尾，原文给得很直接：深度对 code 的偏导 $\partial D_A[\mathbf{u}]/\partial \mathbf{c}_A$ 会「involve many convolutions」，因此算一次最多要 1 秒；而如果解码器是线性的，这一项就可以预先算好，于是雅可比的求值被大幅加速。

互动判断

假设有人觉得「非线性激活能增强表达力，为什么不给深度解码器也加上 ReLU」？按原文的取舍逻辑，这么做最主要的代价是什么？

原文还顺手做了一件很「讲究」的事：它把深度用一种自创的参数化表示——叫 proximity（式 4）：

$$p = \frac{a}{d + a}$$

其中 $a$ 是一个平均深度值。这个式子的妙处是它在近处像普通深度、在远处像逆深度：

原文特意指出这个参数化「differentiable and better relates to the actual observable quantity」，并明确说它参照了逆深度参数化。这条线索其实一直在第三季里出现：0046 DTAM 用逆深度是因为「在逆深度上均匀采样等于在极线上均匀采样」，0047 LSD-SLAM 的深度分布也是建在逆深度坐标上，本节又是同一族思想——因为可观测的是视差，而视差和逆深度成正比。

6. 它怎么进 SLAM：三个环节

有了「深度 = 图像 + 一小串数」这个表示，剩下的就是把经典的 SLAM 套路接上去。

具体的三个误差项，原文写得很干净（式 13、14）：

$$E_{\mathrm{pho}} = L_p\big(I_A[\mathbf{u}] - I_B[\mathbf{w}(\mathbf{u},\mathbf{c}_A,\mathbf{T}_A^B)]\big),\qquad E_{\mathrm{geo}} = L_g\big(D_A[\mathbf{u}] - D_B[\mathbf{w}(\mathbf{u},\mathbf{c}_A,\mathbf{T}_A^B)]\big)$$

第一条是光度误差：A 图的某个像素和「它投影到 B 图上的那个像素」灰度应该一样。第二条是几何误差：A 图某像素的深度和「投影到 B 图位置上的深度」应该一致。两条都在说「同一块表面，从两个角度看应该自洽」，只是分别在「灰度」和「深度」这两个量上度量。

$L_p$ 和 $L_g$ 这两个损失函数承担的功能原文列了五条：屏蔽无效对应、给光度与几何项做相对加权、施加 Huber 加权、对强倾斜表面降权、以及对可能被遮挡的像素降权（只有 $L_p$ 有这一项）。最后用阻尼高斯牛顿求解，变量是所有帧的 code 和位姿。

6.1 一个小而漂亮的技巧：zero code

因为变分自编码器的潜在损失里用了 KL 散度做正则，「全零的 code」就对应一张「对这张图像来说最可能」的深度图（也就是 $D(I,\mathbf{0})$）。原文利用这一点，把它当成了初始化的默认值——不需要额外的先验就能起手。

另外有个细节值得注意：训练时网络输出的不是原始深度值，而是 proximity 值，深度金字塔有四层，每层权重按「像素数变少」放大 4 倍（这一条我们已经在上面 proximity 那节看过它的意义）。

6.2 系统循环：一个「初步但完整」的 SLAM

初始化

取两张图像，联合优化它们的相对位姿与各自的 code（这就是上面那套 N 帧 SfM）

跟踪

把当前帧与上一个关键帧配对，最小化代价得到相对位姿。注意这里不加入几何项——因为当前帧还没有深度图（只有个粗略猜测）。原文还做了由粗到细：先在低分辨率深度图上对齐

建图与边缘化

攒够基线就新增关键帧并做全局优化；关键帧数达到上限时，把旧关键帧边缘化掉，换来对剩余关键帧的一个线性先验。原文报告：4 关键帧的配置下地图更新率 5 Hz

那个「边缘化 → 线性先验」的操作，正是你在第二季 0032 与 0049 VI-DSO 学过的 Schur 补。原文也明确承认这个系统是「inspired by PTAM」（本季 0042 讲过的双线程架构），而且自己定位为「a preliminary system」——初步系统，这个自我评价很重要，下一节 DeepFactors 的两条主要补丁就是从这儿来的。

7. 实验，以及三件必须说清的事

7.1 一个漂亮的消融：帧越多，深度越准

既然 code 只有 128 维、而且它是可以被优化的，那么「多给它几帧观测」应该能改善重建。原文的 Table 1 就是这么做的（误差是指 proximity 的 RMS，单位 $10^{-2}$）：

帧数与重建误差

1 帧：2.65 ／ 2 帧：2.47 ／ 3 帧：2.31 ／ 4 帧：2.39 ／ 5 帧：2.30 ／ 6 帧：2.14

怎么读

误差总体随观测增多而下降，但不是单调的（4 帧比 3 帧略差）。原文给的解释是：改善幅度取决于新帧带来多少信息——它是否提供了新的视角、是否有足够的基线。这个「信息量决定收益」的说明很实在，值得记住

原文还很坦诚地说明了「零 code」与「编码器给的 code」的对比（Fig. 6）：零 code 能抓住部分几何细节，但无法正确重建整个场景；而用优化求出的最优 code 重建，与编码器直接给出的 code 重建非常接近——原文用这个对比说明「编码器部分工作得很好」。

7.2 三件必须说清的事

① 它没有跟任何方法做定量对比

这一条很重要，也很容易被忽略。原文在 EuRoC 的 MH_02_easy 上跑滑动窗口视觉里程计，报告「9 米行程上大约 1 米误差」，然后自己加了一句很克制的话：「这无法与最先进的视觉惯性系统相比，但对一个纯视觉系统而言表现尚可」（原文：While this cannot compete with a state-of-the art visual-inertial system, it performs respectably for a vision only system）。它还特别声明没有使用可用的 IMU 数据。全文没有和 ORB-SLAM、LSD-SLAM、CNN-SLAM 中的任何一个做数字对比——它是一篇"概念验证"性质的论文。读到这种论文，要清楚它想证明的是「这个表示可行、可优化」，不是「我的系统最强」。

② 训练数据是纯合成数据，而失败模式正好暴露了这一点

网络在 SceneNet RGB-D 上训练——那是「photorealistic renderings of randomised indoor scenes」，也就是渲染出来的合成室内场景。最精彩的证据是原文 5.2 节对 Fig. 10 的说明：过曝的图像区域「saturate to infinite depth values」，而其原因是训练集里有大量带窗户的场景。也就是说，模型把「白花花一片」直接学成了「无穷远」，因为它见过的白花花一片都是窗户外面。这是「训练分布决定失败模式」的一个教科书级例子——它恰好也预告了下一节的思路：不能只靠网络猜，得让优化去纠。

③ 它自认是「初步系统」，而且明确列了未来工作

原文 4.3 节自称「a preliminary system」，结论里列了三条后续：建完整的实时关键帧 SLAM 系统、把训练扩展到真实数据（也可以只用强度信息做自监督）、以及把这种「可优化的紧凑表示」推广到一般 3D 几何、最终接到 3D 物体识别上。它还顺手提了一个工程短板：系统目前靠 TensorFlow 做图像 warp，换成专用实现还能再快。这些自我诊断，正好就是三年后 DeepFactors 要交付的东西。

④ 上手成本：训练配置也得看清

ADAM 优化器，初始学习率 $10^{-4}$，训 6 个 epoch，学习率降到 $10^{-6}$。深度值先通过 proximity 变换到 $[0,1]$。这个规模不算大，说明真正的门槛不在算力，而在「要有一批带深度真值的室内图像」。

本节小结：这篇给 SLAM 与深度学习重新分了工

如果只能记住一句话，我建议记住这个分工安排：神经网络不用来直接输出答案，而是用来提供一个「可优化的低维流形」。原文对这一点有一个很清醒的说法：他们认为自己的方法「relies less on the network generalisation」，因为后续的优化允许修正网络的坏预测；网络的主要作用只是「obtaining an image conditioned manifold to optimise over」（提供一个以图像为条件的、可供优化的流形）。

这个分工有个很实在的好处：它把「网络准不准」从生死问题降级成了「初值好不好」的问题。而这也直接呼应了第一季 0010 与 0011 讲过的结论——深度学习在 SLAM 里最稳的位置，不是替换整个系统，而是给经典优化提供更好的先验。下一节 0056 DeepFactors 就是把这个分工推向完整的实时系统。

8. 巩固练习

课后练习

  1. 用一段话解释：「稠密表示一定需要大量参数」这个推论错在哪一步？
    展开查看答案

    错在把「像素彼此独立」当成了前提。原文指出自然场景的几何具有高度秩序，深度图的邻域像素强烈相关，因此并不需要为每个像素配一个独立未知数，而可以用一个低维的「码」来生成整张深度图。这样参数从几十万降到一百多，同时保住了「稠密」这个表示形态。原文还更进一步指出：图像本身已经携带大量细节信息，所以 code 只需承担「图像预测不出来的那部分」，这才是为什么 128 维就够。

  2. 为什么作者非要牺牲表达力、把深度解码器做成线性的？请说出这个取舍换来了什么、代价是什么。
    展开查看答案

    换来的是可预计算的雅可比。深度对 code 的偏导（$\partial D/\partial \mathbf{c}$）需要穿过大量卷积，原文实测最贵时约 1 秒算一次；而如果解码器是线性的，$D_i = D_i^0 + \mathbf{J}(I_i)\mathbf{c}_i$ 中的 $\mathbf{J}$ 只依赖图像、与 code 无关，于是每个关键帧只需算一次、之后反复代入即可。代价是表达力下降——原文的补救办法是在每处拼接时额外拼上逐元素乘积 $[L_1, L_2, L_1 \odot L_2]$，让图像对 code 的影响仍然保留下来。

  3. 验算 proximity：取 $a = 3$ m，分别算出 $d = 2$ m、$d = 6$ m 时的 $p$，并解释这两个值落在曲线的哪一段、各自像什么参数化。
    展开查看答案

    $d = 2$ m：$p = 3/(2+3) = 0.600$。因为 $d < a$，落在「前段」，$p \in (0.5, 1.0)$，行为像普通深度。

    $d = 6$ m：$p = 3/(6+3) = 0.333$。因为 $d > a$，落在「后段」，$p \in (0, 0.5)$，行为像逆深度（远处压缩得厉害）。

    两个点都满足 $d$ 增大则 $p$ 减小的单调性，且在 $d = a = 3$ 处恰好 $p = 0.5$ 作为分界。

  4. 原文在 EuRoC 上报告「9 米行程约 1 米误差」，紧接着自己说了一句什么话？为什么这句话体现了一种值得学习的科研态度？
    展开查看答案

    原文紧接着说：「这无法与最先进的视觉惯性系统相比，但对纯视觉系统而言表现尚可」（While this cannot compete with a state-of-the art visual-inertial system, it performs respectably for a vision only system），并且明确声明没有使用数据集中可用的 IMU 数据。

    它的价值在于：主动指出自己结果的可比范围，而不是把「1 米 / 9 米」当成一个亮眼数字直接抛出。同时它也没有回避「我没用 IMU」这个事实——否则读者可能误以为这是与 VIO 系统的公平对比。这种「自己先说清不利条件」的做法，在后来 DeepFactors 的评测里也能看到（它也标注了对比方法的口径差异）。

  5. 本节说 code 的每一维「倾向于对应图像上的特定区域」，但原文同时提醒不能孤立地读它。这两句话矛盾吗？为什么？
    展开查看答案

    不矛盾。原文的观察是：把「深度对某一维 code 的偏导」可视化后，看到每一维的影响主要集中在图像上的某些区域，而且某种程度上尊重图像给出的边界（原文也承认这些区域「略微破碎」）。

    但最终的深度图是全部 code 项影响的线性组合（原文原话：the final reconstructions will always be a linear combination of the effect of all code entries）。所以「某一维主要管某块区域」是一个统计倾向，不是「这一维 = 这块区域的深度」这样的一一对应。读的时候要当成「责任分工的倾向」，而不是「查表」。

  6. 把本节和 0054 摆在一起：CNN-SLAM 把网络深度当「外部输入」，CodeSLAM 把网络输出当「内部变量」。这个转变在数学上最关键的一步是什么？
    展开查看答案

    最关键的一步是让深度图成为一个少数参数的、可微的函数，即 $D = D(I, \mathbf{c})$，并且刻意保证它对 $\mathbf{c}$ 是线性的。这样一来，深度就不再是一张「只能用不确定度加权的外部观测」，而变成了和位姿同一等级、可以进雅可比、可以一起被高斯牛顿优化的状态变量。数学上的分水岭是「能不能写出 $\partial D/\partial \mathbf{c}$ 并且算得起」——这正是本节第 5 小节那一整节在讲的事。
