1. 开场：一张分工表，胜过十页公式

先把结论摆在最前面。事件相机有四块天生的短板，而每一种「队友」恰好补其中一块：

队友 它补的是哪一块短板 凭什么能补
标准帧（APS）静止退化；以及「事件没有绝对亮度」这条帧有完整亮度图，静止时它照样能给出特征；而且很多算法需要一张帧来启动（bootstrap）模板
IMU初始化；以及高频段的运动先验IMU 高频且不依赖场景，能先猜一个运动，让事件不用从零开始找
深度相机 / 双目尺度（单目事件根本拿不到的那个量）有了深度，二维事件点立刻变成一个已知位置的三维点，一步到位
已有的离线深度图把问题从「SLAM」降级成「跟踪」地图不用建了，只剩「我在哪」，问题一下子简单很多

这就是整节课的骨架。记住一句口诀：双目 / 深度管尺度，帧 / IMU 管静止退化与初始化。后面四篇论文，无非是这四种队友的不同组合。

2. Ultimate SLAM（2018）：事件 + 标准帧 + IMU 的三路紧耦合

Ultimate SLAM（Vidal 等，RA-L 2018）是第一个把事件 + 标准帧 + IMU 三者紧耦合起来的事件相机 SLAM 系统（单目）。它的课题很实在：在 HDR 与高速这两种常规相机最难受的场合下，把鲁棒性做出来。作者甚至在标题里带了个问号——「Ultimate SLAM?」，意思是「这么拼，够不够叫终极？」

它的关键机关叫虚拟事件帧。做法是：拿 IMU 预积分出来的运动，把这段时间里的事件运动补偿（warp）到参考时刻，再累加成一张图：

$$ I_k(\mathbf{x}) \;=\; \sum_i \delta(\mathbf{x} - \mathbf{x}'_i) $$
输入：被 IMU 运动补偿到同一时刻的一批事件 → 处理：把每个事件按它补偿后的像坐标落进对应的像素里，累加计数 → 输出：一张「假设相机在参考时刻静止」时看到的事件图

这句话在说什么：① 这个式子在算「如果所有事件都发生在同一瞬间，画面会是什么样」；② 为什么这样就能用——因为相机在动，事件会散在整条运动轨迹上，糊成一片；用 IMU 的运动把每个事件「退回」到参考时刻，它们就重新聚回到物体的边缘上，这张图于是可以像普通图像一样去做 FAST 角点检测与 KLT 跟踪（每帧大约用 20000 个事件）；③ 权重／核函数在这里的角色由 IMU 的运动估计承担——IMU 猜得准，事件就聚得紧、特征就好找；IMU 猜得不准，这张虚拟事件帧就是糊的，所以 IMU 在这一步里说的分量很重。这也是为什么系统必须把 IMU 与事件相机之间的时间偏移标定得非常准（论文标到 2.5 ms）。

有了虚拟事件帧之后，前端变成「双源」：在虚拟事件帧上做一遍 FAST + KLT，在标准 APS 帧上再做一遍，两条线的特征都进入后端。后端用 Ceres 做非线性最小二乘，三路残差一起优化：

$$ \min\ \sum \|\mathbf{r}_{evt}\|^{2}_{\Omega_{evt}} \;+\; \sum \|\mathbf{r}_{img}\|^{2}_{\Omega_{img}} \;+\; \sum \|\mathbf{r}_{imu}\|^{2}_{\Omega_{imu}} $$
输入：事件特征的重投影残差、标准帧特征的重投影残差、IMU 预积分残差 → 处理：三者按各自的信息矩阵加权求和 → 输出：一个统一的代价函数，一起解出位姿、速度、IMU 偏置

这句话在说什么：① 这个式子在算「三路证据合起来有多矛盾」；② 为什么三路一起就能判对——事件特征在高速段最可靠、标准帧在静止段最可靠、IMU 在两者都失效的短暂间隙里还能顶住，三路互相补位，任何一路烂掉都不会让整个系统崩；③ 权重什么时候把观测当回事——每个残差前面的 $\Omega$ 是它的信息矩阵（可以理解为「这条证据有多可信」）：在高速运动时事件特征的权重实际更高，在静止或弱纹理时标准帧的权重更高，而 IMU 项的权重由它自己的噪声模型与预积分时长决定。这就是「紧耦合」的含义：不是先各自算一个结果再投票，而是在同一个优化里共同决定位姿。

成绩与代价：在 Event-Camera Dataset 上，比「事件 + IMU」准 85%、比「帧 + IMU」准 130%（这两个百分比务必带着对比基线来读）。它也是第一个在事件相机 SLAM 上做了四旋翼闭环飞行验证的工作。原文自述的局限同样要记住：事件分支对参数和场景运动敏感；静止 / 弱纹理时标准帧仍是主力；时间偏移需要仔细标定。

3. EventTracking（2018）：事件 + 一张「已经给你的」深度图

第三篇的角度完全不同，也最容易被误会，所以先把它的定位钉死：

⚠️ 它的真实身份：这是「跟踪」，不是完整 SLAM

这篇论文的完整标题是 Event-Based, 6-DOF Camera Tracking from Photometric Depth Maps——关键词是 from Photometric Depth Maps（从光度深度图出发）。它不建图：深度图是「已经给你」的——要么来自 RGB-D 相机（论文用的是 Intel RealSense R200），要么来自离线的稠密重建（DTAM / REMODE）。它做的事情只有一件：给定这张深度图（强度 + 深度），逐事件更新相机的 6 自由度位姿。

所以把它和 0176 的 EVO、0178 的 ESVO 并列时，必须说清它们的层级不同：EVO / ESVO 要同时解决「地图长什么样」和「我在哪」；它只解决后者。它的优势也正来自这个简化——可以做到几乎零延迟（微秒级）。

它的技术核心是一个漂亮的观察。按 0175 讲的，事件产生的条件是「对数亮度变化跨过阈值」。那么反过来：如果我知道这张参考图长什么样，也知道相机的位姿，我就能预测「这个事件应该对应多大的亮度变化」。于是定义一个测量函数：

$$ M \;:=\; \frac{\Delta \ln I}{C_{th}} \;-\; 1, \qquad p(o_k \mid s_k) \;=\; \pi_m\,\mathcal{N}\!\left(M;\,0,\,\sigma_m^{2}\right) \;+\; (1-\pi_m)\,\mathcal{U}\!\left(M;\,M_{min},\,M_{max}\right) $$
输入：把事件 warp 到参考图上，在 t_k 与 t_k − Δt 两个时刻取对数亮度、相减得 Δln I → 处理：用它除以对比度阈值 C_th 再减 1，得到「跨阈值的倍数」M → 输出：M 接近 0 就说明位姿算对了，观测可信；M 离谱就说明这个事件是离群，交给均匀分布那一项吞掉

这句话在说什么：① 这个式子在算「这个事件报出来的变化，跟位姿预测出来的变化，对得上吗」——若对得上，$\Delta \ln I$ 应该恰好等于阈值 $C_{th}$，于是 M 等于 0；② 为什么这样就能判对——位姿错了，事件被 warp 到参考图上的位置就错了，取到的两点亮度差就会乱掉，M 会成批地偏离 0；位姿对了，M 就聚在 0 附近，所以「让 M 尽量接近 0」就等于「让位姿尽量对」；③ 权重／核函数在这里非常关键：$\pi_m$ 是内点比例，$\sigma_m$ 是内点的噪声尺度；而那个均匀分布 $\mathcal{U}$ 是专门用来「兜住离群值」的——当一个事件的 M 远离 0（比如场景里有别的运动、或深度图本身有错），正态项给的概率已经很小，均匀项却仍然给出一个大致恒定的概率，于是这个观测不会把位姿拽走。这就是所谓的 normal-uniform 混合似然，它让这套方法在快速运动、深度有瑕疵时依然稳。每一轮更新都写成 EKF 的形式，卡尔曼增益 $K_k = P_k J_k^{\top}(J_k P_k J_k^{\top} + \sigma_m^{2})^{-1}$ 决定「这个事件能改多少位姿」。

成绩与代价：在室内 DVS（128×128，注意这个分辨率有多低）的 rocks 序列上，位置 RMS 1.63 cm、朝向 RMS 2.21°；换算成相对量是 2.71%（相对 60 cm 的平均景深）。作为对照，一台 752×480、90 Hz 的标准相机做同样的事，位置 1.8%、朝向 1.04°——事件法只略差一点，而它的分辨率低了约 20 倍，这个对比很有说服力。更有说服力的是高速实验：标准相机在约 8.66 秒处因运动模糊彻底跟丢，事件法继续准确跟踪。

原文自述的局限必须照抄：依赖已有的准确深度图（不是在线建图）；DVS 空间分辨率低；未优化的实现每事件要 32 ms，处理不了 1 M/s 的事件率（需要优化，实测约 31k events/s）；并且假设恒定光照。

4. DEVO（2022）：事件 + 深度相机，深度只要 1 Hz

第四篇把「借深度」这件事做得更彻底。DEVO（Nunes 等，ICRA 2022）的配置是事件相机 + 深度相机的混合立体系统：深度相机直接给出深度图，事件相机负责高频运动。它的中心思想是那句话——既然深度相机能直接测出深度，为什么还要去估计它？

  • 事件的用法：把事件攒成 Time-Surface Map（TSM），再按一个阈值 δ 二值化，得到一张边缘图。
  • 深度的用法：深度相机给的点，配上参考帧的位姿，投影成一组带深度的三维点，再 warp 到当前时刻，得到「参考边缘图在当前视角下应该长什么样」。
  • 优化：用 forward compositional LK 最小化「当前 TSM 边缘」与「warp 过来的参考边缘」之间的对齐残差（含一个稳健损失 ρ）。
$$ \theta_{rel}^{*} \;=\; \arg\min_{\theta_{rel}}\ \sum_k \rho\!\left( \overline{\mathcal{T}}_{cur}\!\left( W(\mathbf{x}_k^{ref};\ \theta_{rel}) \right) \right)^{2} $$
输入：参考帧上被选中的边缘点集，以及当前的 TSM → 处理：用待求的相对位姿 θ_rel 把这些参考点 warp 到当前 TSM 上，取对应值求残差 → 输出：让所有残差最小的那个相对位姿

这句话在说什么：① 这个式子在算「把参考帧的边缘按某个相对位姿挪过来，和当前这一刻的边缘图能不能重合」；② 为什么这样就能判对——边缘是由事件的时间表面值表达的（刚变过的位置值高），位姿正确时，warp 过来的参考边缘应该正好压在当前 TSM 的高值处，残差小；位姿偏了，两条边错开，残差变大；③ 权重／核函数在这里是稳健损失 ρ——当某个点的残差特别大（深度图有噪声、边缘提取错了），ρ 会让它的权重降下来，不让一个坏点拖偏整个位姿。这和 0176 里事件线 SLAM 用距离降权是同一类做法。

它最大的实用价值是一个数字：深度相机只要 1 Hz 就能跟踪。原因很直白——深度是「慢变量」，房间里的墙和桌子不会每秒挪位置，所以低频测一次就够；而运动是「快变量」，交给事件相机去高频地跟。这个分工正好对上第 1 节那张分工表。代价也很清楚：它依赖深度相机，需要仔细标定事件相机与深度相机的外参；深度图有噪声或空洞时会退化；TSM 的二值化阈值 δ 很敏感；而且它没有 IMU，所以尺度与漂移的处理是缺失的。原文自述里也写了这些。

5. 行星机器人（2022）：把 EKLT + xVIO 送到火星场景里

最后一篇常被误会成「一篇对比综述」，这里要如实纠正：它是一篇提出 pipeline 并在火星类比场景里做验证的方法论文（Klenk 等，RA-L 2022），只不过它做的对比实验特别多。它把已有的两个零件拼起来：

前端：EKLT（事件 + 帧）

用 Harris 角点做种子，对每个角点维护一个亮度模板，靠事件流与标准帧一起逐事件更新模板（亮度增量对齐），输出异步的特征跟踪。

后端：xVIO（EKF）

状态里含 IMU 误差状态与特征（MSCKF 式的滑窗 + 深度先验特征），最小化 IMU 预积分残差 + 特征重投影残差；每 $n_e = 3200$ 个事件同步一次。

为什么这件事和行星探测扯上关系？因为火星车/火星直升机面对的光照条件极端：论文在 JPL Mars Yard 里测的是高动态（常规图像严重过曝到出伪影），在 Wells Cave 里测的是低光（常规图像严重欠曝）。而从事件重建出来的 HDR 图像不受这两种伪影影响，这正是方法能赢的原因。结果：在 Event-Camera Dataset 上平均 MPE 0.54%，比次优方法低 32%；而且在一段纯旋转序列上，它成了唯一收敛的方法（靠 xVIO 后端加的深度先验顶住了退化）。

它的局限也很典型，正好呼应前两节：EKLT 仍然需要初始 APS 帧（因为事件不提供绝对亮度，模板要靠帧 bootstrap）；DVXplorer 这类没有帧的机型压根用不了 EKLT 前端；而且计算比较重（论文如实报告了它在处理事件率上的开销）。

最后补一句判断（这是本课的归纳，不是原文自评）：这四篇里，Ultimate SLAM 的「三路紧耦合」和 DEVO 的「深度低频、事件高频」最接近工程取用；EventTracking 的价值在于把「事件 + 已有深度」这条路走到了极致（微秒级延迟），但它的前提最苛刻；行星机器人那篇的贡献更多是「证明在极端光照 + 弱纹理下可行」，方法本身是 EKLT + xVIO 的组合。它们合起来把 0176 三篇的天花板补齐了——但补的方式是加传感器，而不是让纯事件自己变强。

    展开查看答案
    因为场景的几何结构（墙、桌子、地面）变化得很慢，房间里没有东西每秒挪一次位置，所以深度图低频获取一次就足以支撑后续的运动补偿；而相机自身的运动是快变量，必须高频跟上，这件事交给事件相机。DEVO 正是把深度相机的深度直接投影成三维点再 warp 成参考边缘图，省掉了立体匹配和深度估计，因此深度相机的帧率不再是瓶颈。
  2. EventTracking 的测量函数 M 为什么要除以对比度阈值 C_th 再减 1？直接看 Δln I 不行吗？
    展开查看答案
    不行。事件产生的条件就是 Δln I 跨过阈值 C_th（见 0175 的触发规则），所以「一个事件被触发」这件事本身就说明 Δln I 的量级应当在 C_th 附近。除以 C_th 再减 1，就把判据归一化成了「跨阈值的倍数」：M = 0 表示预测的变化恰好等于阈值，正是「这个事件符合预期」的状态；M 明显偏离 0 就说明位姿算错或这个事件是离群。这样处理后，残差的量纲与阈值无关，对不同传感器、不同光照更通用。
  3. EventTracking 的似然函数里那个均匀分布项起了什么作用？没有它会怎样？
    展开查看答案
    它专门用来兜住离群观测。正态项 N(M; 0, σ_m²) 只在 M 接近 0 时给出较高概率，而均匀项 U(M; M_min, M_max) 在给定区间内给出大致恒定的概率。当某个事件的 M 远离 0（场景里有别的运动、深度图本身有错、或光照变化），正态项的概率已经很小，但均匀项仍然提供了一个「这种情况也可能发生」的解释，于是这个观测不会被当成强证据去拽偏位姿。若去掉它，少数坏事件会被当成可信观测，位姿就会被带偏——这正是 DSO 一类方法要额外引入稳健核函数的原因。
  4. 为什么说 Ultimate SLAM 的 85% / 130% 这两个数字必须带着对比基线来读？
    展开查看答案
    因为它们是相对提升：比「事件 + IMU」（E+I）准 85%，比「帧 + IMU」（Fr+I）准 130%。脱离基线，读者会误以为它是某种绝对精度指标。另外本篇精读材料还提醒了一个疑点：表 I 标的「E+I」与表 II / 正文里的「Fr+I」口径需要核对，作者自述不同实验的参数也不同，引用应以正文叙述为准。这类百分比在事件相机文献里很常见（比如行星机器人那篇的「比次优低 32%」也同样需要基线）。
  5. 行星机器人那篇为什么属于「方法论文」而不是「对比综述」？它的方法由哪两个已有零件组成？
    展开查看答案
    因为它提出了一条完整的 pipeline 并做了验证，只不过顺带做了很多对比实验（因此常被误认成综述）。它的前端是 EKLT（用 Harris 角点作种子、以事件 + 标准帧融合更新亮度模板，输出异步特征跟踪），后端是 xVIO（EKF，MSCKF 式滑窗加深度先验特征，每 3200 个事件同步一次）。代价是 EKLT 仍需要初始 APS 帧来 bootstrap 模板，因此没有帧的机型（如 DVXplorer）无法使用该前端。
