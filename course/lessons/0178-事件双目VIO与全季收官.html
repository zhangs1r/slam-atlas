1. 开场：把棋盘上所有棋子都用上

回顾一下这一块走过的路。0175 把机理讲清；0176 看了「什么队友都不带」的纯事件路线（EVO、事件线 SLAM、CMax-SLAM），它们的共同天花板是：一静止就失明，而且单目拿不到尺度；0177 看了四种「一对一补短板」的配对（事件 + 帧 + IMU、事件 + 已有深度、事件 + 深度相机）。

这一节要看的，是把所有棋子一起用上的形态：事件双目 VIO。骨架是三个问题各自找对了负责人：

尺度：交给双目

两台事件相机有固定基线，左右眼看到同一条边的视差直接给出深度——单目事件拿不到的那个量，靠基线一次解决。

静止退化：交给标准帧

场景不动时事件为零，但同芯片的标准帧照样有纹理，特征照样能提。

高频与初始化：交给 IMU

IMU 不依赖场景，能先给出运动预测；而且它顺带负责把事件「补偿」到同一时刻。

而这一节的第四篇（VECtor）角色不一样——它是一把尺子：把事件、标准帧、深度、LiDAR、IMU 全部硬件同步地录下来，附上高精度真值，让所有人用同一种口径比。它的结论很不好看，但非常重要，第 5 节会讲。

2. ESVO（2021）：第一个事件双目 VO，靠「左右眼时空一致」估逆深度

ESVO（Zhou 等，IEEE T-RO 2021）是第一个事件 + 双目的视觉里程计。它的输入是两台标定好的事件相机（论文自制的支架，两台 DAVIS346，水平基线 7.5 cm），输出是相机位姿加一张半稠密的三维边缘点云；跟踪与建图两条线程并行，可以在标准 CPU 上实时，代码开源。

它的核心工具在 0176 已经见过：时间表面（$\mathcal{T}(\mathbf{x},t)=\exp(-(t-t_{last})/\eta)$，取 η = 30 ms，以 100 Hz 更新）。ESVO 的创新在于：它不问「这个事件对应哪个三维点」，而是问「哪个深度值，能让左右两只眼看到的时间表面一致」。

换句话说，对左眼某个像素上的一条视线，沿它取一个候选逆深度 ρ，就能算出它投影到右眼的哪个像素；如果 ρ 是真值，那么左右两眼在那两个像素上的时间表面读数应该差不多（因为它们是同一个三维边缘在同一时刻的痕迹）。于是代价函数就是：

$$ C(\rho) \;=\; \sum_i r_i^{2}, \qquad r_i \;=\; \mathcal{T}_{\text{left}}\big(\pi_l(\rho)\big) \;-\; \mathcal{T}_{\text{right}}\big(\pi_r(\rho)\big) $$
输入：左眼一个事件的像素位置，以及一个候选逆深度 ρ → 处理：把 ρ 投影成右眼对应的像素，取左右两张时间表面在那两个位置的值，相减 → 输出：这个 ρ 假设下左右眼的「不一致程度」，越小说明 ρ 越接近真值

这句话在说什么：① 这个式子在算「如果我猜这个点离我 1/ρ 米远，左右两只眼看到的东西对得上吗」；② 为什么这样就能判对——因为左右眼看到的是同一条三维边，同一个时刻它在两张时间表面上的痕迹必然位置对应；猜错了深度，投到右眼的像素就偏了，两边的读数就对不上，残差 r 就会变大；所以「让残差最小」就等于「让深度最准」；③ 权重／核函数在这里的角色由概率分布承担：论文发现这些残差并不服从高斯，而是拖着长长的尾巴（因为场景里有遮挡、有误投影），所以它用 Student's t 分布去融合逆深度（用 IRLS 求解），t 分布的重尾让少数离谱的观测不至于把深度估计带飞——这与 0177 里 EventTracking 用 normal-uniform 混合似然是同一个目的（都是「别让离群值说话」），只是换了一种分布。

另外两个工程细节值得记：融合时每像素用最近 M+1 = 20 个立体观测；初始逆深度是用改进的 SGM 块匹配得到的（比暴力搜索高效），这也解释了它对初始化为什么敏感。跟踪那一侧，则把参考帧的时间表面当作一张「各向异性距离场」，最小化三维点投影与当前时间表面的 3D-2D 对齐误差——本质上还是 0176 讲的「对齐派」。

3. ESVIO（2023）：第一个事件双目 VIO，四路残差紧耦合

ESVIO（Chen 等，RA-L 2023）的定位写得很清楚：第一个事件双目视觉惯性里程计。它有两个版本——ESIO 只用事件 + IMU，ESVIO 再加上标准帧；两者共用同一套滑窗图优化后端。作者团队自建的挑战数据集（HKU）里有暗光、高动态、激进运动等场景。

先说它最重要的一步：运动补偿。事件是在相机运动过程中陆续产生的，直接叠在一起是一团糊（0177 的虚拟事件帧也是为了解决这个问题）。ESVIO 的做法是用 IMU 的角速度 + 后端估计出的线速度，把每个事件 warp 到同一个时刻，于是事件流从「弯的」变成「直的」，再转成正负两张 SAE / 时间表面。这一步做得好不好，直接决定后面能不能提出干净的特征。

接下来前端在时间表面上用改进的 Arc* 提事件角点（每帧 100–200 个），用 LK 光流做左右（空间）与前后（时间）两种数据关联，再用 RANSAC + 三角化得到逆深度。后端是一个滑窗非线性优化，四路残差同时约束：

$$ \min_{\boldsymbol{\chi}} \sum_{k\in\mathcal{B}}\|\mathbf{r}_b\|^{2}_{\Omega_b} + \sum_{(l,k)\in es}\|\mathbf{r}_{es}\|^{2}_{\Omega_{es}} + \sum_{(l,k)\in et}\|\mathbf{r}_{et}\|^{2}_{\Omega_{et}} + \sum_{(l,k)\in c}\|\mathbf{r}_c\|^{2}_{\Omega_c} $$
输入：IMU 预积分、事件角点的左右关联、事件角点的前后关联、标准帧上特征的重投影 → 处理：四类残差各自按信息矩阵加权求和 → 输出：一个统一的代价函数，一起解出位姿、速度、偏置与逆深度

这句话在说什么：① 这个式子在算「四路证据合起来矛盾有多大」：$\mathbf{r}_b$ 是 IMU 预积分残差（两帧之间 IMU 说走了多少 vs 位姿说走了多少），$\mathbf{r}_{es}$ 是同一个事件角点在左右眼必须投到同一条三维边上，$\mathbf{r}_{et}$ 是同一个角点在前后帧必须落在同一条边上，$\mathbf{r}_c$ 是标准帧上特征的重投影；② 为什么四路一起就能判对——双目那一项负责尺度，前后那一项负责时间连续，帧那一项在事件稀少的时刻顶上，IMU 那一项在短暂无特征时扛住；任何一路变差，剩下的仍然把解拉住；③ 权重什么时候把观测当回事——每个残差前面的 $\Omega$ 是信息矩阵：在事件角点被跟踪得很稳、视差充足的地方，事件项权重自然高；当场景静止、事件稀疏时，帧项与 IMU 项就接管话语权。这就是「紧耦合」的实质：四路不是各算各的再平均，而是在同一个优化里互相牵制。

成绩单（都请带着对比基线与数据集来读）：平均 MRE，ESVIO 0.033°/m，对比 ORB-SLAM3 的 0.12°/m；平均 MPE，ESIO+ 0.66% 对比纯事件版 ESIO 的 0.89%；高动态下四旋翼机载飞行的 ATE RMSE 0.17 m（轨迹 56 m），激进运动下 0.26 m；大规模校园场景跑了 1.8 km / 34.9 分钟。耗时方面，346×260 分辨率下前端 10.44 ms、后端 19.30 ms；640×480 下前端 35.69 ms、后端 35.59 ms。

局限也要如实写：低纹理环境（比如论文里的 units-dolly、scooter 序列）视觉方法容易退化或误匹配；参数是固定的、没有细调；而且它自己报告了一个很有信息量的现象——纯事件方法（EVO、ESVO）在团队自建的数据集上几乎全失败，原因是它们的初始化太严格。这句话很值得记住：「某方法在别人数据集上全挂」很多时候是初始化问题，不等于方法本身无效。

4. PL-EVIO（2024）：点、线、帧、IMU 与回环，全都上

最后一篇把「能加的都加上」。PL-EVIO（Guan 等，IEEE T-ASE 2024）是单目事件 VIO——注意与 ESVIO 的双目不同，它靠 IMU 与 SfM 初始化来拿尺度。它的名字里 P 和 L 指的是点特征与线特征，而且这两类特征各有「事件版」与「帧版」：

事件角点（P）

在带极性的时间表面上用 Arc* 提取，用双向 LK 跟踪，维持 150–250 个；极性当掩码还能让角点分布更均匀。

事件线特征（L）

用 LSD 提线、LBD 描述子匹配；线的最小长度取 $L_{min}=\eta\cdot\min(W,H)$，其中 η = 0.125——太短的线不要，免得引入噪声。

标准帧特征

同一芯片 APS 帧上的点特征，进入后端一起优化（这就是 PL-EVIO 里那个 E 与 I 的区别）。

回环

用归一化的时间表面生成描述子，BRIEF 描述、Hamming 距离 16–25 作阈值，闭环修正漂移。

后端是滑窗图优化（关键帧窗口 K = 10，关键帧的选择条件是平均视差大于 10 或跟踪到的角点少于 20），把四类残差再加上边缘化项与回环项一起解：

$$ J(\chi) \;=\; \sum \|e_{event}\|^{2} + \sum \|e_{line}\|^{2} + \sum \|e_{imu}\|^{2} + \sum \|e_{image}\|^{2} + \|e_m\|^{2} + \|e_r\|^{2} $$
输入：事件点重投影、事件线重投影（用 Plücker 四参数正交表示）、IMU 预积分、标准帧点重投影 → 处理：再加上边缘化先验 e_m 与回环约束 e_r，一起求和 → 输出：一个统一的代价函数，滑窗内整体求解

这句话在说什么：① 这个式子在算「六类约束合起来有多矛盾」；② 为什么加线和回环能让它更稳——线提供结构：在楼道、走廊这类地方点特征稀少但直线很多，线约束能在点不够时继续拉住位姿（这就是第三季 0069 / 0070 讲过的点线融合理由，只是换到事件上）；回环提供全局修正：前端再准也会漂，回环是唯一能把累计漂移拉回来的手段；③ 权重／核函数在这里最重要的角色是 $e_m$（边缘化先验）：滑窗要往前挪，被移出窗口的状态不能就这么丢了，而是把它携带的信息压缩成一个先验留在代价函数里——这正是 第三季 0049 VI-DSO「动态边缘化」与 0063 DM-VIO「延迟边缘化」反复讨论的那件事，做得不好会让估计变得过度自信。另外线特征用的是 Plücker 直线加四参数正交表示，是为了在优化中避免参数退化。

成绩与代价：在用 VICON 做真值的 vicon_aggressive_hdr 等序列上，MPE 低到 0.11%–0.19%；事件流 60 Hz（DAVIS346，346×260）/ 50 Hz（DVXplorer，640×480）；在笔记本（i7-11800H）上实时；完成了四旋翼的翻转飞行；初始化走 SfM + IMU 对齐，不需要平面或标记。

它的局限里有一条特别值得记住：在激进运动下，事件 + IMU 的运动补偿因为 IMU 偏置的存在，收益有限（论文里纯事件版 PL-EIO+ 相对 PL-EIO 的提升并不显著）；在低光下，加了图像反而可能不如纯事件——因为此时图像上的点特征已经退化了，等于往系统里塞了一条坏证据。此外低纹理与纯旋转仍然是挑战，而且它依赖 DAVIS 这种同芯片的帧—事件标定。

5. VECtor（2022）：一把尺子，也是一面照妖镜

最后这篇不是方法论文，是数据集与评测基准。它要解决一个很实际的问题：前面这些方法各用各的数据、各用各的指标（MPE、MRE、RPE、ATE、RMSE 混着来），谁都很难跟谁比。

VECtor（Gao 等，RA-L 2022）的贡献是一套「全硬件同步 + 高精度真值」的多传感器平台：以事件双目为中心，同时装上标准双目、RGB-D、LiDAR 与 IMU，全部由 MCU 硬件触发同步（亚微秒级）；小尺度场景用 MoCap（120 Hz）经手眼标定提供真值，大尺度场景用 FARO 激光扫描点云与 LiDAR 扫描做 ICP 配准提供真值；评测统一用 EVO 工具算 RPE / ATE。论文还用一个红外滤光片（IR690）压掉 MoCap 850 nm 频闪带来的噪声，并给出不同光照下的 bias 参数表。

它最重要的结论其实是负面的：作者自述当前的事件 SLAM 方法仍不成熟——基准网站上的结果显示事件方法的表现有限。换句话说，把大家放到同一把尺子上之后，那些「在自家数据上很好看」的成绩并没有全部兑现。这正好印证了本块的硬结论：事件相机的真实优势只在高速 / 高动态 / 低光时才兑现，且几乎每篇都靠帧或 IMU 兜底。

还有两条边界要如实标注：这份数据里 RGB-D 与 LiDAR 不同时使用；而且有部分序列被留作秘密测试集，只用于排行榜。

7. 收官（二）：还剩哪些没拆干净

把上一张图的红框说透。四个块各留下了一个没解决的核心问题，它们恰好可以和本季的横向关系对上：

动态块：打补丁的代价

本块绝大多数方法都是在 0043–0045 ORB-SLAM 外面加一层动态剔除，没有改内核。于是「判断哪些点/像素在动」本身始终是个可能出错的前置步骤，而判错的代价（把静止的路标删掉、把动态的留下）一直没有被系统地量化。0156 那句「别把停着的车删掉」就是这个洞的最直白表达。

语义块：标签是借来的

本块的语义几乎全部来自外部的分割/识别网络（回链 第六季 0114 / 第七季 0147 的 SAM / DINOv2）。地图有了标签，但「同一物体跨帧被认成同一个」这件数据关联的事直到 0166 才被当作一等公民来对待；物体被搬走之后地图怎么更新，仍然是开放的。

多机块：一致性与通信量是死结

从中心化（0169 COVINS / LAMP 2.0）到分布式（0170）再到去中心化（0172 Swarm-SLAM），做的都是「在带宽约束下尽量保持全局一致」；而 0174 的两条替代路线（只传拓扑、UWB 量距）是绕开问题而不是解决问题。假回环这条铁律（第七季 0140）仍然要靠 PCM / GNC 这类鲁棒后端兜。

事件块：优势是「补位」而不是「替代」

本块十一篇里，纯事件的三篇都要靠运动才能工作，其余八篇都要帧 / IMU / 深度兜底。VECtor 用统一基准再次确认了这一点。事件相机真正兑现的优势，是在常规相机失效的那一小段里——它的定位是补位选手。

还有一件事值得留一句话：本季拆掉的三条假设都还是「关于外部世界和传感器配置」的假设。如果你要问「下一个还没被碰过的前提是什么」，一个很自然的候选是「传感器给出的数据是可信的」——本季没有一个块处理观测被欺骗、被污染或标定失效的情况。这只是一句留给读者的开放提示（属于本课的判断，不是任何一篇原文的结论），但它大概就是下一季会去撞的墙。

最后回到事件块本身，用三句话收尾：

  • 它改变了「什么时候能看清」：高速、高动态、低光——常规相机最难看的时候，它给出可用的边缘。
  • 它没有改变「什么才算看清」：没有绝对亮度、没有完整图像、静止时没有信息，这三条从 0175 到 0178 一步都没变。
  • 它把「表示」这件事重新推到了台前：事件累积图、时间表面、IWE——整块论文的真正战场在「怎么把流水账攒成能算的东西」上，而不在优化器上。

课后练习

  1. 为什么事件式的深度估计天然是「概率式」的？直接用一次观测定深度会怎样？
    展开查看答案
    因为一个事件只给出「这条视线上的某个位置发生了亮度变化」，也就是一条射线，它没有任何关于距离的信息（方向确定、深度完全未知）。只有把同一条射线在不同时刻、不同视角下的多次观测融合起来，深度才逐步收窄。所以做法是维护一个概率分布（ESVO 用 Student's t 分布融合最近 M+1 = 20 个立体观测），而不是解一个数。用一次观测定深度，结果几乎完全不可用——这也是 ESVO 被批评「初始化严格」的根源。
  2. ESVIO 的运动补偿为什么需要「IMU 角速度」和「后端线速度」两样东西？
    展开查看答案
    因为把事件 warp 到同一时刻，需要知道相机在每个事件时刻的位姿变化。纯旋转时，角速度一项就足以描述运动；但一旦相机同时有平移，同一个三维点在不同时刻的投影位置还受平移影响，这时就需要后端估计出的线速度来补上平移那一部分。两者缺一不可——只补旋转的话，平移带来的偏移仍然留在事件流里。这也解释了 PL-EVIO 报告的现象：激进运动下 IMU 偏置较大时，补偿的收益会被打折（所以它引入了带偏置的估计与图像兜底）。
  3. ESVIO 自述「纯事件方法（EVO、ESVO）在自己数据集上几乎全失败」，这句话应该怎么理解？
    展开查看答案
    不能直接理解成「EVO / ESVO 无效」。原文给出的原因是它们的初始化过于严格——EVO 需要场景在传感器前方近似平面地持续运动数秒才能 bootstrap，ESVO 对初始逆深度与搜索区间也很敏感。而在 ESVIO 自建的 HKU 数据集（含暗光、高动态、激进运动）上，这种初始化前提往往不成立，于是它们在还没跑起来时就失败了。这正是本块硬结论里提醒的那句：数据/评测口径要统一后才能比较，「在别人数据集上全失败」很多时候是初始化问题而非方法无效。
  4. PL-EVIO 的滑窗图优化里，边缘化项 e_m 起什么作用？做不好会怎样？
    展开查看答案
    滑窗必须不断向前推进，被移出窗口的旧状态不能直接丢弃，否则历史信息全没了；边缘化项的作用就是把这些旧状态携带的信息压缩成一个先验，留在代价函数里继续约束当前状态，从而在不扩大计算量的前提下保留历史。做不好会让估计变得过度自信（先验被当成确定的信息，实际上它带着误差），这正是 0049 VI-DSO 与 0063 DM-VIO 反复讨论的核心问题。
  5. 用一句话概括第八季「拆掉三个假设」的结果。
    展开查看答案
    三个假设确实都被戳破了——动态块拆「环境静止」、语义块拆「地图只有几何」、多机块拆「只有一台机器人」、事件块拆「相机是快门式的」（四块对应三条假设外加一条传感器层面的假设），但每一条都只拆掉了一部分：动态方法多在 ORB-SLAM 外面打补丁、语义标签全靠外部分割网络、多机在通信受限下只能绕开全局一致、事件系统几乎都要靠帧或 IMU 兜底。所以本季真正的收获是「知道了前七季的结论是有前提的」，而暴露出来的问题比解决掉的更多。
