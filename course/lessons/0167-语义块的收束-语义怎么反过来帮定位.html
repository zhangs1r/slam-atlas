1. 语义块的收束：一条主线

九节课走下来，语义建图块其实只讲了「地图该怎么装语义」这一件事，但答案沿着表示能力一路升级：

  • 表示：surfel（0159 / 0160）→ octree / TSDF 体素（0161 / 0162）→ 动态场景图 DSG 五层（0163）；
  • 粒度：逐像素语义（0159）→ 实例级（0160 / 0161）→ 全景 stuff+things（0162）；
  • 关联：几何+语义硬判（0160）→ IoU / EM（0161）→ 地图参考 + 统计集成（0162 / 0166）；
  • 物体模型：从稠密 / 体素（0161–0162）到紧凑椭球 / cube-quadric（0164 / 0166）；
  • 代价：实时性始终是瓶颈，来源各异（CNN 降频、GPU 对象重建、检测频率）。

这篇 2023 综述（Pu、Luo 等）恰好是按「DL 融入 SLAM 的前 / 后端与回环」来系统梳理的，是给本块收束的天然透镜。

6. 诚实收尾：本块最该记住的纠正

⚠️ 把「CRF = 回环」这个误读正式了结

这篇 2023 综述的 §V-A 写道：SemanticFusion「employs a fully connected conditional random field (CRF) ... enabling loop detection」。这是错的。0158 与 0159 已核实：SemanticFusion 的 CRF 只用于标签空间平滑（让邻域像素更像同一类），和回环检测毫无关系。本块在此正式了结这个误读——引用综述时请勿采信，应回到原文判断。

另外诚实标注综述自身的局限（也是本块的代价账）：① 语义分割网络类别有限、算力消耗大；② 多数动态方法删除动态物体导致特征损失（这正是 0155 DynaSLAM II 要「留 + 追踪」的动机）；③ 深度可靠性影响实例重建质量。

  1. 用一句话说明「语义建图」和「定位」的关系——为什么建语义图最终是为了定位更准？
    展开查看答案
    语义不是地图的装饰，而是「增值约束」：前端用语义剔掉动态点（不让走动的人把位姿带偏，见 0153/0165），后端把物体/平面当几何约束加进位姿图（见 0164/0166），回环用语义描述子做更稳的同源场景匹配。三者都让「我在哪」算得更准。所以建语义图的目的，最终是反哺定位——这也是本课标题「语义怎么反过来帮定位」的含义。
  2. 综述说「DL 鲁棒准确但实时更弱」。用本块至少两个具体系统的取舍来证明这句话。
    展开查看答案
    例一：MID-Fusion / EM-Fusion（0161）做对象级体素重建必须 GPU，且实时性随物体数骤降——准确（能建物体模型）但慢。例二：YOLO-SLAM（0165）为了实时，放弃实例分割和物体模型、只用轻量 YOLO 出框删点，在 Intel 无 GPU 笔记本可跑，但只识别「人」一类、精度上限低。两者正好印证「准」与「快」的权衡——DL 强在准、弱在快。
  3. 为什么综述 Fig.6 的「语义 vs 实例」区分，是本块最关键的粒度跃迁？它对应哪两节课？
    展开查看答案
    语义分割只告诉「这是椅子类」，无法区分同类个体；实例分割把同类不同个体分开，才能支持「拿第②把椅子」这类物体级交互。这正是 0159（逐像素语义，只给类）到 0160（实例级，给编号）的跃迁，综述用一张图把这次跃迁点透了。后续 0162 的全景（stuff+things）是把两者统一，0164/0166 的对象参数化则建立在这之上。
  4. 为什么本块要在收束处特别纠正「CRF = 回环」这个误读？写课时我们是怎么处理的？
    展开查看答案
    因为这个误读出自一篇 2023 综述的 §V-A，而综述容易被当权威引用；若照搬，会把「标签平滑」错当成「回环检测」，误导读者。我们核实原文（0158/0159 已查）后确认：SemanticFusion 的 CRF 只做标签空间平滑，与回环无关。处理方式是在 0158、0159 点出，并在本收束课（0167）正式了结，明确标注「引用综述时请勿采信，应回到原文判断」——这是硬规范「诚实标注不确定性 / 纠正 OCR 与文献误读」的要求。
