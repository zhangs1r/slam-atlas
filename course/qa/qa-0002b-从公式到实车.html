从公式到实车：ROS 小车的激光、相机、里程计，是怎么变成因子图算出位置和地图的

你的理解大方向完全正确——不同传感器提供不同的"证据"，证据变成因子，因子连成图，解图得到位姿和地图。 这一页把这句话拆成看得见的东西：先画一台真车（SVG），再把公式里每个符号按到车上的一个零件上，然后给你两个层次的伪代码，最后手算一遍三个传感器互相拉扯的过程。🧭

1. 先看车：它身上到底挂了什么

假设你有一台最典型的 ROS 差速小车，跑在一条直走廊里。它身上至少有这三样东西：

硬件ROS 话题它给的是什么"证据"它靠不靠谱
2D 激光雷达（RPLIDAR 之类） /scan 一圈距离读数：每个角度上，墙在多远 单帧很准（厘米级），但它不知道自己在地图的哪里——只知道"周围长这样"
相机（单目 / 双目 / RGB-D） /camera/image_raw、/camera/camera_info 图像里的一堆特征点像素坐标 $(u,v)$ 信息丰富、能认路标，但受光照影响、单目还有尺度问题
轮式编码器（里程计） /odom 两个相邻时刻之间"我大概移动了多少"：$\Delta x, \Delta y, \Delta\theta$ 短期平滑连续，但长期一定漂移——轮子打滑、地面不平、轮胎磨损
IMU（常有） /imu 角速度、加速度 高频、短期准，但积分两次噪声爆炸

你说的那句话，修正一下措辞就完全对了

你说："不同传感器收集不同的证据，形成因子图，根据公式算出小车位置和地图。"
✅ 完全对。只补两个精确说法：

① 传感器给的是量测 $z_k$，不是因子。因子 = 量测 + 观测模型 + 信息矩阵（即"这条证据说的是哪几个变量之间的什么关系、它有多可信"）。
② 公式算出来的不是"位置和地图"两个东西，而是同一个东西：所有未知量 $\mathcal{X}$ 联合最优的那一组值。位姿和地图在数学上是平权的，都被塞在同一个 $\mathcal{X}$ 里一起解——这正是 SLAM 和"先定位再建图"的根本区别。

2. 把公式里每个符号，按到车上的一个具体零件上

上一页那四行公式，符号看着抽象。现在把它们一个个"钉"到实车上：

符号数学名字实车上的具体东西典型数值 / 来源
$\mathcal{X}$ 全部未知量 机器人位姿序列 $x_1,\dots,x_T$ + 地图里所有路标 $l_1,\dots,l_L$ 跑 5 分钟 @10 Hz → $T\approx 3000$ 个位姿；地图里 $L\approx 2000$ 个路标。合计约 5000 个变量
$x_t$ 第 $t$ 帧位姿 base_link 在 map 坐标系下的位姿。2D 是 $(x,y,\theta)$，3D 是 $\mathrm{SE}(3)$ $(3.2\ \mathrm{m},\ 1.5\ \mathrm{m},\ 30^\circ)$，由 /tf 里的 map→base_link 给出
$l_j$ 第 $j$ 个路标 视觉三角化出的 3D 地图点 / 反光柱 / 二维码 / 激光里的角点，在 map 下的坐标 $(5.0\ \mathrm{m},\ 2.1\ \mathrm{m})$；一开始不知道，是要解出来的未知量
$z_k$ 第 $k$ 个量测 /odom 的两帧位移、/scan 的一个距离读数、相机上某个特征点的像素 $(u,v)$ $(u,v)=(320,240)$ 像素；里程计 $\Delta=(0.52\ \mathrm{m}, 0.01\ \mathrm{m}, 3^\circ)$
$\mathcal{X}_k$ 这个量测涉及的变量子集 第 100 帧看到路标 7 → $\mathcal{X}_k=\{x_{100},\,l_7\}$。只这两个，别的 4998 个变量跟它无关 这就是因子图稀疏性的来源，也是后端能算几万变量的原因
$h_k(\cdot)$ 观测模型 "给定候选位姿和候选路标，应该看到什么"。相机是投影：$h=\pi(K,\,T_{cam}^{-1}l_j)$；激光是距离：$h=\|l_j - t_i\|$ 代码里就是一个函数，吃进去变量、吐出来预测值
$\Omega_k$ 信息矩阵（$=\Sigma_k^{-1}$） 这个传感器有多准。由标定 / 出厂手册给出。$\Omega=1/\sigma^2$ 激光 $\sigma=0.02\ \mathrm{m}\Rightarrow\Omega=2500$；相机 $\sigma=1.5\ \mathrm{px}\Rightarrow\Omega\approx 0.44$
$\epsilon_k$ 噪声 轮子打滑、墙面反光、特征点误匹配、时间戳不同步 我们假设它服从高斯（或拉普拉斯）分布
$p(\mathcal{X})$ 先验 开机时给的初始位姿（/initialpose）、GPS 一次性读数、或"机器人不会瞬移" 通常只在 $x_0$ 上加一个先验因子把整个图"钉住"

★ 最重要的一句话：位姿和路标是同一类东西

很多人第一次看这个表会以为"位姿"是状态、"路标"是输出。不是的。
在 $\mathcal{X}$ 里，$x_t$ 和 $l_j$ 完全平权——都是未知量、都要被优化、都有初值、都会被修正。
这就是为什么 SLAM 能做到"边定位边建图"：因为它从来没把这两件事分开过。

那"位姿"为什么不能当成普通向量？

因为 $\theta$ 不是普通数字。比如 $179^\circ$ 和 $-179^\circ$ 只差 $2^\circ$，但数字上差了 $358$。你要是直接对角度做算术平均，会得到 $0^\circ$——彻底错了。

所以工程上约定：位姿存成 $T\in\mathrm{SE}(2)$（旋转矩阵+平移），更新的时候用"李代数增量" $\delta\in\mathbb{R}^3$：

$$T_{t}\leftarrow T_{t}\cdot\exp(\hat{\delta}),\qquad \delta\in\mathbb{R}^3\ \text{（就是一个普通向量，可以随便加减）}$$

公式里那些 $\mathrm{Log}(\cdot)$、$\mathrm{Exp}(\cdot)$ 就是干这个的：把"位姿的差"翻译成一个普通 3 维向量，好写残差、好求导。你暂时只需要知道"有这么个翻译层"就够了。

3. 一种传感器 = 一类因子（这是全篇最实用的一张表）

公式 (4) 是 $\mathcal{X}^\star=\arg\min_{\mathcal{X}}\sum_k\|h_k(\mathcal{X}_k)-z_k\|^2_{\Omega_k}$。那个 $\sum_k$ 里的每一项，在实车上就是一个因子。四大类：

因子类型连接哪些变量残差（代码里真正算的东西）来源
先验因子
PriorFactor		 只连 $x_0$（或某一个 $x_t$） $e = \mathrm{Log}\big(x_0^{-1}T_{\text{init}}\big)$ /initialpose、GPS、AMCL 给的初值。没有它，整个图可以整体平移/旋转，解不唯一
里程计因子
BetweenFactor		 连 $x_{t-1}$ 和 $x_t$ $e = \mathrm{Log}\Big(\big(T_{t-1}^{-1}T_t\big)^{-1}\,\Delta_{\text{odom}}\Big)$
"预测的相对位姿"和"里程计测到的相对位姿"差多少		 /odom。相邻两帧的相对位移 $\Delta$
视觉观测因子
ProjectionFactor		 连 $x_t$ 和 $l_j$ $e = \begin{pmatrix}u\\v\end{pmatrix} - \pi\big(K,\ T_{\text{cam}}^{-1}\,l_j\big)$
"路标应该投到哪个像素"和"实际看到哪个像素"差多少（单位：像素）		 /camera + 特征提取 + 数据关联
激光观测因子
RangeFactor / ScanMatch		 连 $x_t$ 和 $l_j$（或 $x_t$ 和一小段局部地图） $e = r_{\text{measured}} - \|l_j - t_t\|$
"测到的距离"和"预测的距离"差多少（单位：米）		 /scan。距离读数或扫描匹配的位姿增量
回环因子
LoopFactor		 连 $x_i$ 和 $x_j$（$i\ll j$，隔得很远） 和里程计因子长一模一样：$e=\mathrm{Log}\big((T_i^{-1}T_j)^{-1}\Delta_{\text{loop}}\big)$
但"隔得远"这三个字才是关键		 回环检测：视觉词袋（DBoW）、Scan Context、激光直方图…
IMU 因子
PreintegratedIMU		 连 $x_{t-1},x_t,v_{t-1},v_t$ 预积分量测与状态预测之差 /imu。给姿态和速度提供高频约束

4. 一帧一帧怎么跑：从传感器数据到 map→odom 的 tf

实车程序不是"攒够所有数据再解一次"，而是增量地跑一个循环。用一张图看清楚：

为什么最后发布的是 map→odom，而不是 map→base_link？

这是 ROS 里一个特别容易搞混、但面试常问的点。标准做法是让 tf 树长这样：

$$\texttt{map}\ \xrightarrow{\ \text{SLAM 全局修正（低频、会跳变）}\ }\ \texttt{odom}\ \xrightarrow{\ \text{里程计递推（高频、连续）}\ }\ \texttt{base\_link}\ \xrightarrow{\ \text{外参标定}\ }\ \texttt{laser / camera}$$

为什么要在中间插一个 odom？两个理由：

  • odom→base_link 必须连续、不能跳：它是用编码器递推出来的，任何时候都在平滑更新（50 Hz）。如果直接用它做局部导航，不会因为后端优化而"瞬移"。
  • map→odom 可以有跳变：后端每次优化完，会给出一个"全局修正量"，这个量就发布成 map→odom。回环闭合时，你会看到这个变换突然变化一下——那一下就是"漂移被摊平"的瞬间。

所以代码里通常这么算：

# 后端给出 map 下的位姿，里程计给出 odom 下的位姿
T_map_base  = result.atPose2(X(t))        # 优化后的全局位姿
T_odom_base = latest_odom_pose()            # 纯里程计推出来的

# 中间那一环：map -> odom
T_map_odom  = T_map_base * T_odom_base.inverse()
tf.sendTransform(T_map_odom, "map", "odom")

5. 伪代码：从 20 行看懂原理，到真正能抄的 ROS 骨架

版本 A：概念版（把 (4) 式原样翻译成代码）

先别管 ROS，就看看"最小化加权平方和"这件事在代码里长什么样：

# ================= 概念版：20 行看懂整个后端 =================

# 1) 未知量：轨迹 + 地图，都是"待求的数"
X = { x_0, x_1, ..., x_T,        # 位姿（SE(2) 或 SE(3)）
      l_0, l_1, ..., l_L }      # 路标（世界坐标下的点）

# 2) 因子列表：每条证据一项
factors = []

def add_factor(h, var_ids, z, Omega):
    #   h       : 观测模型（吃变量，吐预测值）
    #   var_ids : 这条证据涉及哪几个变量（就是 X_k）
    #   z       : 实际量测
    #   Omega   : 信息矩阵，越大表示越信这个传感器
    factors.append((h, var_ids, z, Omega))

# 3) 代价函数：这就是 (4) 式
def cost(X):
    J = 0.0
    for (h, var_ids, z, Omega) in factors:
        e = h(X, var_ids) - z          # 残差 e = h_k(X_k) - z_k
        J += e.T @ Omega @ e           # ‖e‖²_Ω
    return J

# 4) 求解：一般没有闭式解，只能迭代线性化
def solve(X_init):
    X = X_init
    for it in range(20):        # 高斯-牛顿 / LM 的迭代
        H, b = linearize(cost, X)     # 在当前估计处一阶展开
        dX   = solve_linear(H, b)     # 解正规方程 H·dX = b
        X    = retract(X, dX)         # 位姿要在流形上更新，不能直接加
    return X

# 5) 用起来
add_factor(h_odom,  [0, 1], delta_odom_01, Omega_odom)
add_factor(h_proj,  [1, 'l7'], uv_of_l7_at_t1, Omega_pixel)
add_factor(h_range, [2, 'l7'], range_to_l7_at_t2, Omega_laser)

X_star = solve(X_init)   # ← 轨迹和地图同时出来了

看这三行 add_factor，把第 3 节的表对上了

· 第一行：里程计因子，涉及 $x_0,x_1$，量测是相对位移，用 Omega_odom 加权。
· 第二行：视觉因子，涉及 $x_1$ 和路标 7，量测是像素坐标，用 Omega_pixel 加权。
· 第三行：激光因子，涉及 $x_2$ 和同一个路标 7，量测是距离，用 Omega_laser 加权。
同一个路标 $l_7$ 被两个不同传感器"看"到，这就是多传感器融合在代码里的真实样子——不是什么高级技巧，就是把两条因子加进同一个列表。

版本 B：ROS 版（GTSAM 风格，能直接对着改）

# ============ ROS + GTSAM 后端节点骨架 ============
import gtsam

graph   = gtsam.NonlinearFactorGraph()
initial = gtsam.Values()          # 迭代初值（用里程计累积出来）
iSAM    = None

# ---- 1) 噪声模型：这里填的是 σ，不是 Ω！----
#      GTSAM 内部会转成 Ω = Σ⁻¹ = diag(1/σ²)
prior_noise = gtsam.noiseModel.Diagonal.Sigmas([0.01, 0.01, 0.005])   # m, m, rad
odom_noise  = gtsam.noiseModel.Diagonal.Sigmas([0.05, 0.05, 0.02])
pixel_noise = gtsam.noiseModel.Isotropic.Sigma(2, 1.5)                    # 1.5 像素
laser_noise = gtsam.noiseModel.Diagonal.Sigmas([0.02])                   # 2 cm
loop_noise  = gtsam.noiseModel.Diagonal.Sigmas([0.10, 0.10, 0.03])

# 符号：X(t) 是第 t 帧位姿，L(j) 是第 j 个路标
X = lambda t: gtsam.symbol('x', t)
L = lambda j: gtsam.symbol('l', j)

t = 0

# ---- 2) 先验因子：把整个图"钉"在世界坐标系里 ----
def on_initial_pose(msg):
    pose0 = gtsam.Pose2(msg.x, msg.y, msg.theta)
    graph.add(gtsam.PriorFactorPose2(X(0), pose0, prior_noise))
    initial.insert(X(0), pose0)

# ---- 3) 里程计因子：连相邻两帧 ----
def on_odom(msg):
    global t
    t += 1
    delta = gtsam.Pose2(msg.dx, msg.dy, msg.dtheta)

    graph.add(gtsam.BetweenFactorPose2(X(t-1), X(t), delta, odom_noise))

    # 用里程计累积一个初值（只是迭代起点，不是最终答案）
    guess = initial.atPose2(X(t-1)).compose(delta)
    initial.insert(X(t), guess)

# ---- 4) 视觉观测因子：连位姿和路标 ----
def on_landmark_obs(j, u, v):
    # uv 是该路标在图像中的像素坐标，K 是相机内参
    factor = gtsam.GenericProjectionFactorCal3_S2(
        gtsam.Point2(u, v), pixel_noise, X(t), L(j), K)
    graph.add(factor)

    if not initial.exists(L(j)):
        initial.insert(L(j), triangulate(u, v, t))   # 给个初值

# ---- 5) 激光因子：位姿 ↔ 路标（或扫描匹配得到的位姿增量）----
def on_laser_obs(j, r):
    factor = gtsam.RangeFactor2D(X(t), L(j), r, laser_noise)
    graph.add(factor)

# ---- 6) 回环因子：连隔得很远的两个位姿 ----
def on_loop_closure(prev_t, rel_pose):
    graph.add(gtsam.BetweenFactorPose2(X(prev_t), X(t), rel_pose, loop_noise))

# ---- 7) 定时优化 + 发布 ----
def on_timer():                       # 每 1 秒触发一次
    global iSAM
    if iSAM is None:
        params = gtsam.ISAM2Params()
        params.setRelinearizeThreshold(0.1)
        iSAM = gtsam.ISAM2(params)

    iSAM.update(graph, initial)          # 增量更新，不重解全图
    result = iSAM.calculateEstimate()    # ← 这就是 X*

    # 发布 map -> odom（全局修正），不是 map -> base_link
    T_map_base  = result.atPose2(X(t))
    T_odom_base = latest_odom_pose()
    T_map_odom  = T_map_base.compose(T_odom_base.inverse())
    tf.sendTransform(T_map_odom, "map", "odom")

    # 顺便把地图点和轨迹也发出去
    publish_cloud(result, L)
    publish_path(result, X)

对照一下：伪代码和公式的对应关系

公式里的东西代码里的东西
$\mathcal{X}=\{x_t\}\cup\{l_j\}$initial 这个 Values 容器
因子 $k$graph.add(...) 加进去的一个对象
$\Omega_k$noiseModel（注意填的是 $\sigma$）
$h_k(\mathcal{X}_k)$因子内部固定的观测模型，比如 GenericProjectionFactor 里的相机投影
$\sum_k\|\cdot\|^2_{\Omega_k}$求解器内部的误差函数，你不需要手写
$\mathcal{X}^\star$iSAM.calculateEstimate() 的返回值

用 g2o / Ceres 的话，会有什么不同？

思路完全一样，只是 API 换了个壳：

  • g2o：你要自己继承 BaseEdge 写残差和雅可比矩阵，然后 optimizer.addVertex() / addEdge()。比 GTSAM 低层，但能看到线性化过程。
  • Ceres：你要写一个 CostFunctor，在里面实现 operator() 算残差（可选地给出雅可比），然后 problem.AddResidualBlock()。自动求导很方便。
  • GTSAM：因子库最全，用起来最像在写数学——上面那段伪代码就是这个风格。

面试时可以说的一句话："这三个库都是同一件事的不同外壳——把 (4) 式的求和拆成一个个因子，用高斯-牛顿或 LM 迭代求解。"

6. 手算：三个传感器，四个因子，最后落在哪

光看代码不够。我们把上一页那个 1 维算例升级一下，加进一个路标，让它真的像一台小车在做 SLAM。

设定：小车走了一小步

小车沿直线前进，我们要求三个未知量：

  • $x_1$：起始位置（未知，但有个先验说它大概在 0）
  • $x_2$：走了一步之后的位置
  • $l_1$：路上那个路标的位置

四个因子（每条证据一个）：

因子类型残差量测 $z_k$$\Omega_k$
F0先验$x_1 - z_0$$z_0 = 0$100（非常自信）
F1里程计$(x_2 - x_1) - z_1$$z_1 = 5.0$ m1（一般）
F2视觉（在 $x_1$ 处看路标）$(l_1 - x_1) - z_2$$z_2 = 3.0$ m4（比较准）
F3视觉（在 $x_2$ 处看同一个路标）$(l_1 - x_2) - z_3$$z_3 = -1.9$ m4

注意 F1 和（F2、F3 合起来）是冲突的：里程计说走了 5.0 m，两个视觉读数推出来的位移是 $3.0-(-1.9)=4.9$ m，差了 0.1 m。最小二乘的工作，就是在这 0.1 m 的分歧里找一个最合理的平衡点。

写出代价函数

$$J = 100\,x_1^2 \;+\; \big(x_2-x_1-5\big)^2 \;+\; 4\big(l_1-x_1-3\big)^2 \;+\; 4\big(l_1-x_2+1.9\big)^2$$

（正好就是 (4) 式：$\sum_k\|h_k(\mathcal{X}_k)-z_k\|^2_{\Omega_k}$。）

三个未知量分别求导，令零

对 $x_1$、$x_2$、$l_1$ 各求一次偏导，令它们为 0，整理后得到三个方程：

$$ \begin{cases} 210\,x_1 - 2\,x_2 - 8\,l_1 = -34 & (\text{对 }x_1)\\[3pt] -2\,x_1 + 10\,x_2 - 8\,l_1 = 25.2 & (\text{对 }x_2)\\[3pt] -\,x_1 - x_2 + 2\,l_1 = 1.1 & (\text{对 }l_1) \end{cases} $$

解出来：

$$\boxed{\;x_1^\star = 0.000\ \mathrm{m},\qquad x_2^\star = 4.933\ \mathrm{m},\qquad l_1^\star = 3.017\ \mathrm{m}\;}$$

因子预测值量测值残差为什么
F0 先验$x_1=0$$0$0.000$\Omega=100$，太大了，谁都拉不动它
F1 里程计$4.933$$5.0$$-0.067$$\Omega=1$，被"牺牲"得最多
F2 视觉$3.017$$3.0$$+0.017$$\Omega=4$，动了很少
F3 视觉$-1.917$$-1.9$$-0.017$同上

三件事值得注意：

  • $x_1$ 精确等于 0。因为先验的 $\Omega=100$，比别的因子大两个数量级——权重压倒性的时候，它就是硬约束。这也解释了为什么工程上总要在 $x_0$ 上加一个强先验把图钉住。
  • 残差没有一个是 0（除了被钉死的先验）。最小二乘从来不是"让每条证据都成立"，而是找让总冲突最小的那一点。
  • 位移被分成了 $4.933$，正好在里程计说的 5.0 和视觉说的 4.9 之间，但因为 $\Omega$ 不同，它没停在正中间——偏向 4.9 一侧更多一点。

互动判断 ②

如果把先验的 $\Omega_0$ 从 100 改成 0.01（"我也说不准 x₁ 在哪"），会发生什么？

7. 实车上最容易踩的七个坑

坑 1｜没有回环，图就是一条链，漂移一定累积

只加里程计因子和观测因子，因子图是一棵树（或一条链）。链上的误差只能沿着一个方向传递，走一百米之后偏一米是常态。回环因子的唯一作用是"把链变环"——让远处的约束能反过来修正近处。

所以工程上：回环检测的召回率比精度更重要（漏掉一个回环只是少一次修正，加错一个回环会让整张地图毁掉）。

坑 2｜错误的回环比没有回环更糟

一个假回环（把两个看起来像、实际不同的地方关联起来）会给 (4) 式加进去一个残差极大的因子。因为最小二乘是平方惩罚，这一项会主导整个代价函数，把地图拉歪。

解法就是上一页 Q5 说的那两条：
· 把平方换成 鲁棒核（Huber、Tukey、Cauchy）——残差大到一定程度后，惩罚从平方变成线性；
· 或者用 DCS / switchable constraints 这类方法，给每个回环因子加一个自动学习的"开关"。

坑 3｜$\Omega$ 不能瞎填

很多人代码里所有 noiseModel 都写成 Sigma(1)，然后奇怪为什么结果不对。$\Omega$ 是权重的物理含义，填错了就是"让不准的传感器说了算"。

正规做法：激光用出厂精度或标定值（$\sigma\approx 0.01\sim0.03$ m）；相机用重投影误差统计（$\sigma\approx 0.5\sim2$ 像素）；里程计用轮距和编码器分辨率推，或者干脆用一段时间的数据去拟合。ROS 里很多驱动的 covariance 字段默认是 0，直接拿来用会出大问题。

坑 4｜时间戳不同步

里程计 50 Hz、激光 10 Hz、相机 30 Hz。如果直接拿"收到激光那一刻"的里程计位姿去当 $x_t$，误差可能有好几厘米。必须用 tf 插值到同一个时间戳，或者用 message_filters 做时间同步。

更狠的做法是把时间偏移量也当成未知量放进 $\mathcal{X}$ 里一起优化——这就是在线时间标定。

坑 5｜外参也是误差源

相机装在车头，激光装在车顶，它们到 base_link 的外参是量出来的，也有误差。而这个误差会直接污染观测模型。

高级系统会把外参一起放进 $\mathcal{X}$ 优化（在线外参标定），或者至少把标定残差反映到 $\Omega$ 里。

坑 6｜每次都重解全图，实时性崩盘

跑 10 分钟有 3 万个位姿，每次优化都重新线性化+求解，车上那颗 CPU 扛不住。

标准解法：① 关键帧（只对关键帧建节点）；② 增量式求解（iSAM2 只更新受影响的局部）；③ 边缘化（把老的路标从状态里消掉）。这些就是第二季"打地基"的正题。

坑 7｜把优化当成"绝对正确的真值"

优化出来的只是"在当前所有约束下最自洽的解"。如果所有传感器同时被同一个系统误差影响（比如外参整体偏了 5 cm），优化会把这 5 cm 均匀分摊到所有位姿上，你看不出来。优化不能凭空创造信息，它只能平衡信息。

一句话串起来：你在项目里会写到的三种代码

① 前端代码：订阅 /scan、/camera、/odom，做特征提取、数据关联、回环检测，输出"量测 + 它涉及哪几个变量"。
② 后端代码：把量测包成因子加进图，设定 noiseModel，定时调用优化器，取出 $\mathcal{X}^\star$。
③ 输出代码：把结果转成 map→odom 的 tf、/map 点云、/path 轨迹。

这三件事背后是同一个公式，这就是为什么读懂那四行很重要。

8. 自测与练习

三句话总结

① 传感器给的是量测 $z_k$；量测 + 观测模型 + 信息矩阵 $\Omega_k$ 才构成因子。
② 位姿和路标在 $\mathcal{X}$ 里平权，一起被优化——这就是 SLAM 不分两步的原因。
③ 后端做的事只有一件：让 $\sum_k\|h_k(\mathcal{X}_k)-z_k\|^2_{\Omega_k}$ 最小。

三个必答问题

① /odom 和 /scan 在你的代码里分别对应哪一类因子？它们的残差单位分别是什么？
② 为什么发布的是 map→odom，而不是直接发 map→base_link？
③ 如果所有 noiseModel 都填 1，你的小车会出现什么现象？

课后练习（先自己算，再展开对答案）

  1. 一台小车在 1 维里走，两个位姿 $x_1,x_2$。先验 $x_1=0$（$\Omega_0=100$），里程计 $x_2-x_1=2.0$ m（$\Omega_1=1$）。求 $x_2^\star$。
    展开查看答案
    $J = 100x_1^2 + (x_2-x_1-2)^2$，对 $x_2$ 求导：$2(x_2-x_1-2)=0 \Rightarrow x_2=x_1+2$。
    对 $x_1$ 求导：$200x_1 - 2(x_2-x_1-2)=0$，代入 $x_2=x_1+2$，第二项变成 0，所以 $200x_1=0$，即 $x_1=0$。
    于是 $x_2^\star=2.0$ m。
    要点：先验极强时，$x_1$ 被钉死在 0，里程计完全说了算。这就是"强先验 + 相对约束"的标准结构。
  2. 接着上一题，如果再加一个回环因子 $x_2 - x_1 = 1.8$ m（$\Omega_2=4$），$x_2^\star$ 会变成多少？为什么？
    展开查看答案
    这时 $x_1$ 仍被先验钉死在 0，问题退化成两个关于 $x_2$ 的证据：$z_1=2.0$（$\Omega_1=1$）和 $z_2=1.8$（$\Omega_2=4$）。
    加权平均：$x_2^\star = \dfrac{1\times 2.0 + 4\times 1.8}{1+4} = \dfrac{2.0+7.2}{5} = \dfrac{9.2}{5} = 1.84$ m。
    要点：回环的 $\Omega$ 是里程计的 4 倍，所以结果被拉向 1.8 那一侧。这就是"回环修正"在数字上的样子——它不是把轨迹瞬间掰到 1.8，而是在两个说法之间重新加权。
  3. 你的相机内参标定得不太准，重投影误差比手册上大很多。你应该改代码里的哪个地方？改了之后结果会怎么变？
    展开查看答案
    改 pixel_noise 对应的 $\sigma$——把它调大（比如从 1.5 像素调到 4 像素）。
    因为 $\Omega=1/\sigma^2$，$\sigma$ 变大会让 $\Omega$ 变小，也就是相机这个因子在图里的话语权变小。
    结果：位姿更倾向于相信激光和里程计，视觉对轨迹的"拉扯"变弱。这是正确的做法——承认自己不准，比假装很准要好得多。
  4. （串联）如果小车在走廊里跑了一圈，回到起点，但回环检测没触发。此时因子图是什么形状？优化结果会怎样？
    展开查看答案
    图是一条链（树）：位姿 $x_1 \to x_2 \to \cdots \to x_T$ 依次相连，每个路标挂在某一两个位姿上。没有任何一条因子连接首尾。
    优化结果：整条轨迹会保持"内部自洽"（相邻两帧的里程计残差被摊平），但整体可能相对于真实位置偏移——因为没有任何约束把它拉回真实世界。这就是"漂移"。
    更麻烦的是：如果链上没有先验，整条轨迹可以整体平移/旋转而代价不变，正规方程是奇异的。
  5. 为什么说"因子图的形状 = 你的传感器配置 + 你的回环策略"？举两个例子说明改了什么会改变图的形状。
    展开查看答案
    因为图的节点是变量、边是因子，而节点和边都是由"你有哪些传感器、以什么频率产生什么量测"直接决定的。
    例一：加一个 IMU → 每对相邻位姿之间多一个 IMU 因子（还会引入速度和零偏节点），图变得更稠密。
    例二：从"逐帧建节点"改成"只对关键帧建节点" → 节点数减少一个数量级，里程计因子变成"两个关键帧之间的预积分约束"，图的拓扑完全变了。
    例三：把回环检测从"只在视觉相似时才触发"改成"每个关键帧都做 Scan Context 匹配" → 回环因子变多，图里出现更多的长边。
    所以调 SLAM 系统的时候，很多时候你调的不是参数，而是图的形状。

回到你的问题：你的理解对在哪、可以更精确在哪

你说的："激光、相机、里程计收集不同证据 → 形成因子图 → 根据公式计算小车位置和地图。"

✅ 完全正确，这就是标准答案。只补三处更精确的说法：

① "形成因子图"这一步在代码里是显式的：你要为每条证据决定"它连接哪几个变量、用什么噪声模型、残差怎么定义"。这三件事决定了结果好坏，比选哪个优化库重要得多。
② "计算位置和地图"其实是"一次解出 $\mathcal{X}$"：位姿和路标是同一个向量里的两部分，没有先后。
③ 这个计算不是一次性的：它是"来一帧 → 加因子 → 优化 → 发布 → 再来一帧"的无限循环，而且每次优化都是从上一轮的结果出发再做局部线性化。
