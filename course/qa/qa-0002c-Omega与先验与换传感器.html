1.2 换传感器时，其实要改四样东西

你的直觉是"换传感器 = 换 Ω"。方向对，但实际工程里往往要改四个地方，而且有一个比 Ω 更麻烦：

要改什么什么时候必改典型场景
① Ω（噪声模型） 永远要改——只要换了硬件 从普通 RPLIDAR 换成工业级雷达，$\sigma$ 从 3 cm 降到 1 cm，$\Omega$ 直接涨 9 倍
② 观测模型 $h_k(\cdot)$ 换了不同原理的传感器、或参数变了 从单目相机换成 RGB-D：$h$ 从"投影到像素"变成"投影 + 深度"；换了镜头，内参 $K$ 也得重新写进去
③ 因子类型 / 图的拓扑 换了不同种类的传感器 加一个 IMU：不只是"多几项"，而是多出速度节点、零偏节点、预积分因子，图的形状都变了
④ 时间同步 / 外参 硬件位置或时钟变了 相机从车头挪到车顶：外参要重新标定，时间偏移量可能要重新估计

★ 一个很实际的提醒：ROS 驱动里的 covariance 字段

很多 ROS 驱动在 /odom、/scan 消息里带一个 covariance 字段。它本来应该就是 $\Sigma$（然后 $\Omega=\Sigma^{-1}$），但现实里三种情况都常见：

· 填 0——最常见的坑。0 的逆是无穷大，等于"我无限自信"，会让这条因子把别的因子全部压死。
· 填一个瞎猜的常数——比如永远填 0.1。它不反映实际精度，但至少能跑。
· 填真实协方差——最好，但需要你自己标定或统计。

所以工程上的标准做法：不要盲信驱动给的 covariance，自己按实测残差重新填一个 noiseModel。

1.3 Ω 到底怎么"统计"出来？——一个能直接上手的做法

你不用一开始就调得完美。一个非常实用的"三步法"：

  1. 先跑一遍：用一个中等大小（比如手册值的 2 倍）的 $\sigma$ 跑起来，让系统不崩。
  2. 收残差：把每条因子在优化收敛后的残差 $e_k$ 记录下来（代码里很容易打印）。
  3. 反推 $\sigma$：如果残差近似零均值高斯，那么 $\sigma_k\approx\sqrt{\mathrm{mean}(e_k^2)}$。用它反过来更新 $\Omega_k=1/\sigma_k^2$，再跑一遍。

一般迭代两三轮就稳定了。这个方法叫"残差统计法"，比查手册靠谱得多——因为它反映的是你这台车上、这套环境里的真实精度。

2. Q2｜Ω 是矩阵——你说对了，而且比你想的更重要

完全对
现实是多维的，$\Omega$ 就是协方差矩阵的逆，维数等于这条量测的维数。 而且——这是最关键的一点——Ω 的"非对角元素"才是它真正的价值所在。

2.1 维度对照表：每条量测的 Ω 长什么样

量测维数Ω 的形状对角元素含义非对角元素含义
激光单点距离1 $1\times1$，就是个标量 $1/\sigma_r^2$ —（一维没有）
视觉特征点 $(u,v)$2 $2\times2$ $1/\sigma_u^2$、$1/\sigma_v^2$ $\Omega_{uv}$：像素横纵误差是否相关（通常设 0）
2D 里程计 $(\Delta x,\Delta y,\Delta\theta)$3 $3\times3$ 三个分量各自的精度 关键：$\Delta x$ 和 $\Delta y$ 的误差相关吗？转弯时通常相关
2D 位姿残差 $(x,y,\theta)$3 $3\times3$ 位置和角度的精度 位置和角度的耦合——比如打滑时"位置偏"和"角度偏"经常同时发生
3D 位姿残差（SE(3)）6 $6\times6$ 平移 3 + 旋转 3 各自精度 平移-旋转耦合（比如 IMU 的零偏会同时影响两者）
单目相机的重投影（含尺度）2 $2\times2$ 像素精度 通常设 0（等方性假设）

2.2 为什么"非对角元素"才是关键：一个直观的例子

假设你的小车在转弯。差速轮打滑的特点是：如果横向前进偏多了，角度往往也转多了。这两个误差不是独立的——它们"绑"在一起。

★ 为什么工程上很多代码还是填对角 Ω？

因为填非对角元素需要两件事：① 知道它该是多少（要标定或统计），② 求解器能处理稠密的小块（多了耦合项，计算量增加）。

所以工程上常见三种选择：
· 只填对角：最简单，跑得动，大多数场景够用。
· 填分块对角：同一传感器内部耦合（比如 3×3 块里带非对角），不同传感器之间不耦合。
· 填完整 Ω：最准，但少见，一般用在标定很精细或对精度要求极高的场景。

GTSAM / g2o / Ceres 都支持完整矩阵，只是你要显式给一个 Gaussian 噪声模型而不是 Diagonal。

2.3 回到那个手算例题：为什么它看起来那么简单？

上一页的例题里，所有 Ω 都是标量（1 或 4），所有量测都是 1 维。所以最后解出来能写成一个简单的"加权平均"公式。

一旦维数上去，就不一样了：

  • 残差 $e$ 变成向量 → $e^{\mathsf T}\Omega e$ 变成二次型 → 求导要算矩阵
  • 位姿更新要用流形 $\mathrm{SE}(2)/\mathrm{SE}(3)$ → 需要 $\mathrm{Exp}/\mathrm{Log}$ 映射
  • 解不再是"一个加权平均"，而是一组线性方程 $H\Delta x = b$

但物理意义完全一样：$\Omega$ 越大 → 这条因子越硬 → 残差被罚得越狠 → 解越靠近它说的值。

# 1D 版本（上一页的例题）：Σ 是标量，Ω = 1/σ²
sigma = 0.5
Omega = 1.0 / (sigma**2)
J += Omega * (h(X) - z)**2

# 3D 里程计版本：Σ 是 3×3，Ω = Σ⁻¹
Sigma_odom = np.array([
    [0.0025,  0.0001,  0.0   ],   # Δx²
    [0.0001,  0.0025,  0.0   ],   # Δy²（和 Δx 有轻微相关）
    [0.0,     0.0,     0.0004]    # Δθ²
])
Omega_odom = np.linalg.inv(Sigma_odom)   # ← 这一步是公式里的 Ω

e = h(X, var_ids) - z                   # 残差现在是 3 维向量
J += e.T @ Omega_odom @ e               # ← 二次型，不是标量乘平方

3. Q3｜先验能不能丢——你的观察全对，但把两件事混在了一起

结论对，理由差一点
你说"建图时以小车当前位置为原点，先验是 0，所以能丢"。
前半句事实完全正确——建图时确实会这么做；后半句"所以能丢"因果链接错了。 另外你说"导航时手动选一个初始位置，那就有了一个先验"——这条完全正确，而且非常关键。

3.1 把"先验是 0"和"先验可以丢"分成两件事

说法它到底在说什么对不对
"建图时先验是 0" 你把 $x_0$ 的值设成了单位位姿（原点），并且给了它一个非常大的 $\Omega_0$，让它几乎无法被别的因子拉动。 ✅ 对。这是"钉住规范自由度"的标准做法。
"因为值是 0，所以这一项可以丢" 把"值恰好为 0"当成了"这一项不存在"。 ❌ 不对。值为 0 的先验仍然是一条约束，它规定了"世界坐标系的原点在哪"。丢掉了它，整个地图就可以随便平移旋转。
"先验可以丢"（论文里的说法） 指的是：如果你对 $\mathcal{X}$ 一无所知，那么 $p(\mathcal{X})$ 是均匀分布（常数），它对 argmax 没有影响——这时候它在数学上可以被省略。 ✅ 对。但这是"没有信息所以丢"，不是"值为 0 所以丢"。

3.2 那论文为什么说"先验可以丢"？——它说的是哪一件事

原文那句 "if no prior knowledge is available, $p(\mathcal{X})$ becomes a uniform distribution, which is inconsequential for optimization" 里的关键短语是："if no prior knowledge is available"——没有先验知识的时候。

它的意思不是"先验这个东西可以随便删"。它的意思是：

  • 数学上：均匀分布的密度函数是常数，常数乘在 $p(Z\mid\mathcal{X})$ 前面不改变 argmax 的位置 → 可以省略。
  • 工程上：你绝不能真的什么都不加——否则整个图的坐标系没法定义。你总得在某一个变量上钉一个先验（哪怕是你选的那个），才能让 $H$ 矩阵满秩。

所以真实做法是："数学上省略均匀先验" + "工程上给 $x_0$ 加一个钉住坐标系用的先验"。这两件事不矛盾——前者说的是"未知变量上的先验分布"，后者说的是"坐标系固定约束"。

3.3 你的"导航场景"完全正确，再补充三个细节

完全对
你说的"导航时手动选一个位置，那个位置就成了先验"——这正是工业界导航系统的做法。

补充三个细节，你以后自己写代码会用到：

  1. 先验的 $\Omega_0$ 决定了"你点的那个位置有多硬"。
    如果你在 RViz 里点的位置不太确定（比如刚开机，只知道车在大厅里），那就把 $\Omega_0$ 调小；如果是 GPS 给的高精度初值，可以把 $\Omega_0$ 调大。 "值"和"Ω"是一对，不能只给值不给 Ω。
  2. 导航时通常会有"一次性先验"和"持续先验"两种。
    · 一次性先验：开机时给一个初始位姿，之后就不再改；
    · 持续先验：整个过程中每一帧都可能有一个弱先验（比如 GPS 每 1 秒来一次），这时每一帧都是一个先验因子。
  3. AMCL / 粒子滤波里那个"初始位姿"，在数学上就是先验。
    你在 RViz 里用 2D Pose Estimate 点一个箭头，AMCL 就把粒子撒在那附近——撒粒子的范围 = 你告诉它"我有多不确定"，撒粒子的中心 = 你告诉它"我在哪"。这就是先验的粒子版实现。 
# 导航场景：手动给初始位姿 → 直接变成一个先验因子
def on_initial_pose_from_rviz(msg):
    pose0 = gtsam.Pose2(msg.x, msg.y, msg.theta)   # 你在 RViz 里点的位置

    # σ 由"你有多自信"决定
    # 如果你确定车就在大厅门口：σ 小（Ω 大）
    # 如果你只知道"车大概在大厅里"：σ 大（Ω 小）
    sigma_xy  = 0.5     # 米
    sigma_th  = 0.1     # 弧度
    prior_noise = gtsam.noiseModel.Diagonal.Sigmas([sigma_xy, sigma_xy, sigma_th])

    graph.add(gtsam.PriorFactorPose2(X(0), pose0, prior_noise))
    initial.insert(X(0), pose0)

4. 换传感器时的"完整 checklist"——比换 Ω 多三件事

你的直觉"换传感器就换 Ω"是对的起点，但完整工程上要做的事情比这多。下面这张清单，你以后换硬件时可以直接对照：

#要改什么怎么改常见坑
1 Ω（噪声模型） 先按手册填，再用实际残差统计重新估一遍 直接抄手册值；covariance 字段填 0
2 观测模型 $h_k$ 如果传感器原理变了，重写残差函数；如果只是参数变了，更新内参/外参 换了镜头没更新内参 $K$；换了安装位置没重新标外参
3 数据关联方式 换传感器往往意味着"怎么把量测和地图里的东西对上"要重做 用旧的特征提取器去处理新传感器的数据，匹配率暴跌
4 时间同步 / 时间戳 用 message_filters 做时间对齐，或把时间偏移量也放进 $\mathcal{X}$ 一起优化 新传感器频率变了，原来的 queue_size 不够
5 图的拓扑 如果加了新类型的传感器（如 IMU），图里会多出新节点和新因子 忘了给新变量加初值，求解器不收敛
6 鲁棒核 新传感器如果更容易产生外点（如视觉在强光下），要加 Huber / Tukey 直接换传感器不加鲁棒核，一个外点毁掉整张图

    比值 $= 9$ 倍。
    激光"说话更大声"——它在优化里的权重变成原来的 9 倍，结果会更倾向于相信激光的读数。
    但要注意：如果你只改了激光的 Ω 没改别的，整个权重结构就变了——原来可能靠里程计平衡，现在激光一方独大，某些场景反而会过拟合激光的误差。所以换完之后通常要"重新调一遍所有传感器的噪声"。
  2. 2D 里程计的协方差是 $\Sigma = \begin{pmatrix}0.01 & 0.005 \\ 0.005 & 0.01\end{pmatrix}$。这个非对角元素 0.005 在物理上是什么意思？
    展开查看答案
    非对角元素 0.005 表示 $\Delta x$ 和 $\Delta y$ 的误差正相关。
    物理含义："如果车在 x 方向偏多了，往往在 y 方向也偏多"。这在转弯打滑时非常常见——两个方向同时被同一种干扰（比如地面湿滑）影响。
    如果这个值是负的，意思是"往 x 正方向偏的时候，往往往 y 负方向偏"——这对应另一种物理模式。
    要记住：对角元素告诉你是"多不准"，非对角元素告诉你"这些不准的方向有没有关联"。
  3. 建图时你在 $x_0$ 上加了一个先验 $z_0 = \text{原点}$、$\Omega_0 = 10^6$。如果把它改成 $\Omega_0 = 1$，地图会怎样？
    展开查看答案
    $\Omega_0$ 从 $10^6$ 降到 $1$，意思是"我对原点这个位置不再那么确定"。
    结果：整张地图可以相对于"世界原点"漂移。位姿和路标的值都会变，因为现在 $x_0$ 可以被其他因子拉动。
    直观地说，地图"松了"，可能整体平移、整体旋转。
    要点：先验的 $\Omega_0$ 决定"参考系钉得牢不牢"。太小 → 会漂；太大 → 数值上可能导致 $H$ 矩阵条件数很差，反而不稳定。工程上一般取一个"比你真实自信度略大"的值。
  4. （串联）导航时你在 RViz 里点了"小车大概在门口"。这个动作在代码里会变成什么？它和建图时的先验，有什么区别？
    展开查看答案
    变成一个新的先验因子：值为你点的位姿，$\Omega_0$ 由你对自己点的那个位置有多自信决定。
    和建图时的先验的区别：
    · 建图时：先验钉住的是"世界坐标系原点"，值是固定的单位位姿，$\Omega_0$ 通常取很大。
    · 导航时：先验钉住的是"车在已建好的地图里的初始位置"，值是你手动给的，$\Omega_0$ 反映你对自己判断的不确定度。
    本质上，两者都是"给某几个变量一个额外的、独立的、带权重的约束"。
  5. 为什么"回环因子不是先验"？两者在公式里长得差不多，有什么区别？
    展开查看答案
    连接的对象不同：
    · 先验因子：连接的是"一个变量"和"世界坐标系"——也就是一个绝对参照。它只连一个节点。
    · 回环因子：连接的是"两个位姿"——它是相对约束。它连两个节点。
    作用不同：
    · 先验的作用是"把图钉在世界坐标系里"，让解唯一。
    · 回环的作用是"把累积的漂移摊平"，它是修正信息，不是参照。
    所以即使回环因子的形式和里程计因子一样（都是 BetweenFactor），它的"角色"也和先验完全不同。
  6. （进阶）如果同一条物理量测被两个不同的传感器同时观测（比如激光和相机同时看到同一个路标），在优化里会发生什么？这算不算"同一证据被用了两次"？
    展开查看答案
    会发生什么：两条因子分别加进图。它们各自有各自的残差、各自的 $\Omega$。求解器会同时考虑这两条约束——结果会落在两条约束的"加权折中"处。
    算不算重复使用：不算，只要两条量测物理上独立（激光和相机的噪声来源不同），它们带来的信息就是真的两份，不是把同一份用了两次。
    但如果两个传感器共享一个物理误差源（比如装在同一块板子上，同一次震动同时影响二者），那它们就是相关的——严格来说要写成联合因子。工程上为了简单常常按独立处理，这时 $\Omega$ 会被高估（因为把相关部分当成独立信息数了两次），可能让结果过于自信。
    一句话：独立量测各加一条因子；相关量测要么合并成联合因子，要么把 $\Omega$ 调大一点"惩罚"这份被重复计算的信息。

回到你的三条判断

Q1（出厂精度 → Ω，换传感器 → 换 Ω）：方向完全对。补一句：出厂精度只是起点，真实 Ω 要经过四层；换传感器要改的不只是 Ω。

Q2（Ω 是矩阵）：完全对。补一句：非对角元素才是它真正比"一组 σ"多出来的信息。

Q3（先验能不能丢）：结论对，理由要修正。把"值为 0"和"可以丢"分开——建图时你是在钉坐标系，不是在丢先验；导航时你是在加一个新的先验。这两件事你的直觉都对，只是措辞上差了一小步。
